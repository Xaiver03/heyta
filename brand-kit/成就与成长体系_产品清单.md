# heyta · 成长与激励体系 —— 产品体系清单（PM 版）

> **这份是什么**：按产品经理视角，把 heyta **自己已有**的「激励与成长体系」梳理成一份可执行的体系清单，
> 说明每个体系的目标、机制、数据口径、UI 落点、状态与边界，并据此界定品牌视觉该做什么、不该做什么。
>
> **依据（全部为仓库现量，不是编的）**：
> - 设计/实现总账：`docs/plans/archive/motivation-and-progression.md`（L1/L2/L3 已并入 main，merge `84cc7f5`）
> - 现役口径：`docs/plans/roadmap.md` §1.2「并行轨道：激励与成长体系」
> - 心理与竞品证据：`docs/research/motivation-psychology.md`、`docs/research/competitor-incentive-teardown.md`
> - 真实数据定义：`packages/domain/src/milestones.ts`（17 里程碑）、`identity-tags.ts`（8 标签）、`habit-resilience.ts`、`today-progress.ts`
> - 产品原则：`.agents/context/PRODUCT.md`（三个目的地、Anti-references）、`docs/plans/product-principles-2026-11.md`
>
> **一句话结论**：heyta 的「成就体系」**不是**装饰性徽章墙 / 稀有度收藏 / 排行榜，
> 而是一套 **「三层 × 四循环」的成长回路**：L1 即时反馈、L2 连续性与韧性、L3 叙事；
> 真实可展示的"成就"只有三类实体——**17 个里程碑、8 个身份标签、活动分类着色**。
> 因此品牌侧要做的"徽章"，应当是**里程碑的视觉载体**，不是 Litopia 那种 common/rare/epic/legendary 收藏体系。

## 0. 先纠正一个方向错误

Litopia 的成就是"收集稀有度徽章 + 排行榜"，适合社区型内容产品。
**heyta 的产品定位和红线与它相反**：本地优先、可自托管、E2EE 可选、**只与自己比、不制造愧疚、不发行货币**。
把 Litopia 的 rarity 徽章照搬过来，既违背 heyta 的 Anti-references（禁装饰性徽章墙/排行榜/断签惩罚），
也重复了一套产品已经明确否掉的东西。**正确的做法是从 heyta 自己的三层回路出发，设计少量、克制、只增不减的成长标识。**

## 4. 逐体系设计要点（PM 版）

### S1 即时反馈（L1）
- 完成动作 → 200–400ms 确认动效 + 一次轻微音效；**能被关掉**，尊重 `prefers-reduced-motion`。
- 顶部常驻「今日 N/M」进度；M 默认 3–5（宁少不多），可调，**不默认塞全部待办**。
- 全部今日项完成 → 一句**具体的**结束语（"今天推进了 4 件事，专注 65 分钟"），**不给徽章**（信息 > 徽章）。
- 不做：全屏撒花、强制弹窗、需点"确定"的庆祝。

### S2 连续性与韧性（L2）
- 三指标并存：`current`（会断）/`longest`（只增）/`累计`（只增）。**任何界面至少一个只增数字**，断签后不许只显示"0 天"。
- 韧性四级：0 宽限（今天没打不算断）→ 1 冻结（提前装备、上限 2、每连续 7 天 +1）→ 2 续接（断签 24h 内补打卡、无代价）→ 3 重新开始（>7 天，longest/累计保留）。
- "绝不错过两次"：连续错过第 2 天触发**一次**温和干预，一天最多一次，连发 3 天无响应即停，文案必须含用户自己的历史事实。
- 文案禁用：归零/失败/别人都完成了/虚假紧迫；不许红点计数。

### S3 里程碑（17 个，详见 §5）
- 4 维度累计：打卡次数、专注小时、完成任务、使用天数；阈值递进，**只增不减、无扣分**。
- 第一个里程碑要"够得着"（从 10 次/7 天起步），符合目标梯度。
- 纯派生、零 schema 改动。

### S4 身份标签（8 个，详见 §6）
- 给"身份"不是"奖励"；用户可编辑、可隐藏、可关闭整个功能。
- 无金币/无排名/无"超过 X% 用户"。

### S5 回顾复盘
- 周复盘卡：推进了什么 → 最专注一天 → 与上周趋势 → 下周一句话（AI 可选且需隐私边界）。
- 年度视图：热力图升级为年视图，纯派生。
- 不做积分结算、排名、连续考核。

### S6 活动分类着色
- 8 个色槽，**颜色由用户赋义**，App **永不判断某活动"健康/不健康"、永不自动上色**（避免在"戒不掉"的活动上制造内疚）。
- 工程量在时间归因（专注→任务→清单，习惯按分钟），颜色是最后 10%。

### S7 分享
- 唯一对外形态：用户自愿导出图片，带"本机生成"来源标记，**不可证真** → 定位身份表达，非竞技。

### S8 提示（未做，需产品决策）
- 要先决定通知策略：浏览器通知 / 应用内提示 / 只在打开时提示。这是产品决策，不是实现细节。
- 约束：本地触发、不用红点计数、一天≤1 次、3 天无响应即停。

### S9 启动期（未做）
- 新习惯前 7 天"启动期"，与长 streak 分开算，界面写"启动期 3/7"，中断不产生归零观感；7 天后转正式 streak。
- 待拍板：与 `HabitFrequency` 的联动方式。

## 5. 里程碑 17 个全表（PM 定义）

| 维度 | 阈值档 | 单档含义 | 视觉建议 |
|---|---|---|---|
| 累计打卡 `checkIns` | **10 / 50 / 200 / 500 / 1000** 次 | 记录过多少次"我做到了" | 同一维度同一形状，数字递进（如一摞打卡印/日历格点亮） |
| 累计专注 `focusHours` | **10 / 50 / 200 / 1000** 小时 | 真实坐下来的深度时间 | 沙漏/光圈，随小时数增大 |
| 完成任务 `tasks` | **50 / 200 / 1000 / 5000** 件 | 推进了多少实事 | 勾选/清单，累加 |
| 使用天数 `activeDays` | **7 / 30 / 100 / 365** 天 | 你与 heyta 同行了多久 | 日历/年轮 |

> 合计 5+4+4+4 = **17**。每枚只有"已达成 / 未达成"两态，**没有稀有度**、没有掉落、没有可购买。

## 11. 双向闭环：代码 ↔ VI 手册 ↔ 设计系统

**这套 VI 不是从零画的，也不是照抄竞品的。** 它从 heyta 的代码里读出来，再以门禁的形式写回代码 ——
任何一边改动，另一边要么自动跟随，要么被门禁拦下。

### 11.1 取数方式（唯一事实源 + 可复跑的读取器）

所有色值都由 `_pipeline/read_tokens.py` 从 `packages/design-system/src/tokens.css` **解析**得到，
本目录里**没有任何一处手写的色值**：

```bash
PY=/Users/rocalight/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/bin/python3
PYTHONNOUSERSITE=1 $PY brand-kit/_pipeline/read_tokens.py   # 打印八槽与主题色，并实算对比度
PYTHONNOUSERSITE=1 $PY brand-kit/_pipeline/build_badges_v2.py
```

`tokens.css` 里有多段 `:root`（原始色阶 / 语义色 / 尺 / 动效），读取器**合并解析**，
否则 `var(--ht-blue-600)` 这类跨段引用会解析成空值。

### 11.2 里程碑四维色（本次新增，已进代码）

四维色原先**只存在于品牌物料里**，代码里没有对应 token —— 这是双向闭环暴露出来的第一个缺口。
现已作为语义 token 进 `tokens.css`（亮/暗各一份）与 `TOKEN_GROUPS`，并生成到六端产物。

| 维度 | token | 亮色取值 | 与 surface 对比度 |
|---|---|---|---|
| 打卡 | `color-milestone-checkin` | `#2563eb` | 5.17:1 |
| 专注 | `color-milestone-focus` | `#a21caf` | 6.32:1 |
| 完成 | `color-milestone-tasks` | `#059669` | 3.77:1 |
| 天数 | `color-milestone-days` | `#d97706` | 3.19:1 |

| 维度 | token | 暗色取值 | 与 surface 对比度 |
|---|---|---|---|
| 打卡 | `color-milestone-checkin` | `#60a5fa` | 7.17:1 |
| 专注 | `color-milestone-focus` | `#e879f9` | 7.41:1 |
| 完成 | `color-milestone-tasks` | `#34d399` | 9.48:1 |
| 天数 | `color-milestone-days` | `#fbbf24` | 10.92:1 |

**取值必须同时满足三条**（`packages/design-system/tests/milestone-colors.spec.ts` 实算，不是声明）：

1. 与 `color.surface` 对比度 **≥ 3:1**（WCAG 1.4.11 图形门槛）—— 这四档只当图形色用（圆点、档位描边），
   **不进任何正文文字颜色**；余量最小的是亮色的「天数」3.19:1，换色前必须重算。
2. 正常视觉下四档两两 **ΔE ≥ 10**（实测最差 亮 45.7 / 暗 57.6）。
3. 红色盲、绿色盲模拟下四档两两 **ΔE ≥ 10**（实测最差 protan 12.6 / deutan 12.1）。

### 11.4 与用户赋义色的关系

| | 四维里程碑色 | 八槽分类色 |
|---|---|---|
| 谁定义含义 | **产品** | **用户** |
| 用户能改吗 | 不能 | 能（"我把短视频设成 1 号"） |
| 约束 | 四档固定、互可区分 | 两两可区分（含色盲） |
| 用在哪 | 成长页的维度圆点、已达成的档位描边 | 分类色块、堆叠条、图例 |

两者**不共用取值**：把它们混成一套，会让"我给某个清单选了蓝色"和"打卡是蓝色"在同一个屏幕上撞车。

### 11.6 文案同样走唯一事实源（`read_copy.py`）

海报、卡片、手册上的标语与副文案一律由 `_pipeline/read_copy.py` 从
`packages/i18n/src/locales/{zh-CN,en}.ts` 读取，**不在脚本里手写**。
key 不存在时脚本直接抛错，而不是回退到一句兜底文案 —— 品牌物料不该带着编的内容发出去。

```bash
PYTHONNOUSERSITE=1 $PY brand-kit/_pipeline/read_copy.py   # 打印真实标语，逐语言
```

### 11.7 两种分享卡的分工（不要互相"对齐"）

| | 生产用 OG 卡 | 品牌样张 |
|---|---|---|
| 产物 | `apps/landing/public/og-card{,-en}.png` | `brand-kit/09-social/` |
| 生成器 | `apps/landing/scripts/gen-og-card.mjs`（源 `scripts/og-card.html`） | `brand-kit/_pipeline/` |
| 色板 | **暖纸色**（`--ht-paper-*`），刻意区别于产品蓝 | 品牌蓝（`--ht-blue-*`） |
| 文案 | `site.og.card.*`（独立的分享文案，不是首页标语） | `landing.hero.*` |

两者都只消费 token 与 i18n，**但视觉方向不同且都是刻意的**：
链接卡走纸感以区别于产品界面，品牌样张走品牌蓝以代表品牌。改任一张时不要拿另一张当标准。
