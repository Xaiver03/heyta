# 产品体验性能基线

这份读数服务于产品审计中的 PERF-1：任务列表的排序/筛选和本地同步恢复都属于用户能直接感知的等待。它们不是门禁阈值；每次优化后用同一命令重测，比较中位数和趋势。

## 读侧基线

命令：

```bash
pnpm -r build
node scripts/measure-product-ux.mjs 500 1000 5000
```

2026-10-06，Node v22.22.0，macOS：

| 任务数 | `sortTasks(display)` 中位数 | `filterTasks(next7Days)` 中位数 |
|---:|---:|---:|
| 500 | 0.13 ms | 0.07 ms |
| 1000 | 0.11 ms | 0.08 ms |
| 5000 | 0.49 ms | 0.21 ms |

这组读数证明领域读侧在当前规模下不是首要卡点；如果真机验收出现列表卡顿，下一步应量化 React 渲染、虚拟列表和 DOM 行数，而不是先改排序规则。

## 同步恢复基线

命令：

```bash
node scripts/measure-hydration.mjs 500 1000 5000
```

同日同机的中位单次读数：

| 历史 op 数 | 全量恢复 | 增量恢复 100 ops | checkpoint 大小 |
|---:|---:|---:|---:|
| 500 | 16.2 ms | 8.4 ms | 267,982 B |
| 1000 | 56.7 ms | 18.1 ms | 537,495 B |
| 5000 | 426.4 ms | 17.4 ms | 592,993 B |

增量恢复没有回退到全量扫描（`fullScans=0`）。这保留了本地优先产品在重新打开应用时的可感知优势；后续若历史规模继续增大，优先观察 checkpoint 体积和首次打开，而不是牺牲 op-log 的确定性。
