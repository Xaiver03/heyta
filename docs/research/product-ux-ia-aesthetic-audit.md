# heyta 产品 UI / UX / IA / 设计系统审计

> 状态：**当前产品方向基线**（2026-10-06）  
> 范围：Web、移动端、桌面壳、落地页、共享 UI、设计系统。  
> 方法：代码阅读、当前工作树截图、竞品信息架构对照；本文不把门禁通过当成产品体验结论。

## 0. 结论

heyta 的工程纪律强于产品收敛度。颜色、字体、跨端 token、共享组件和本地优先架构已经形成资产；但产品仍同时承载任务、日历、四象限、时间线、习惯、专注、成长、便签、倒数日、AI 和同步，用户还不能快速理解“heyta 最适合怎样工作”。

当前最准确的描述是：**一个视觉克制、功能面过宽、执行路径尚未收敛的本地优先任务工作台。**

产品优化的第一目标不是增加模块，也不是全局玻璃化，而是让用户在十秒内完成三件事：

1. 找到现在该做的事；
2. 快速记录或安排一件事；
3. 清楚知道自己当前处于哪个范围、哪个视图、哪个编辑上下文。

## 2. IA 评审

### 2.1 已成立的结构

- 三层外壳有清晰意图：rail 表达“去哪”，sidebar 表达“当前范围”，main 表达“内容”，detail pane 表达“当前对象”。
- 任务、日历、四象限、时间线正在共享同一批实体和选择状态，避免每个视图各自维护一套任务语义。
- 移动端将四象限、习惯、成长等次级内容放在“我的”或任务页内，避免底部导航无限增长，这个方向正确。
- 模块开关是合理的高级能力，可以让用户收起低频功能。

### 2.2 必须收敛的问题

1. [view-tabs.ts](../../apps/web/src/features/shell/view-tabs.ts) 同时保留“不要做更多”和“收进更多”的相反说明；[App.tsx](../../apps/web/src/App.tsx) 的 `visibleMainTabs` 仍直接渲染启用模块，没有真正的“更多”交互。产品决策、文档和实现没有单一事实源。
2. “视图”和“范围”仍有双重含义：四象限既是完整看板，又可以是任务筛选；任务按钮再次点击又承担回收集箱手势。特殊手势必须有明确的状态反馈。
3. 设置、回收站、帮助、账户、同步仍没有完全从“日常目的地”中分离。低频工具不应该和今天要做的任务争夺一级注意力。
4. 移动端和窄屏 Web 不能把桌面 rail 与 sidebar 简单压成同一条底栏。当前窄屏样式允许长中文标签换行，截图已经出现逐字竖排。
5. 页面状态仍是 React 本地状态，缺少稳定的 URL/深链接策略。短期可接受，随着 landing、帮助、桌面 URL scheme 和跨端恢复增加，会成为方向性债务。

### 2.3 推荐 IA

**一级目的地：** 任务、日历、专注、习惯、搜索。

**任务范围：** 收集箱、今天、最近 7 天、已完成、清单、标签、自定义筛选。

**次级工具：** 四象限、时间线、便签、倒数日、成长、回收站。

**全局入口：** 同步、账户、设置、帮助、数据导出、隐私与安全。

这个结构把“执行任务”和“使用方法”分开：四象限、时间线仍然保留，但不再与任务本体争夺同一级产品地位。

## 3. 视觉审美评审

### 3.1 资产

- 蓝白和冷灰体系可靠，暗色主题不是简单反相。
- 当前三栏截图已经比旧版顶栏多 tab 更清楚。
- 内容面保持实色，悬浮层才使用材质，这是正确的层级判断。
- 设计系统已经把颜色、字号、字重、对比度和跨端 token 变成可复用资产。

### 3.2 主要问题

- 当前整体像“精致后台”，还不像有鲜明性格的个人效率产品。蓝色圆点、冷灰背景、白卡和细边框容易落入通用 SaaS 语言。
- 空态留白过大。`0/0`、AI 工具、输入框和中央空态同时出现，却没有唯一主动作。
- 四象限空区域过大，四张卡片的空白比任务更突出。
- 详情列把备注、子任务、清单、重复、RRULE、截止和提醒平铺，技术配置压过了任务本身。
- AI 工具调用放在任务主路径上，安全说明很重要，但“调用工具”是高级动作，不应与新建任务处于同一视觉层级。
- 设置页仍可能保留任务详情列，造成设置上下文与任务编辑上下文相互竞争。
- 截图目录同时存在旧顶栏视觉和新 rail 视觉，评审基线不一致。

### 3.3 视觉原则

1. 首屏只保留一个主动作：记录或安排任务。
2. 内容面保持实色，材质只用于导航条、菜单、浮层和短生命周期面板。
3. 卡片只有在表达独立层级时使用；四象限和设置应更多依靠空间分组，而不是四面白卡。
4. 中文标签必须在窄屏保持单行可读，不能依赖自然换行表达层级。
5. 品牌需要体现“安静、可信、私密、可执行”，而不只是蓝色和圆角。

## 4. 交互评审

### P0

- 设置、帮助、搜索等全局表面打开时，应关闭或隐藏与当前对象无关的详情列。
- 窄屏底部导航不得同时承载 rail 与范围 sidebar。
- AI 工具调用默认收起，主输入框必须成为唯一首要动作。

### P1

- 详情列按“基本信息 / 时间 / 组织 / 自动化”分组，RRULE 原始文本放入高级设置。
- 四象限空态压缩，任务多时才扩展。
- 任务行的 AI 拆解、AI 估时、删除等次级动作应在 hover、选中或详情列中出现，避免每行同时有多个 CTA。
- 空态提供一个明确动作和少量示例，不再只留下大面积留白。

### P2

- 视图切换、完成任务、打开详情和保存应拥有统一的短动效；动效服务于状态变化，不做装饰循环。
- 搜索、同步、AI 远程出境和本地处理需要有一致的披露组件。

## 5. 设计系统评审

当前设计系统“值”层较强，“行为”层不足。下一步应补充：

- list / board / pane / sheet 的使用契约；
- density、empty、loading、error、disabled、selected、focused 状态矩阵；
- detail pane 的分组与折叠规则；
- 桌面到窄屏的导航降级规则；
- 材质档位和 reduced-transparency 行为；
- 原生壳对 XAML、GTK、Swift 的 token 消费契约。

## 6. 产品级结论

现阶段不建议继续增加一级模块，也不建议把内容面全面玻璃化。应先完成 IA 收敛、核心任务闭环、详情列分组、窄屏导航和设置上下文隔离，再把隐私和本地优先能力转化成用户能理解的体验。

## 6.1 设置界面专项审计与竞品对照

整改前的设置页把个人资料、显示、功能模块、同步、隐私、AI、导入导出、账号安全和帮助串成单一长流。这个结构的问题是信息架构问题：所有面板都像同一层级，用户必须先滚动才能找到关闭出口，也无法建立“我正在解决哪类问题”的心智模型；管理员、数据迁移和注销等低频高风险能力还会打断日常设置。

对照 Todoist 的公开设置结构，账号、一般设置、主题、通知等稳定问题域被分开，用户可以从目录直接进入目标类别；对照 Apple Human Interface Guidelines，设置应按稳定类别分组、使用可预测的返回路径，并让当前焦点落在用户触发的目标控件上。两者共同点是把“找设置”变成分类选择，而不是滚动竞速。

本项目据此做出以下产品裁决并已落地：

| 判断 | 当前实现 |
|---|---|
| 设置属于低频全局工作区，不是任务详情的附属表单 | 独立设置表面，打开时详情列隐藏，关闭后恢复原选中对象 |
| 桌面需要同时看见分类与内容 | 左侧 sticky 分组目录 + 右侧内容区 |
| 窄屏不能把桌面长流原样压缩 | 顶部横向目录，标签保持单行，内容区不与底层任务文字透叠 |
| 关闭和返回必须可预测 | 首屏标题区直接提供关闭按钮；由既有 Esc/返回路径退出 |
| 分组按用户问题而不是实现模块命名 | 个人资料、任务与显示、同步与隐私、AI 与集成、数据管理、账号与安全、关于与帮助七组 |

这次整改解决了 IA、焦点顺序、遮蔽关系和渐进披露的第一层问题；它没有把每个面板内部的业务复杂度伪装成已解决。AI 授权、密钥库轮换、导入导出、注销等内容仍应在后续批次继续采用二级页或默认折叠，避免把高风险动作与日常外观设置放在同一操作密度。

## 7. 执行后复核（2026-10-06）

第 2–6 节是整改前的审美与交互基线。整改已把其中的 P0/P1 主路径落到代码：首屏主动作收敛为任务输入，AI 默认收起，设置不再与详情列并列，窄屏导航标签保持单行，低频视图进入“更多”，详情面按行为规范分组；四象限保留 2×2 铺满的空间心智模型，只去掉重复引导并把规则说明收进帮助。当前视觉证据见 [`apps/web/evidence/product-ux-2026-10-06/`](../../apps/web/evidence/product-ux-2026-10-06/)，行为规则见 [`docs/reference/design-system-behavior.md`](../reference/design-system-behavior.md)。

设置页另做了一次产品级重排：它不再把个人资料、同步、AI、数据迁移和账号安全串成一条无目录长流，而是用桌面左侧分组目录、窄屏顶部横向目录和首屏可见关闭出口组织成七个问题域。设置背景改为不透明，底层任务视图仍保留在 DOM 以保证返回上下文，但不再产生“任务文字透过设置”的视觉噪声。

这些修改没有宣称品牌视觉已定稿：蓝白冷静 SaaS 语言、内容面与浮层材质边界、动效节奏和跨端原生投影仍是后续审美工作；本轮验收重点是信息层级、主路径和设置可理解性。四端当前产物已按 `pnpm reinstall:all` 的分端收口流程完成清旧、重打、重装与启动判据验收。
