## 0. 怎么用（先读这一节）

### 0.1 两个维度，缺一个都叫「没学到」

一格要算「学到了」，必须**同时**满足：

| 维度 | 含义 | 缺它会怎样 |
|---|---|---|
| **产品实现度** | heyta 有没有这个屏（有 / 半有 / 无） | 没有 = 功能缺口，用户直接感受得到 |
| **一手靶子** | 我们有没有**亲眼看过**滴答这一屏长什么样（截图 / 录屏 / uiautomator dump） | 没有 = 就算做了，也是凭猜做的，永远「不像」 |

🔴 **最危险的不是「无」，是「没靶子还在做 / 要做」** —— 做出来一定是猜的，下一轮又被打回。
`feature-matrix` 时代我们只盯第一个维度，所以「功能清单」看着挺全，产品却总差一口气。

### 0.2 五个档（每格落一个；由「实现度 × 靶子」两维机械算出，见 §0.3 脚本）

| 档 | 产品 | 靶子 | 处置 |
|---|---|---|---|
| **A 完全学到** | 有 | 有 | 只需保判据 |
| **H 半有** | 半有 | 有 | 照靶子补齐差的那半 |
| **B 缺靶子** | 有/半有 | 无/待核 | 补靶子再校，**别宣称「已对齐」**（「看着有其实凭猜」） |
| **C 缺功能** | 无 | 有 | 照靶子做，成本最低、最不会做歪 |
| **D 双缺** | 无 | 无/待核 | **先取证再动手**，否则必然是猜的 |

> 🔴 **「有功能」严格 = 实现度「有」，不含「半有」**。半有单列 H：功能只做了一半，即使有靶子也只是半学到。把半有并进 A 会虚高「学到的格数」——这是 v0.1 犯过的错（曾报 34 格已学到，收紧后只有 23，其中 4 个还是 heyta 独有）。

### 0.3 怎么重算（不许手抄会漂的数字）

```sh
# 实现度分布（从 surface-matrix §1 现量，79 格）
python3 - <<'PY'
import re,collections
rows={}
for ln in open('docs/research/ticktick-surface-matrix.md'):
    m=re.match(r'^\|\s*(\d+)\s*\|',ln)
    if m:
        c=[x.strip() for x in ln.strip().strip('|').split('|')]
        if len(c)>=5 and int(m.group(1))<=79:
            rows[int(m.group(1))]=re.split(r'[ ·（(]',c[-1])[0]
print(collections.Counter('无' if v.startswith('无') else '半有' if v.startswith('半有') else '有' if v.startswith('有') else '其它' for v in rows.values()))
PY
# 2026-11-24 现量：有 47 / 半有 11 / 无 21  （其余 0）
```

## 9. 滴答清单自己的四个实体：文件夹 / 清单 / 标签 / 筛选器（数据模型 + UI 双证）

> 产品负责人 2026-11-25 点名「说的是**滴答清单**」。这一节只讲**滴答自己的模型**（证据：`ticktick-data-model-parity.md` 表 #4/#5/#6/#27 的 macOS `ZTT*` 表 + Windows `*Model` 类 + Mac/Android 实拍），heyta 对照放 §9.4。

### 9.1 其实是**四个**实体（不止三个——还有"筛选器/智能清单"）

| 概念 | 滴答表(mac) / 类(win) | 关键字段 | 是什么 |
|---|---|---|---|
| **清单 List** | `ZTTPROJECT` / `ProjectModel` | `ZKIND`(kind)、`ZGROUPID`(groupId)、`ZISINBOX`(isInbox)、`ZVIEWMODE`、`ZSORTOPTION` | 任务的**唯一物理归属**；`groupId` 让它挂到某个文件夹；`isInbox` 标记收集箱 |
| **文件夹 Group** | `ZTTPROJECTGROUP` / `ProjectGroupModel` | `ZNAME`、`ZEXPANDED`、`ZSHOWSALL`、`ZSORTTYPE`、`ZSORTOPTION` | **独立实体**，只收纳**清单**（清单靠 `groupId` 指向它）；不管任务；无 parent 列 ⇒ 一层 |
| **标签 Tag** | `ZTTTAG` / `TagModel` | `ZNAME`、`ZLABEL`、`ZCOLOR`、**`ZPARENT`**、**`ZCOLLAPSED`**、`ZSORTOPTION` | 任务的**多值属性**、跨清单；🔴 **`parent`+`collapsed` ⇒ 滴答标签自带层级（标签可嵌套成树）**，比"便利贴"更强 |
| **筛选器/智能清单 Filter** | `ZTTFILTER` / `FilterModel` | `ZNAME`、**`ZRULE`（查询 DSL 字符串）**、`ZSORTTYPE`、`ZVIEWMODE` | **保存下来的查询**（既不是清单也不是标签）；产出虚拟任务列表 |

### 9.2 「感觉重复」的真正来源：滴答有 **4 种**「都能出任务列表」的东西

在滴答里能"装任务/出列表"的：**清单、标签、智能清单（内置 今天/最近7天…）、过滤器（自建）**。看着都能"分类"，其实是四种不同职责：

- **清单 = 物理归属**（必选、单亲；任务"放在哪"）
- **文件夹 = 清单的抽屉**（只管清单、不管任务）
- **标签 = 属性**（多选、多亲、跨清单、**还能嵌套**；任务"是什么/什么情境"）
- **筛选器 = 保存的条件**（虚拟、不归属；任务"我想怎么看"）

🔴 **判断口诀：只有「清单」是必选且唯一的归属；其余三个都是视角/属性，不改变任务的家。**

### 9.3 容易在"概念讲解"里被略掉的两个滴答事实（数据模型实证）

1. **标签是树，不是平铺**：`ZTTTAG` 有 `ZPARENT`/`ZCOLLAPSED` —— 父子标签 + 折叠态。所以"工作/客户A"可以作为"工作"的子标签；这比单纯的"便利贴"强一档。
2. **每视图独立排序**：滴答 macOS 有 7 张 `ZTTSORTORDER*` 表（通用/置顶×2/截止日/清单/优先级/标签），即"同一任务在『今天』的序号 vs 在它清单里的序号"是**分开存**的 —— 这正是"清单 / 标签 / 筛选器 是不同视角"的底层支撑（换个视角，顺序空间就换了）。

### 9.4 heyta 对照（brief，差异是取舍不是对错）

| 维度 | 滴答 | heyta | 性质 |
|---|---|---|---|
| 清单 | `ZTTPROJECT` | `Project`（`Task.projectId` 单归属） | 对应 |
| 文件夹 | **独立实体** `ZTTPROJECTGROUP` | `Project.parentId`（一层，**不建独立实体**） | 有意简化（`project-hierarchy.ts` 严格一层） |
| 标签 | `ZTTTAG` 带 `parent`（**可嵌套**） | `Tag` **平铺无 parent** | 滴答多一层能力 |
| 筛选器/智能清单 | `ZTTFILTER` 的 `rule` **DSL 字符串实体** | `TaskFilter` compound（web 已交付，**实体化待 ADR-0092**） | 滴答是独立实体；heyta 半实体 |

> 映射到 §3：清单 #4、文件夹 #20、标签 #33、筛选器 #19、智能清单设置 #18、排序 #34。
