# heyta 个人中心产品决策记录

> 日期：2026-10-07
> 状态：**已接受**
> 依据：现有 `AccountMenu`、设置页 IA、共享成长模型，以及 Todoist、TickTick、Things 与 Apple Human Interface Guidelines 对账号入口、设置分层和个人统计的公开模式对照。

这份记录定义个人中心与设置、成长视图之间的边界。它不新增账号事实源，也不改变同步模型；后续实现与验收以本记录为准。

## 1. 个人中心的职责

个人中心回答三个问题：**我是谁、我最近完成了什么、我正在成长什么**。它是一个低密度的身份与回顾入口，不是设置表单，也不是第二个成长报表。

个人中心首屏只保留：

1. 身份头部：头像、昵称/邮箱、端到端加密与本地优先状态；
2. 近期状态：本周完成任务、专注时间、习惯打卡三个摘要数字；
3. 成就预览：已获得与下一项接近的里程碑，提供“查看完整成长”；
4. 明确出口：编辑个人资料、打开设置、查看完整成长。

不在个人中心首屏放同步凭据、AI 授权、数据导入导出、注销账号或管理员功能。这些动作仍由设置页的既有分组承载。

## 2. 个人中心、设置、成长的关系

| 表面 | 用户心智问题 | 允许的内容 | 进入方式 |
| --- | --- | --- | --- |
| 头像菜单 | 我现在要去哪 | 个人中心、编辑个人资料、设置、成长、退出登录 | 点击头像 |
| 个人中心 | 我是谁、我完成了什么 | 只读身份摘要、近期状态、成就预览、跳转入口 | 头像菜单 → 个人中心 |
| 设置 → 个人资料 | 我要修改身份资料 | 昵称、头像、邮箱说明 | 个人中心 → 编辑个人资料；头像菜单 → 编辑个人信息 |
| 成长 | 我要看完整趋势和里程碑 | 现有 `GrowthView` / `GrowthBoard` 全量投影 | 个人中心 → 查看完整成长；头像菜单 → 成长 |
| 设置其他分组 | 我要改变应用行为或账号安全 | 任务与显示、同步与隐私、AI、数据、账号安全、帮助 | 头像菜单 → 设置 |

个人中心与设置共用同一个次级 surface 机制。个人中心只是该 surface 的概览模式；点击“编辑个人资料”会切换到设置的个人资料组，而不是再打开一个新的浮层或复制一份表单。

## 3. 头像菜单结构

已登录时顺序固定为：

1. 身份区（邮箱或昵称）；
2. 个人中心；
3. 编辑个人信息；
4. 设置；
5. 成长（仅在成长模块启用时出现）；
6. 分隔后的退出登录。

未登录时只显示登录/注册、设置和本地可用入口，不显示个人中心、编辑个人信息和退出登录。危险动作保持在菜单末端，并与普通入口保持视觉区分。

这个顺序延续现有 `AccountMenu` 的可访问菜单行为：菜单获得焦点，方向键循环，Esc 返回头像按钮，点击外部关闭。新增个人中心只增加一个入口，不改变既有“编辑个人信息”到设置锚点的兼容路径。

## 4. 成就展示原则

成就使用现有 `milestonesFromState` 与 `MilestoneMap`，不新增统计表或持久化字段。个人中心只取前两层信息：

- 已获得的里程碑数量与最近进度；
- 下一项里程碑的目标与差距。

完整成就仍在成长视图中按打卡、专注、任务、活跃天四个维度展开。未达成项目可见但不使用错误色；成就只增不减，不因断签扣除，不显示公开排行榜，也不把用户与他人比较。每个数字必须与成长页共享同一投影函数和同一个 `now`。

## 5. Web 与移动端的投影

Web 采用头像菜单 + 次级 surface，保留任务视图作为下层上下文。移动端保留五个一级 tab，“我的”是个人中心根页；设置、完整成长、账号安全等继续进入现有二级 push/pop 栈。两端使用相同的身份、成长选择器和成就组件，差异只在壳的布局与返回方式。

移动端个人中心首屏同样优先身份、同步状态和少量入口；清单、标签、便签管理属于账户工具区，保持在个人中心下方，不提升为新的一级导航。

## 6. 竞品与平台依据

- Todoist 与 TickTick 都把账号/头像作为低频设置与个人状态的入口，把编辑资料放在账号设置中，而不是占用任务导航。
- Things 的个人状态是轻量的偏好与设备信息，不把大量统计塞到账号菜单。
- Apple Human Interface Guidelines 对设置与账户信息采用“按用户意图分组、逐层进入、保留清晰返回出口”的原则；复杂或高风险设置不与日常身份摘要混在同一层。
- heyta 的本地优先与端到端加密状态属于身份上下文，因此在个人中心头部以简短说明呈现；详细凭据和隐私操作仍只在设置中出现。

## 7. 验收标准

- 头像菜单能同时到达个人中心、编辑个人资料、设置和成长；旧的编辑资料入口仍能直接落到昵称输入框。
- 个人中心不出现重复的昵称/头像写入逻辑，不直接修改设置表单状态。
- 个人中心的三个近期数字与成长页使用同一选择器，切换语言、主题、窄屏和同步刷新后不漂移。
- 成就预览至少包含一个已达成或下一项进度说明，并提供完整成长入口；无排行榜、无断签惩罚。
- 关闭个人中心后保留打开前的任务视图与滚动位置；Esc、关闭按钮、点击外部和键盘焦点行为与现有设置 surface 一致。
- 所有可见文案进入中英词条；样式只消费设计 token；暗色、窄屏和 `:focus-visible` 均有真实验收。

## 2026-10-07 实施勘误

本文件保留初始讨论；当前规范见[账号 IA](../reference/account-information-architecture.md)，状态见[优化计划](../plans/profile-center-optimization.md)。本轮核实了 Todoist 与 Things 的官方账号路径，TickTick 复用已有调研，Apple HIG 未作新的现场核验，前文泛化描述不能当作本轮实测。

初版概览只显示邮箱/首字母，未满足“真实 Profile”承诺，现已接入既有账号 API 的只读身份投影；资料写入继续留在 ProfilePanel。新增“返回个人中心”及成长开关联动。移动端保留原位资料编辑作为现阶段平台差异，设置入口前移。所谓“成就只增不减”不包括用户主动撤销或删除记录引起的真实统计重算。


## 2026-10-07 原生 UX 回读后的最终收敛

iPhone 实际页面确认“我的”仍有内联资料编辑与长管理表单，因此撤销本轮前期“移动端暂留原位编辑”的阶段性取舍。当前实施以 [IA 规范](../reference/account-information-architecture.md) 为准：编辑器唯一地投影到设置个人资料组；个人中心只读身份、短回顾与入口。设置采用目录与分组，详细同步、数据、安全回到各自分组；清单/标签/便签改为二级工具入口。返回统一接入既有 profile 栈，本地摘要同时响应本地写入和同步更新。
