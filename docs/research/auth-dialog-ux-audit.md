# 认证入口 UX 对照与决策

更新时间：2026-10-07

## 对照范围

本轮用匿名请求访问了两个仍在维护的产品入口：

- [Linear signup](https://linear.app/signup)（HTTP 200，最终地址仍为 `/signup`）
- [Todoist signup](https://todoist.com/auth/signup)（HTTP 200，最终地址为
  `https://app.todoist.com/auth/signup`）

页面会根据浏览器、地区和登录状态继续渲染，因此这里记录的是入口形态与信息架构
原则，不把某次服务端下发的营销文案当成 heyta 的产品事实。

## 可借鉴的入口结构

两者都把“开始使用”收敛到一个短表单，先让用户完成身份输入，再展开更多验证方式；
辅助认证与企业/自定义配置不会和第一步并列争夺注意力。Todoist 的入口还把注册与登录
放在同一条路径内，减少用户先判断“我是注册还是登录”的负担。Linear 的页面更强调
单一主任务与留白，视觉上没有把技术配置当成新用户的前置条件。

heyta 的认证协议有更多能力（密码、通行密钥、邮件链接、自托管地址、令牌回填），但
这些能力不应该改变入口的认知顺序：

1. 邮箱是第一步，`继续` 同时承接登录与注册。
2. 密码是第二步，页面回显当前邮箱，避免在两个身份之间产生歧义。
3. 通行密钥、邮件链接、找回、自托管地址和令牌粘贴属于“其他方式/高级设置”，保持
   渐进披露。
4. 服务端地址只在未配置或用户主动选择自托管时出现，官方托管不要求用户猜域名。

## 本次设计决策

认证弹窗使用“开始自己的自律计划”作为轻量的视觉主题：桌面左侧只保留计划标题、
一句说明和当天开始的短句，右侧仍是原来的共享 `AuthForm`。它不展示虚假的任务、
进度或成就；移动端只保留一行紧凑标题，保证邮箱输入与主操作在首屏内优先可见。

对话框 `aria-label`、控件 testID 和认证状态保持原有契约。视觉层使用设计系统
语义 token，不使用蓝色下划线堆叠；次级入口以低对比边框/背景区分，服务端地址和令牌
合并到一个默认收起的“高级选项”中。弹窗在窄屏变为
底部 sheet，在桌面保持紧凑双栏；滚动只发生在弹窗内部。`prefers-reduced-motion` 会
关闭入场动画。

## 验收重点

- 375px：主路径不被计划装饰、服务端说明或高级入口挤出；关闭按钮和输入控件保持触控
  尺寸与焦点环。
- 1440px：双栏层级清楚，计划区是辅助信息，不重复渲染一份可操作表单。
- 亮色/暗色：表面、边框和文字都从同一套语义 token 取值。
- 无障碍：保持 dialog 名称、live region、字段标签、键盘焦点和原有 testID。
- 降低动态效果：系统设置 reduced motion 后不得出现入场动画。

## 2026-10-07 追加：验证码、密码反馈与注册仪式感

用户指出的缺口成立：目前服务端发的是验证链接；注册界面没有验证码输入步骤、确认密码或实时强度反馈。“开始自律计划”只有短暂行入场，不足以构成用户要求的动态场景。只读生产核对确认 SMTP 已配置且邮箱验证开启，可复用现有邮件服务，不能把“已有发件邮箱”当成“已有验证码流程”。

核读来源（2026-10-07）：

- [NIST SP 800-63B-4 §3.1.1.2](https://pages.nist.gov/800-63-4/sp800-63b.html)：单因子密码最少15字符；至少支持64字符；允许Unicode和空格；禁止额外字符组成规则；常见/泄露密码黑名单。当前产品此前显式选定8～256码点，仍属于已记录偏离；注册邮箱验证并不等于每次登录的多因素认证。
- [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)：本地强度提示、阻止常见/泄露密码、允许密码管理器与长密码；不要用强制字符拼凑代替强度。
- [GOV.UK Confirm an email address](https://design-system.service.gov.uk/patterns/confirm-an-email-address/)：支持链接或验证码，但必须解释去邮箱再返回的旅程，提供重发，明确过期，一次性消费，新验证码使旧码失效。确认邮箱只证明当时可访问邮箱，不证明自然人身份。
- [GOV.UK Passwords](https://design-system.service.gov.uk/patterns/passwords/)：注册与登录使用不同的字段自动填充语义，支持显示密码，避免无意义输入负担。本次按用户明确要求保留注册二次确认，不放到登录中。
- [OWASP Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)：短码/令牌需安全生成、过期、单次消费和限速；统一响应避免枚举。该文档的“二次输入密码”建议针对重置场景，不能误写成所有注册表单的强制行业标准。

实施边界：验证码单独挑战并绑定待设密码，避免注册劫持；低熵六位数字不以裸SHA哈希存储，而用服务端密钥域分离HMAC。客户端不负责最终密码安全裁决，强度仅建议。背景场景与真实账号数据分离，所有装饰从无障碍树移除；不在用户输入时持续移动表单。
