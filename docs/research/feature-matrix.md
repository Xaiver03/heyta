# 滴答清单 / TickTick 功能对照矩阵

> 用途：这是本项目（heyta）的**需求基准线**。我们不是要"抄界面"，而是要**功能等价**。
> 状态：草稿 v0.1，基于公开资料整理，**待逐项实机核对**。
> 图例：`P0` = 没有它产品不成立；`P1` = 核心竞争力；`P2` = 差异化/锦上添花；`—` = 不做

---

## 1. 任务对象模型（数据模型的地基）

| # | 能力 | 优先级 | 备注 / 难点 |
|---|------|--------|-------------|
| 1.1 | 任务标题 / 描述（富文本或 Markdown） | P0 | 描述里支持 Markdown 是加分项 |
| 1.2 | 子任务（树形，可折叠） | P0 | 递归结构，注意无限层级与排序 |
| 1.3 | 优先级（无 / 低 / 中 / 高） | P0 | 四色，与四象限联动 |
| 1.4 | 标签（多对多） | P0 | 标签需要独立管理页 |
| 1.5 | 所属清单（List/Project） | P0 | 清单可分组（文件夹） |
| 1.6 | 开始时间 + 截止时间 | P0 | 时间块（time blocking）的基础 |
| 1.7 | 全天 / 定时任务 | P0 | 日历视图区分两种渲染 |
| 1.8 | 重复规则（RRULE） | P1 | **难点**：每周几、每月第几个周几、结束条件、"完成后顺延" |
| 1.9 | 提醒（一次 / 多次 / 提前 N 分钟 / 位置提醒） | P1 | 跨端通知是最大工程坑之一 |
| 1.10 | 附件 / 图片 | P2 | 涉及对象存储 |
| 1.11 | 评论 / 备注 | P2 | 协作场景才需要 |
| 1.12 | 完成时间 / 创建时间 / 修改时间 | P0 | 统计与"已完成"清单依赖 |
| 1.13 | 回收站（软删除 + 恢复） | P1 | 同步场景必备 |
| 1.14 | 排序（手动拖拽 / 按时间 / 按优先级） | P0 | 手动排序需要小数位/lexorank 方案 |

## 6. 协作与同步

| # | 能力 | 优先级 | 备注 |
|---|------|--------|------|
| 6.1 | 清单共享（邀请成员） | P2 | **已实现（E2EE 邀请凭证 + 成员角色 + 所有权转让）** — 证据见 [dida365-feature-benchmark.md](dida365-feature-benchmark.md) §2.6 的 6.1 与 `pnpm verify:collab-journey`；多人并发写同一条任务的写路径路由仍是最大连通件 |
| 6.2 | 任务指派 / 分配 | P2 | 🔴 **已建模、不可达**（W4 残余）：`Task.assigneeUserId` 在 `packages/domain/src/entities.ts` 里是**可选字段**且在加密 payload 内，通知过滤层（`packages/ui/src/sync/notification-model.ts` 的「指派给我的」那档）**已经在读它** —— 但全仓**没有任何一处写它**（`packages/app-host` 零个指派 op 构造、`apps/*` 零个界面）。⇒ 差的是写入者与入口，不是数据模型。⚠️ `check:reachability` 只覆盖**实体**，字段级的"已建模≠可达"它拦不住 |
| 6.3 | 评论 | P2 | 🟡 **宿主层通了、界面上只有 owner 那一侧走得到；移动端还没挂**：组件 — `packages/ui/src/sync/CommentThread.tsx`；宿主写路径与下行 — `packages/app-host/src/share-comments.ts`；挂载 — `apps/web/src/features/share/ShareCommentsSection.tsx`（由任务详情挂，反查 `grep -rln "ShareCommentsSection" apps` 只回一处）；宿主层两实例互拉 + WS 扇出 — `pnpm verify:collab-sync`（`RESULT=OK steps=11`）。⚠️ 别把那一格读成"两台浏览器互相看得到"：验收里的"两台"是**两个无界面宿主实例**；成员那侧的共享清单行只有 `addProject` + `setProjectShare`（无 share 日志拉取）⇒ 空清单、点不进评论区。⚠️ 这一格以前写的是"apps/* 与 app-host 对它零引用、差最后一米" —— 那句话在 2026-10-21 之后已经不成立，别照它施工（会造出第二份评论区）。仍然没做的：移动端的评论区、成员侧的界面入口（随 M2），以及**除评论以外那一族 op 还没进 share log**（`TASK` 的共享写路径是 M2，要先立 ADR）|
| 6.4 | 多设备实时同步 | P0 | **决策已定并已接线**：模型仍是 op-log（不是 CRDT），服务端只发信号、成员自己拉并解密（ADR-0062 决策 7）。两条信号都有宿主在接 —— 个人 `new_ops` ⇒ 跑一次普通同步，共享 `new_share_ops` ⇒ 宿主判断该不该拉、`@heyta/ui` 谓词决定要不要吵（反查 `grep -rn "createHostRealtimeClient(" apps packages`；读数见 [collaboration-shared-lists.md](../plans/collaboration-shared-lists.md) §9.10）|
| 6.5 | 离线可用（offline-first） | P0 | |
| 6.6 | 冲突解决 | P0 | CRDT 或 last-write-wins + 字段级合并 |
| 6.7 | 分享清单为链接 / 公开清单 | P2 | **入群链接已实现**（owner 生成 `?shareToken=`、点开进加入流程，Web 落点）；**公开清单未做** |
