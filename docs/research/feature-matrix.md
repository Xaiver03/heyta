# 滴答清单 / TickTick 功能对照矩阵

> 用途：这是本项目（heyta）的**需求基准线**。我们不是要"抄界面"，而是要**功能等价**。
> 状态：草稿 v0.1，基于公开资料整理，**待逐项实机核对**。
> 图例：`P0` = 没有它产品不成立；`P1` = 核心竞争力；`P2` = 差异化/锦上添花；`—` = 不做

---

## 1. 任务对象模型（数据模型的地基）

| # | 能力 | 优先级 | 备注 / 难点 |
|---|------|--------|-------------|
| 1.1 | 任务标题 / 描述（富文本或 Markdown） | P0 | 描述里支持 Markdown 是加分项 |
| 1.2 | 子任务（树形，可折叠） | P0 | 递归结构，注意无限层级与排序 |
| 1.3 | 优先级（无 / 低 / 中 / 高） | P0 | 四色，与四象限联动 |
| 1.4 | 标签（多对多） | P0 | 标签需要独立管理页 |
| 1.5 | 所属清单（List/Project） | P0 | 清单可分组（文件夹） |
| 1.6 | 开始时间 + 截止时间 | P0 | 时间块（time blocking）的基础 |
| 1.7 | 全天 / 定时任务 | P0 | 日历视图区分两种渲染 |
| 1.8 | 重复规则（RRULE） | P1 | **难点**：每周几、每月第几个周几、结束条件、"完成后顺延" |
| 1.9 | 提醒（一次 / 多次 / 提前 N 分钟 / 位置提醒） | P1 | 跨端通知是最大工程坑之一 |
| 1.10 | 附件 / 图片 | P2 | 涉及对象存储 |
| 1.11 | 评论 / 备注 | P2 | 协作场景才需要 |
| 1.12 | 完成时间 / 创建时间 / 修改时间 | P0 | 统计与"已完成"清单依赖 |
| 1.13 | 回收站（软删除 + 恢复） | P1 | 同步场景必备 |
| 1.14 | 排序（手动拖拽 / 按时间 / 按优先级） | P0 | 手动排序需要小数位/lexorank 方案 |

| # | 视图 | 优先级 | 说明 |

| 2.10 | 搜索（含即时搜索） | P1 | 本地优先架构下需要索引 |

## 10. 数据与迁移（免费替代品的杀手锏）

| # | 能力 | 优先级 | 备注 |

| 10.1 | 从滴答清单 / Todoist 导入 | P1 | **最有效的获客手段**：让用户能带着数据走 |
| 10.2 | 全量导出（JSON / CSV / ICS） | P0 | 反锁定，也是信任来源 |
