## 1. 结论摘要

heyta 落地页在**单页叙事的完成度**上明显强于对标物（滚动叙事、真实界面复现、3D 同步场景、
隐私逐字加密），但它**只覆盖了访客四分之一的路**。

滴答清单的访客有四条明确的路 —— **了解功能 → 选平台安装 → 比较付费 → 遇到问题查帮助**，
外加两条常驻的 **登录 / 注册**。heyta 现在只覆盖了第一条的一半。

| # | 访客的问题 | heyta 现在 | 缺口性质 |
|---|---|---|---|
| 1 | 这东西具体能干什么？ | 6 格 bento + 3 屏展厅 | 没有**功能介绍页**，只有一段摘要 |
| 2 | 我怎么开始用？装在哪？ | 只有「立即使用 → `/app/`」 | 没有**平台/下载页**，也看不到各端真实进度 |
| 3 | 要花钱吗？花在哪？ | 首页一段三栏定价 | 没有**定价页**（对比表 / FAQ / 到期会怎样） |
| 4 | 我有个问题怎么办？ | 什么都没有 | 没有**帮助中心**，也没有更新动态 |
| 5 | 我已有账号，怎么进去？ | 导航里**没有登录入口** | 没有 `/signin`（应用内的认证面板藏在同步设置里） |

## 2. heyta 落地页现状（配置清单）

只写**代码里真的有什么**。日期 2026-09-28。

### 2.1 形态

| 维度 | 现状 | 证据 |
|---|---|---|
| 技术栈 | Vite 7 + React 19 + `motion/react` + `three`（懒加载）+ `lucide-react` | `apps/landing/package.json` |
| 入口数 | **2 个**：`index.html`（中文 `/`）与 `en/index.html`（英文 `/en/`），**共用同一份 bundle** | `apps/landing/vite.config.ts` 的 `input: { main, en }` |
| 路由 | **无路由库**。整站一页，所有导航都是页内锚点 | `apps/landing/src/Landing.tsx` |
| 开发端口 | 5180 | `apps/landing/vite.config.ts` |
| 打包切分 | `three` 单独成 chunk（131 kB gzip），由 `<Deferred>` 滚动触发才取 | `vite.config.ts` `manualChunks` + `Landing.tsx` |

### 2.2 页面区块（10 段，每段布局族不同）

顺序与理由写在 `apps/landing/src/Landing.tsx` 文件头：

| # | 区块 | 组件 | 布局 |
|---|---|---|---|
| 1 | 英雄区 | `Hero.tsx` | 非对称分栏（左文右 3D 景） |
| 2 | 事实条 | `Hero.tsx` 的 `Facts` | 四栏等分 |
| 3 | 能力 | `Capabilities.tsx` | bento 网格（**6 项能力 = 6 个格子**） |
| 4 | 真实界面展厅 | `Showcase.tsx` | 滚动固定的横向切换（3 屏） |
| 5 | 同步 | `SyncScene.tsx`（懒）+ `SyncFallback.tsx` + `SceneBoundary.tsx` | 全宽 WebGL 画布 |
| 6 | 隐私 | `Privacy.tsx` | 滚动驱动的逐字加密 |
| 7 | 价格 | `Pricing.tsx` | 三栏（免费自建 / ¥5 托管 / ¥12 托管+AI） |
| 8 | 自建 | `SelfHost.tsx` | 分栏（终端 + 三步） |
| 9 | 收尾 CTA | `FinalCta.tsx` | 居中宣言 |
| 10 | 页脚 | `Footer.tsx` | 品牌 + 2 组链接 + 免责声明 |

> 🔴 **价格排在自建之前是刻意的**（`Landing.tsx` 文件头）：叙述是
> 「只有一件事收费 → 而免费的那条路就在下面」。反过来会让读者先读完一整段终端流程
> 才看到收费档，那时他已经不知道自己在选什么。

|---|---|---|

| 主题切换 | — | 总是 |

**没有**：登录 / 注册 / 下载 / 帮助 / 更新动态 的入口。

### 2.4 页脚（`Footer.tsx`）

| 分组 | 条目 | 指向 |
|---|---|---|
| （品牌区） | 字标 + tagline | — |
| 产品 | 功能介绍 / 真实界面 / 同步 / 隐私 | 全部页内锚点 |
| 开始使用 | 价格 / 自建 | 全部页内锚点 |
| 底部 | 许可说明与帮助入口 | — |

🔴 页脚**曾经**有 6 组指向 GitHub 的链接（源码 / 贡献指南 / 路线图 / ADR /
第三方许可证 / 文档索引），因为**仓库当前是私有的**、对访客一律 404，整组摘掉了。
加回来的完整清单（**别只把图标放回来**）写在 `Nav.tsx` 顶部注释里，并由
`apps/landing/tests/render.spec.tsx` 的一条用例钉住判据：**整页文本里不该出现 `github.com`**。

### 2.5 语言与文案

| 维度 | 现状 |
|---|---|
| 词条来源 | `@heyta/i18n`（**唯一文案事实源**，`packages/i18n/src/locales/{zh-CN,en}.ts`） |
| 命名空间 | `landing.*`，实测约 **150 个 key** |
| 语言判定 | **由 URL 路径决定**（`src/lib/locale.ts`），不由 `navigator.language` —— 理由是 SEO |
| 门禁 | `pnpm check:ui-language`：界面里不许出现硬编码文案 |
| 取文案方式 | 数据表在组件内用 `useMemo(() => [...], [t])` 现构造，**不把 key 存进数据** |

### 2.6 SEO 与可发现性

| 项 | 现状 | 证据 |
|---|---|---|
| `<title>` / `<meta description>` | 两版各一份，**互不相同** | `index.html` / `en/index.html` |
| `<html lang>` | `zh-CN` / `en` | 同上 |
| canonical | 两版各自指向自己 | 同上 |
| hreflang 三件套 | `zh-CN` / `en` / `x-default`，**两版逐条一致** | 同上 + `tests/seo-head.spec.ts`（12 条） |
| sitemap.xml | **只有 2 个 URL**（`/` 与 `/en/`），刻意不列锚点、不列 `/app/` | `apps/landing/public/sitemap.xml` |
| robots.txt | `Allow: /` + `Disallow: /app/` + sitemap 指向 | `apps/landing/public/robots.txt` |
| favicon | `favicon.svg`（品牌蓝点 + 字标首字母） | `apps/landing/public/favicon.svg` |
| **OG / Twitter Card** | ❌ **完全没有** | 实测 grep 两版 HTML，`og:*` / `twitter:*` 零命中 |
| **og:image** | ❌ 没有 | 同上 |
| **结构化数据（JSON-LD）** | ❌ 没有 | 同上 |
| 分析 / 统计 | ❌ 没有（无 GA / Plausible / Umami） | 全仓无相关依赖 |

> **分享预览是零成本、纯收益的一格。** 现在把 `https://heyta.finlaw.cloud/`
> 贴进微信 / X / Slack，得到的是一张没有图、没有描述的裸链接 ——
> 与"页面本身做得很讲究"是矛盾的：最讲究的那一页，在别人转述它的时候消失了。

### 2.7 主题与动效

| 维度 | 现状 |
|---|---|
| 主题 | 亮色为主、可切暗色；只改 `<html data-theme>`，组件零改动 |
| 防闪烁 | `index.html` 里**样式表之前**同步执行的主题引导脚本，与 `src/lib/theme.ts` **共用同一个 storage key** `heyta.theme` |
| 动效 | `motion/react`；`src/lib/motion.ts` 的 `useMotionPreset()` 统一处理 `prefers-reduced-motion` |
| 已有审计 | `docs/plans/landing-motion-audit/`（5 份改造单 + README） |

### 2.8 应用入口（`src/lib/app-url.ts`）

| 状态 | 行为 |
|---|---|
| `VITE_APP_URL` **已配置** | 英雄区 / 定价免费档 / 收尾 CTA 三处「立即使用」→ 绝对外链；导航多一条；英文页带 `?lang=en` |
| `VITE_APP_URL` **未配置** | **逐字退回**指向 `#selfhost`，标签变成「开始自建」；导航**不出现**那条 |

🔴 未配置时**不渲染入口**是刻意的：应用没部署却露出「立即使用」比没有入口更坏。
校验规则是"非 `http(s)` 一律当没配置"，防止一个拼错的变量变成一个指向 404 的 `href`。

### 2.9 构建与部署

来源：[../runbooks/deployment.md](../runbooks/deployment.md) §3.7。

```bash
cd apps/landing && VITE_APP_URL=https://heyta.finlaw.cloud/app/ pnpm exec vite build
rsync -az --delete apps/landing/dist/ ubuntu-jcli:/var/www/heyta-landing/
```

| 事实 | 值 |
|---|---|
| 线上地址 | `https://heyta.finlaw.cloud/`（根，**不是 `/landing/`**） |
| 应用地址 | `https://heyta.finlaw.cloud/app/`（**同源**，passkey 才能用） |
| 托管方式 | nginx `location /` → `root /var/www/heyta-landing;` + SPA 兜底 `try_files $uri $uri/ /index.html` |
| 旧域名 | `heyta-tmp.litopia.space` 的 `/landing*` 现在 **301** 跳过来 |
| 🔴 应用构建 | 必须带 `--base=/app/`，否则资源去请求落地页路径、拿回 HTML（现象是样式表 MIME 变成 `text/html`） |

## 3. 双向对齐矩阵

### 3.1 三个方向

"双向对齐"在这里是**三个方向**，缺一不可：

| 方向 | 含义 | 做错的代价 |
|---|---|---|
| **A 对标补齐** | 滴答清单有、我们没有 | 访客找不到他要的东西（下载？帮助？登录？） |
| **B 能力回填** | 我们有、站点没说 | 做了但没人知道 —— **最贵的浪费** |
| **C 明确不对齐** | 结构上不该抄 | 抄了就是说谎（假下载页 / 假功能闸门表） |

### 3.2 逐项矩阵

| # | 滴答清单有 | heyta 现状 | 方向 | 我们的形态（结论） |
|---|---|---|---|---|
| 1 | 首页品牌叙事 + 五大支柱 + 社会证明 | ✅ 有，叙事更强 | — | **保持**。不要为了"像它"改成它的排版 |
| 2 | **功能介绍页**（7 板块全量目录） | 🟡 只有首页 6 格 bento + 3 屏展厅 | **A** | 新增 `/features`：**按功能模块**逐模块展开 + 真实界面截图。**只写已实现的**；未实现的进「路线图」而不是混进功能介绍（清单见 [dida365-feature-benchmark.md](dida365-feature-benchmark.md)） |
| 3 | **下载页**（7 平台 × 分发方式） | ❌ 完全没有 | **A（改形态）** | 新增 **`/platforms`（各平台状态）**，不叫"下载"：Web 立即可用；桌面有**未签名**的 `.app`/`.exe`/`linux` 包（`release/`，由 `scripts/package-desktop.mjs` 产出）；移动端 Android 实机跑通、iOS 模拟器跑通、**鸿蒙未跑起来**。逐条写**真实状态 + 可复现命令**，而不是"即将推出" |
| 4 | **定价页**（两档 + 逐项对比表 + 3 条 FAQ） | 🟡 只有首页一段三栏，无对比表、无 FAQ | **A + C** | 新增 `/pricing`：三栏 + **「自建 vs 我们托管」对照** + FAQ。🔴 **不能抄它的功能闸门表**（列表数 9→299 那类）：我们收费的只有 `hosting` 与 `ai`（[ADR-0020](../adr/0020-ai-subscription-two-tiers.md) §3.2，由 `check-pricing-consistency.mjs` 强制）。FAQ 必须答：**到期会怎样 / 数据在哪 / 怎么导出 / 现在能不能买**（现在是**买不到**的，必须如实说） |
| 5 | **帮助中心**（97 篇，按功能模块组织，含「更新动态」一级分类） | ❌ 完全没有。只有仓库内 `docs/`（给贡献者看） | **A + B** | 新增 `/help`。内容**从 `docs/` 派生但面向用户重写** —— 仓库文档含 ADR、迁移纪律、环境陷阱，直接暴露既看不懂又泄露实现细节。组织方式借它的结论：**按功能模块**，并保留「更新动态」 |
| 6 | **登录 / 注册**（两个独立入口，导航第一类公民） | ❌ 落地页无入口；应用内 `AuthPanel` 开在**同步设置内部** | **A** | 新增 `/signin`（+ `/signup`）：**不重写认证 UI** —— 真正的认证仍在 `/app/`（认证要用的服务端地址就是同步设置里的地址，分开会出现"对着 A 登录、令牌存到 B"，见 [../plans/roadmap.md](../plans/roadmap.md) §5.1 第 2 条）。所以 `/signin` 是**带说明的跳板**：说清支持哪几种方式（通行密钥 / 邮件魔法链接），点进 `/app/` |
| 7 | **法律三页**（Terms / Privacy / License） | 🟡 **文本存在但不可达**：`server/legal/*.heyta.md` + 服务端渲染的 `/privacy` 模板，落地页**一个链接都没有** | **B** | 页脚加 Legal 组，指向**已有的**服务端页面。🔴 加链接前先核实线上真的能打开 —— 一个 404 的法务链接比没有更坏 |
| 8 | **更新动态**（5 条 2026 + 3 个年度归档） | ❌ 没有 | **B** | 我们**有极好的素材**：`docs/plans/roadmap.md` §5 每条都带日期与实测证据。做 `/changelog`，从 git tag / 提交派生 |
| 9 | 教育优惠（75 折）/ 礼品卡 | ❌ 没有 | **C** | **不做**。我们月付 ¥5/¥12、非 AI 能力永久免费、自建永久免费 —— 再打 75 折是把价格变成噪音；礼品卡需要一个我们还没有的支付通道 |
| 10 | 媒体资料包（`press.zip`） | ❌ 没有 | **C（暂缓）** | 现在没有报道需求，做了是空转。**等第一次被报道前再做** |
| 11 | 社会证明（媒体引用 + 6 位用户证言） | ❌ 没有 | **C** | **不能造。** 我们还没有用户。替代品是**可验证的证据**：真实界面复现（已有）、`pnpm verify:*` 的实测输出、公开的审计文档。**证言位先空着，不填** |
| 12 | URL Scheme（`ticktick://`）/ MCP / CLI | ❌ 没有 | **B（形态不同）** | 我们**有它没有的**：本机 API + MCP server（6 个工具）+ 出站 AI 的 BYOK / 自托管端点。做 **`/integrations`**，讲**数据主权**：MCP、本机 API、自托管、导出。这是差异化页，不是对标页 |
| 13 | 微信集成（助手 / 提醒） | ❌ 没有 | **C（暂缓）** | 需要公众号 + 服务端明文，**与 E2EE 冲突**。写进「明确不做」清单，不要挂在路线图上吊着 |
| 14 | 平台清单（7 平台 + 浏览器扩展 + 手表） | 🟡 首页事实条**不提平台**（四条是 离线 / 不限设备 / 加密同步 / 一套数据）；导航也没有入口 | **A + 诚实** | 与 #3 合并。**平台状态必须能被 [../plans/roadmap.md](../plans/roadmap.md) 的状态表逐条对上** —— 写"可用"就必须给出可复现的验证命令，写"进行中"就要给出证据 |
| 15 | 联系 / 支持入口（工单页 `dida365.com/v3/tickets/`） | ❌ 没有 | **A** | 帮助中心页脚给一个联系入口（邮箱或表单）。**先确认真的有人看** —— 一个没人回的信箱比没有更坏 |
| 16 | OG / Twitter Card / og:image | ❌ 没有 | **B** | 补 `og:*` / `twitter:*` + 一张 1200×630 分享图。**零成本、纯收益** |
| 17 | 结构化数据（JSON-LD） | ❌ 没有 | **B** | `SoftwareApplication` + `FAQPage`（定价页 FAQ 就位之后）。🔴 **`aggregateRating` 不能编** —— 没有真实评分就别写 |
| 18 | 独立子域（帮助中心） | ❌ 单页 | **C** | **不拆子域**。规模不需要，拆了只会让 SEO 分散、部署多一个环节 |
| 19 | 40+ 主题 / 清单背景 | ❌ 没有 | **C** | 明确不做（设计系统只有语义 token；`Note` 实体已明确否决自由 hex） |
| 20 | 站内搜索 | ❌ 没有 | **C（暂缓）** | 帮助内容量还不够撑一个搜索框。**等文章数超过 ~30 篇再做** |
| 21 | 多语言（中文 / English 切换） | ✅ 有（双静态入口 + hreflang） | **B** | 已做，但**新增的每一页都要跟着做双入口 + hreflang** —— 这是最容易漏的一半 |
| 22 | 国际站独立域名（ticktick.com） | ❌ 没有 | **C** | 不做。我们的海外定价 `$5/$12` 已在同一站点的定价区表达 |

### 3.3 三条最刺眼的现状

按"访客会撞到的顺序"排：

1. **没有任何"登录"入口。** 访客读完一整页，唯一能点进应用的是「立即使用」——
   而那是"打开应用"不是"我有账号"。滴答清单把 Sign In / Sign Up 放在导航里，
   是因为**回访用户和首次用户走的是两条不同的路**。
2. **没有平台/下载页。** 访客看不出"我能在哪些设备上用、现在能不能用"。
   我们其实有大量**可验证的实测证据**（桌面三平台包已在 `release/`、Android 实机、
   iOS 模拟器 36 项零 mock、鸿蒙 20 MB HAP），**一条都没露出来**。
3. **没有帮助中心，也没有更新动态。** 这是"产品在活着"的两个最便宜的证明，
   而我们恰好有全仓库最扎实的素材（`docs/plans/roadmap.md` 的逐条实测记录），
   却只对贡献者可见。

## 4. 不能照抄的地方（写清楚，免得下一个人又试一遍）

| 想抄的 | 为什么不能 | 我们的形态 |
|---|---|---|
| 功能闸门对比表（清单 9→299、附件 1/天→199/天…） | 我们不按功能收费（[ADR-0020](../adr/0020-ai-subscription-two-tiers.md) §3.2），且服务端看不到明文、**没有能力执行功能闸门** | 对照「自建」vs「我们托管」 |
| 「Upgrade Now」购买按钮 | `check:payment-entry.mjs` 会红 —— 生产 compose 没有 `WECHAT_*`，线上只有 noop adapter，结账必然 `503` | 如实写"现在买不到 + 为什么"；渠道接通那天门禁会**要求**我们加按钮 |
| 下载页列 iOS / Android / 鸿蒙安装包 | 那些**可发布**的包不存在（桌面有包但**未签名/未公证**） | 平台状态页 + 证据命令 |
| 微信提醒 / 微信助手 | 与 E2EE 冲突（服务端要读明文） | 「明确不做」清单 |
| 用户证言 / 媒体引用 / 评分 | 没有真实用户与报道 | 空着，用可验证的实测证据代替 |
| 40+ 主题 / 清单背景 | 设计系统只有语义 token | 明确不做 |
| `aggregateRating` 结构化数据 | 没有真实评分 | 不写 |
| 教育优惠 / 礼品卡 / 连续包月 | 需要我们没有的支付通道与价格结构 | 不做 |

## 5. 结论

**对齐不是把页面做成一样，而是把"访客的下一步"补全。**

滴答清单的站点之所以有那些页面，是因为它的访客有明确的路；
heyta 现在只覆盖了其中一段。我们的形态必须**逐页重新推导**
（因为 E2EE / 不按功能收费 / 没有可发布安装包这三处结构性差异会改变每一页的内容），
但**页面的存在性**是对齐的：**功能介绍、平台状态、付费说明、帮助中心、登录**
这五件事一个都不能少。
