# heyta 产品决策记录：第二阶段收敛

> 日期：2026-10-06  
> 依据：`product-level-ia-ux-audit.md`、`product-ux-ia-aesthetic-audit.md`、`product-ux-optimization.md`

这份记录把上一轮审计留下的开放项直接裁决为可执行范围。后续实现与验收以本记录为准；如果新的证据要推翻它，必须新增决策记录，不在代码注释里悄悄改方向。

## 1. 品牌视觉

heyta 继续使用蓝白、冷静、可信、隐私优先的基调。品牌深化只增加一个稳定的识别锚点：主界面的页头显示小型 `heyta` 品牌眉标，使用主蓝和语义文字 token；图标、按钮、任务行和表单仍保持扁平、克制、可扫描。

不引入全局玻璃化、渐变背景、装饰性粒子或为了展示品牌而增加动效。材质只留给浮层与导航，品牌记忆由色彩、字标和一致的间距节奏承担。

验收：页头在亮色、暗色和窄屏都可见且不挤压标题；不新增裸色值；主路径首屏仍只有一个主动作。

## 2. 批量、撤销与手势

第一阶段提供任务列表多选，以及批量完成、移动清单、软删除。一个用户意图只产生一个带批量作用域的 op：删除沿用 `DEL` 墓碑语义，字段批量更新使用 `BATCH`。重复任务混入批量完成选择时整批阻止并解释原因，避免把“完成一次”误解为推进重复规则。

本阶段只为批量删除提供 5 秒 undo toast。撤销只回放这一次删除动作的反向意图，超过窗口后不保留假性的“历史可撤销”状态；批量完成与移动暂不显示撤销入口，因为它们需要保存原始字段快照才能安全反向。移动端先用长按进入多选，暂缓复杂左右滑动，避免滑动方向与系统返回、列表滚动冲突。

验收：选择态有明显但不跳动的行标记；工具栏只在选择态出现；完成、移动、删除可从键盘和触摸命中；Esc/返回退出选择；undo 在窗口内可用，超时后自动消失。

## 3.1 设置页信息架构

设置是低频的全局工作区，不再用一条没有目录的超长表单承载所有能力。桌面端采用左侧分组目录、右侧内容区；窄屏端把同一目录变成顶部横向滚动栏。分组固定为：个人资料、任务与显示、同步与隐私、AI 与集成、数据管理、账号与安全、关于与帮助。

关闭出口在设置首屏标题区内可见，设置内容使用不透明背景，底层任务视图仍保留在 DOM 以便关闭后回到原上下文，但不让底层文字透过来干扰阅读。高风险或低频能力仍由各自面板负责渐进披露；本轮先解决入口、分组、焦点顺序和滚动定位，不新造二级路由。

参考判断：Todoist 的设置按账号、一般、主题与通知等用户心智分组；Apple 的设置以稳定分类和逐层进入降低认知负担。heyta 采用相同的“按问题分组”原则，同时保留本地优先与隐私信息的解释顺序。

## 3. 清单级视图属性

第一阶段只承诺两项清单级属性：已有颜色，以及设备本地的排序偏好。排序偏好按清单 id 保存，未选择清单时沿用全局偏好；它是阅读偏好，不进 op-log、不跨设备同步。

暂不引入每清单默认看板/日历，也不引入自定义智能清单实体。四象限、时间线和日历继续是全局视图，避免把“清单是什么”和“从哪个视角看”混成持久化模型。

## 4. 移动端二级导航栈

五个 tab 是一级根导航。二级页面统一使用 push/pop 栈：打开详情、设置子页或编辑器时入栈；系统返回和页面返回优先 pop，栈为空才回到当前 tab 根页面。切换 tab 不销毁其他 tab 的栈和滚动状态。

本阶段不引入深链和第三方导航库；先把栈语义统一，等出现真实分享链接需求再评估 URL 映射。

## 5. 四端重装验收

交付定义是当前源码产物在 macOS、Windows、Android、iOS 四端重新安装并通过各自启动判据。`pnpm reinstall:all` 是唯一收口命令；Android 构建通过 `windows-pc`，Windows 来源树做 sha256 对账，任何一端失败都使整轮失败。门禁、单元测试和截图只能证明代码行为，不能替代重装验收。

## 6. 取舍顺序

执行顺序固定为：先统一写入语义和 undo，再统一移动端栈，再补品牌眉标与清单排序偏好，最后跑 Web/移动端交互证据和四端重装。任何实现如果扩大一级导航、引入第二套排序事实源或把本地偏好写进同步日志，都不接受。
