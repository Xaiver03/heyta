### 2.2 一行任务上到底显示了什么（信息密度）

一行 = **「复选框 + 标题」主干** + **右侧右对齐元数据区** + **可选第二行备注**：

| 槽位 | 内容 | 出现条件 |
|---|---|---|
| 左 | 复选框 30×30 px（15×15 pt），圆角方框 | 恒有 |
| 中 | 标题（**唯一的主色白字**，字号最大） | 恒有 |
| 右（远） | **清单名**（如 `收集箱`） | 仅普通任务；习惯任务不显示 |
| 右（近） | **日期/时间徽标**：纯文字 `今天`/`明天`/`11:30`/`15:00`，或 `🗓+文字` | 恒有 |
| 右（中） | 计数徽标 `0/5 页` | 仅习惯任务 |
| 右（中） | 闹钟图标（无时间） | 仅「早睡」 |
| 第二行 | 备注摘要，灰、小一号，**单行截断加省略号** | 有备注时 |

- **复选框颜色 = 优先级**（**推断**，见 §8）：**红 = 高 / 橙 = 中 / 蓝 = 低 / 灰空心 = 无**。图面上同批任务的复选框颜色与四象限视图中的象限归属完全一致，支持这一推断。
- **排序与分组**：按**日期升序**分组（今天 → 明天 → 9月30日），组内**习惯任务被单独抽成一个「今日习惯」组**。计数徽标（5 / 17 / 17、组名后的 1/4/2/6）全部右对齐。
- **未在同一行显示的字段**：标签、子任务计数、附件、重复规则、优先级文字——这些在本列表行上**不可见**。

### 2.3 交互线索

- **悬停**：任务行悬停出现整行圆角浅色底（`完成学习网站的公安备案` 行实测 `y≈272–350` 有浅底高亮）。侧栏分组标题悬停出现 `+`。
- **右键 / 拖拽 / 悬停更多按钮**：**不可见**（本轮未测，属红线跳过项）。
- 顶栏 `↓↑` 的 tooltip 是「排序」。

### 2.4 空态与装饰

③ 右栏 ④ 在无详情时是一整块**低对比线稿插画**（描边亮度远低于正文）：铅笔、马克笔、咖啡杯、摊开的笔记本、便签纸、点赞气泡、手表、回形针等文具主题，散布排布。**不抢视线**，也不会被误认为可点内容。

## 3. 日历视图（`03-calendar.png`）

- **无侧栏**，rail 右侧直接是日历（主区吃掉 ② ③ ④）。
- **顶栏**：左侧 `▦ 2026年9月`（粗体大字）；右侧依次为 圆形 `+`、`月 ⌄`（视图切换）、`‹` / `今天` / `›`（连体分段按钮）、`…`。
- **周表头**：`周日 周一 周二 周三 周四 周五 周六`，灰字居中。
- **月网格**：6 行；**每行最左显示周序号**（`35周`…`39周`），低对比灰字——中文用户很受用的一栏。
- **日期格**：
  - 日期数字在格子**左上角**；
  - **非本月日期**（首行 30、31）整体降透明度灰化；
  - **今天（28）**用**蓝色圆角实底 + 白字**高亮；
  - 格与格之间是**极细的分隔线**（不是卡片间距），形成"表格"而非"卡片"观感。
- **节假日原生标注**（中文场景刚需）：
  - 绿色节日文字：**教师节**（9/10）、**中秋节**（9/25）、**国庆节**（10/1）；
  - **红色小「休」角标**：20、25、26、27、1、2、3 日——即调休放假日。
- **格内任务条**：深色圆角条 + 单行文字；**习惯类任务前缀一个「✓」勾图标**，普通任务不带（如 `✓阅读` `✓学英语` `✓涂药膏` vs `要回文化传媒公司的尾款（3 万余元）`）。
- **溢出计数**：28 日格底显示 `+6`，30 日格底显示 `+3`，其余被折叠。
- 任务条**不显示时间**（即使列表里有 11:30 / 15:00 / 17:00），只显示标题——**日历格是"标题级"密度，不是"任务行级"密度**。

## 4. 四象限视图（`04-quadrant.png`）

- **无侧栏**，主区是 **2×2 等分网格**，四块独立深色圆角面板，面板之间有明显间距。
- **象限标题** = 序号圆点 + 文字，序号用罗马数字字形：
  | 象限 | 标题 | 序号圆点颜色 |
  |---|---|---|
  | 左上 | **重要且紧急** | 红 |
  | 右上 | **重要不紧急** | 橙/黄 |
  | 左下 | **不重要但紧急** | 蓝 |
  | 右下 | **不重要不紧急** | 绿 |
- **每格内部再按清单分组**：`⌄ 收集箱 N`，N 为该格该清单的任务数（实测 3 / 5 / 2 / 7）——**在空间分区之上又叠了一层清单分组**。
- **任务行**：复选框 + 标题 + 右侧 `收集箱` + 日期徽标。
- **实测四格内容**（含复选框颜色，是"优先级色"推断的主要证据）：
  - **重要且紧急**（3，全**红**）：到杭州银行蒋村支行开户 `后天`；提交黑塔清单类工具的 APP 备案 `后天`；提交学习 APP 的备案 `后天`
  - **重要不紧急**（5，全**橙**）：办理应用算法备案；提交黑塔清单类应用的公安备案；注销杭州信声有限公司 `周四`；在 DeepSeek 申请企业实名认证 `后天`；完成学习网站的公安备案 `今天`
  - **不重要但紧急**（2，全**蓝**）：去滨江观晖美寓接小猫 `明天`；要回文化传媒公司的尾款（3 万余元）`明天`
  - **不重要不紧急**（7，全**灰空心**）：国庆期间发放两店志愿者福利 / 薪资 `周四`；核算长郡滨江店志愿者福利 / 薪资 `后天`；核算雅礼洋湖店志愿者福利 / 薪资 `后天`；办理股东变更为个人独资公司 `下周四`；联系北京税务局办理注册地址迁移 `下周四`；…
- **日期徽标形态**：`今天`/`明天` 是蓝字；`周四`/`下周四` 是灰字——**近两天用蓝色强调，更远用灰**。
- 右上角 `…`（更多）。每格**独立滚动**（右下格内容在底部被裁切）。

**关键设计点**：象限归属是**由「优先级 + 日期」自动推导**的，不是用户手工拖进去的（**推断**：同一任务在列表视图的复选框颜色与它所在的象限严格对应）。用户无法直接把任务拖进某个象限——这点与 Eisenhower Matrix 的常见交互不同。

## 10. 哪些做法值得抄 / 哪些不适合我们

### 10.1 值得抄

1. **rail 用「留白」把导航和工具分成上下两段**。上段是"去哪看"（任务/日历/四象限/习惯/搜索），下段贴底是"干点啥"（同步/通知/帮助），中间 400px 留白。**不靠分隔线、不靠标题**，只用距离就完成了语义分组——非常干净，抄。
2. **选中态 = 整块填充白，未选中 = 中性灰**。同一形状只换填充，不做额外的背景条/左侧指示条。截图里能一眼读出当前视图，**状态可被"截图咖啡测试"直接读出**，这是很高的标准。
3. **复选框颜色编码优先级**（红/橙/蓝/灰）。一行任务不需要"优先级"三个字、不占第二个字段位，颜色就是优先级，**信息密度白赚一档**。
4. **"标题 — 右侧右对齐元数据 — 第二行小灰备注"的三段式任务行**。右侧元数据统一右对齐成一条隐形的列，备注用更小更暗的字并**单行截断**。结果是：一行能塞下清单名 + 时间 + 备注，却不觉得挤。这是我们最该照搬的一条。
5. **四象限把抽象维度变成空间分区**，而且每个象限内部**继续按清单分组并给计数**——不是"四个筐"，而是"四个带小标题的看板格"。每格独立滚动。
6. **习惯的进度三层表达**：表头环形（今天）+ 卡片 7 点阵（本周）+ 闪电/火焰天数（长期）。**不用打开详情就知道坚持了多久**，这是习惯类产品最核心的一屏信息设计。
7. **日历原生标注中文节假日**：绿字节日名 + 红「休」角标（调休）。中文场景刚需，很多同类产品没有。
8. **"相对 + 绝对"双写日期**：分组标题写 `今天, 周一` 和 `9月30日, 周三`；详情面板写 `今天, 9月28日`。既有亲切感又无歧义。
9. **聚焦后才长出的次级控件**（快速添加条的日期 chip）。常态零噪音。
10. **tooltip 全覆盖**：rail 每个图标都有名字（日历/习惯打卡/通知/同步实测）。对一个图标密集的 rail 来说，这是必需的低成本学习路径。
11. **习惯任务在主任务列表里被抽成独立分组「今日习惯」**，且不显示清单名——同一份数据在"任务"和"习惯"两个视图里各自呈现最合理的样子。

### 10.2 明显不适合我们

1. **右侧 36% 宽的空态插画区**。在 1063pt 宽的桌面窗口里很优雅，但**这块区域在没有详情时是纯浪费**；四象限视图干脆把它吃掉了。如果我们做的是窄窗口 / Web / 移动端，**这块必须回收**——它成立的前提是"桌面宽屏 + 任务详情需要常驻一栏"。
2. **对比度偏低**。正文是白字没问题，但分组标题、日期、备注、周序号都是 `#1c1c1c` 底上的中灰（目测 40–45% 亮度）。暗色主题下在强光环境/低质量屏上会糊。**不值得照抄这个对比度**，我们应把次要文字提到 WCAG AA 以上。
3. **"清单/过滤器"空态引导卡吃掉大量纵向空间**。侧栏在无数据时挂两张 2 行的说明卡，是新手引导形态，不是高频使用形态。**我们用不起**——应把空态压缩成一行，或做成可关闭的引导。
4. **"同步"占了一个一等 rail 位**。手动同步按钮和"任务/日历"平级，是历史包袱。现代产品应自动同步，这个位置应回收（或降级进"更多"）。
5. **四象限不可直接拖拽**。象限归属由优先级+日期**自动推导**，用户看不到映射规则、也无法把任务拖进某个象限。**心智模型不透明**——如果我们要做矩阵视图，应做成显式可拖拽 + 显示推导依据，否则用户会困惑"为什么这条在第二象限"。
6. **帮助入口常驻 rail 底部**。占位成本很高（两个图标位给了同步和帮助）。一般产品放进菜单/设置即可。
7. **日历格不显示时间**。一天有多个定时任务时，格内只有标题、看不到 11:30/15:00，必须点开。**对有强时间安排的场景（会议、日程）不够用**，我们需要在格内保留时间位。
8. **习惯视图的 7 天点阵很吃横向宽度**。窄窗口下会退化成挤压或横向滚动，移动端不能照搬。

## 11. 空态 / 插画 / 暗色主题的具体表现

- **暗色主题**：全局单一暗底（背景亮度 28，rail 36，分隔线 39）。没有渐变、没有玻璃拟态、没有大面积高饱和色块；彩色只用在**复选框描边、标签圆点、日期强调、习惯图标**这些小面积语义点上。**"暗底 + 小面积高饱和语义色"** 是这套配色的骨架。
- **两处装饰插画，都是低对比线稿**：
  1. 右栏空态：文具主题线稿（铅笔、马克笔、咖啡杯、摊开的笔记本、便签、点赞气泡、手表、回形针），散布排布；
  2. 搜索空态：双手举望远镜插画 + 文案 `搜索任务、标签、清单和过滤器`。
  两处都只做"这里现在没东西"的柔性提示，**不做 CTA、不引导点击**。
- **侧栏空态**（清单/过滤器）用灰色圆角卡 + 2 行说明文字，与上述插画是两种不同的空态语汇（一个是"内容区空"，一个是"功能未启用"）。
- **分隔线**承担了主要的结构表达（1px 亮线，横竖都用），几乎不用阴影——只有搜索浮层有阴影。

## 11.5 🔴 「设置」是**浮层**，不是应用内的一页（补充实测，2026-09-29）

⚠️ **本节与 §12 的那条边界冲突，以本节为准。** §12 原本记着
「设置页 / 账户页 / 会员页：**未进入**（会改状态的入口，跳过）」—— 那是第一轮采集的**缺口**。
第二轮由用户直接给出截图，补上了这一条。

**实测形态**（截图：左侧 rail 与列表**仍在**，被压暗；右侧滑出设置面板）：

```
┌────┬──────────┬───────────────────────────────┐
│rail│ 列表(暗) │  设置                          │
│    │          │  ┌──────────┬────────────────┐ │
│    │          │  │ 账号      │  头像 / 昵称     │ │
│    │          │  │ 高级会员  │  邮箱           │ │
│    │          │  │ 功能模块  │  会员到期日      │ │
│    │          │  │ 智能清单  │                │ │
│    │          │  │ 提醒与通知│  [退出登录]      │ │
│    │          │  │ 日期与时间│  [删除账号]      │ │
│    │          │  │ 外观 …    │                │ │
│    │          │  └──────────┴────────────────┘ │
└────┴──────────┴───────────────────────────────┘
```

⇒ 它有**自己的两级结构**（左：设置分区导航；右：该分区的详情），
而**整块盖在当前视图之上**，与 §6 的搜索浮层、§7.1 的通知浮层同族。

### 11.5.1 于是「浮层 vs 应用内」的规律是清楚的

| 表面 | 形态 | 证据 |
|---|---|---|
| 任务 / 日历 / 四象限 / 习惯 | **应用内视图**（rail 切换主区） | §2–§5 |
| 任务详情 | **面板**（占用右栏 ④，左侧列表**仍可见**） | §8 |
| 快速添加 | **同一根添加条的两态**（聚焦 / 未聚焦）—— **不是弹窗** | §9 |
| 搜索 | **居中浮层**（下层视图仍可见） | §6 |
| 通知 | **侧向浮层**（贴 rail 右侧、近满高） | §7.1 |
| 帮助 | **菜单**（rail 底部） | §7.2 |
| **设置** | **侧向浮层面板**（两级结构，盖在当前视图上） | 本节 |

🔴 **规律**：**主视图（任务/日历/四象限/习惯）用 rail 切换、留在应用内；
次级/瞬态表面（搜索 / 通知 / 设置 / 任务详情）一律用浮层或面板，且不离开当前视图
—— 下层的上下文始终可见。**

⇒ 这条规律**不是"弹窗更省事"**，而是：**用户在这些表面里做的事，都需要"回头看下面"**
（搜索时看列表、通知时看列表、设置时也看得到自己在哪个视图）。
**主视图之间切换时不需要这种"回头"，所以它们才留在应用内。**

## 12. 边界与不确定性（推断 vs 实测）

**未采集 / 未测**：
- **番茄钟 / 专注视图**：rail 上**不存在**该入口（点击 + tooltip 双重验证），故未采集；任务书给的 `(58,510)` 实为「习惯打卡」。
- **任务详情面板的完整字段**：首屏未见优先级/标签/子任务/提醒/重复控件，未滚动深挖（见 §8）。
- **右键菜单、拖拽排序、行悬停快捷操作、多选**：截图不可见，本轮未测。
- **浅色主题**：全程暗色，未切换（切换外观属"改设置"，按红线跳过）。
- **设置页 / 账户页 / 会员页**：未进入（会改状态的入口，跳过）。
- **日历的周视图 / 日视图**：只截了月视图（按钮显示 `月 ⌄`），未展开下拉。
- **侧栏「今天 / 最近7天 / 收集箱」三者的差异**：只看了「最近7天」，未切换另外两个（切换本身只读、安全，但本轮时间用在了 rail 映射纠偏上）。

**属于推断、不是实测**：
1. **「复选框颜色 = 优先级」**——依据是四象限视图中四个象限的复选框颜色恰好分别为红/橙/蓝/灰，且同一任务在列表与矩阵中颜色一致。**未打开任务编辑面板确认优先级字段。**
2. **「⚡ = 连续天数、🔥 = 累计天数」**——依据是数值（22/8/1/21 天）与习惯连续性描述吻合；界面**无文字标签**。
3. **「`≡` = 展开/收起描述」**（详情面板标题右侧）——纯形态推断。
4. **日期徽标上「🗓」小图标的语义**——可能是"重复任务"或"已设提醒"，**未确认**。
5. **rail 头像右上角橙色小徽标的含义**——**未确认**。
6. **四象限的归属规则**（优先级 × 日期）——由上一条颜色证据 + 象限名字面义推断。

**过程性边界**：
- 目标窗口初始在**另一个 Space**，坐标写操作被内核以 `refused: cross-space` 拒绝；最终靠 `mac open 滴答清单` 把窗口拉到当前 Space 才可点击。**副作用：会把滴答清单切到用户当前桌面**（对用户可见）。
