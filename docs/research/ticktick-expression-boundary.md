## 0. 三句话

1. **机器能判的只有「来源」，判不了「相似」。** 所以判据不能写成「像不像它」，只能写成「这堆字节有没有我们自己的来源」——
   后者能红，前者只能靠人吵。
2. **仓里已经有两条形状对的先例**：`check:design-token-refs`（每个 `var(--ht-*)` 必须解析到定义）与
   `check:brand-assets`（产物必须 **==** 由 token 生成的那一份）。缺的那条门禁不是新发明，
   是**把这两条从「名字 / 图标」搬到「全部资产字节」**（§4.3 判据 A）。
3. **root `package.json` 现量 157 个 `check*` 键（含伞形 `check`，2026-11-06），没有一条问过「这串字 / 这张图是谁写的」。**
   §4 逐条给出它们各自能拦到哪、在哪一步失效。

## 1. 判定问句与三步

### 1.1 问句

> **把它的实现与产物全部抹掉、只留一句「用户面对的是什么问题」，我还能不能用本仓自己的约束
> （schema / op-log / E2EE / token / 平台规范）把这同一个结论重新算出来 —— 而且算出来的形状是我自己的？**

三个限定语各自挡一类误用：

| 限定语 | 挡的是什么 |
|---|---|
| 「抹掉产物」 | 「看着它的界面点头」——把观感当依据 |
| 「本仓自己的约束」 | 「换成另一家竞品的做法」——那只是换了个人抄 |
| 「形状是我自己的」 | 「结论对、形状照搬」——取证 §4.1 那句：形状照搬 = 抄，把约束想清楚 = 学 |

### 1.2 三步

| 步 | 要问的话 | 红的样子 | 红了意味着 |
|---|---|---|---|
| **① 抹除** | 抹掉它的产物后，我嘴里剩下的是**一句问题**还是**一个方案**？ | 剩下的仍是「用五表链 / 用 7 张排序表 / 用三档字号」 | 你手里没有结论，只有转述 ⇒ 回到问题层重写 |
| **② 重算** | 我能不能给出 **≥2 个候选形状 + 选择理由 + 失效条件**？ | 只写得出一种，而且那种恰好就是它的 | 形状唯一性是复刻的指纹 ⇒ 不许进 ADR |
| **③ 置换** | 所有名词 / 键名 / 数值换成本仓名字重写一遍，还成立吗？ | 必须保留 `ZTT…`、必须保留它的 hex、必须保留它那句原文才成立 | 落**表达**侧，不进产品 |

只有 ②③ 都过、**且我们的形状与它不一致**（或能说清为什么恰好一致）才落「决定」。
「不一致」不是缺点 —— **一致才是可疑信号**：抄出来的形状必然一样，独立推出来的形状通常不一样。

⚠️ 第 ① 步有一条容易漏的分支：**文案、图标、动效这类东西，抹掉产物后连「结论」都不剩**。
剩下的是需求（「需要一句失败提示」），而从需求到那句提示之间**没有推理，只有写作**。
所以它们在第 ① 步就该落表达，不必走到 ③。判据可以压成一句：
**能被「重算」的是结论，只能被「重写」的是表达。**
例 4 就是被这一条分开的；例 5 / 6 虽然也落表达侧，但它们分别是在 ③ 与 ② 上落定的 —— 别把三种理由读成一条。

### 1.3 三分：决定 / 形状 / 表达

| 落点 | 定义 | 允许进哪里 |
|---|---|---|
| **决定** | 关于约束与取舍的断言，能被独立重算 | ADR、计划、schema 注释、实施工单 |
| **形状** | 它的某个具体结构（表的张数、键的个数、档位切法） | 只许出现在 `docs/research/`，且必须写成「我们选了另一个」 |
| **表达** | 字面 / 图形 / 版面 / 时序 / 命名 | 哪里都不许；`docs/research/` 里只能**指路**，不能**收存** |

### 1.4 60 秒版（review 时就这么跑）

1. 指着 diff 里那一段问：「**把它删掉，你还写得出这段吗？**」写得出的继续，写不出的**打回**。
2. 问：「**第二种写法是什么？**」答不出的打回。
3. `git diff --stat` 里凡新增的 `.ttf` / `.png` / `.svg` / `.json` 资产，问：「**它由哪条命令生成？**」
   答不出的打回 —— §4.3 判据 A 就是这一问的机器版。

## 2. 六个正反例

| # | 例子 | 取自取证 | 落点 | 被哪一步分开 |
|---|---|---|---|---|
| 1 | 每个视图一张独立排序表 | §4.1 | **决定** | ②（我们选了不同的形状） |
| 2 | 专注会话单列一条同步通道 | §4.3 | **决定** | ②（结论同、形状不同） |
| 3 | 字号做 delta 表 | §9.6 的 4.8 | **决定一半 / 表达一半** | ③（增量数值是表达） |
| 4 | 3 528 条文案里任意一条 | §5 | **表达** | ①（没有推理链） |
| 5 | `TT…` 类名 / `ZTT…` 表名前缀 | §5 | **表达（且负收益）** | ③（换掉后更成立） |
| 6 | 216 个 `color_#HEX` 色板 + 逐像素布局 / 动效时序 | §9.4 ①、§5 | **表达** | ②（只能给出那一个）+ ③（必须留数值） |

### 例 1（正）每个视图一张独立的手动排序表

- **① 抹除**：剩下「同一个任务在收件箱里排第 2、在项目 A 里排第 7」——这是一句问题，不是一个方案。
- **② 重算**：候选（a）实体上一列 `sortOrder`；（b）`(scope, scopeId)` 二维键的一张排序表；（c）每个视图一张表。
  选（b）：关系库里一张表能表达任意视图，加视图不加表。失效条件写清：scope 会膨胀，需要在 `scopeId` 上建索引并归档旧 scope。
- **③ 置换**：换成本仓术语后仍成立，而且**结论与它不一致** —— 它 7 张同构表，我们 1 张泛化表。
- **为什么落在决定侧**：② 给出的是「我们选了另一条」，而不是「它选了这条」。取证 §4.1 原话就是这个意思：
  形状照搬 = 抄，把约束想清楚 = 学。

### 例 2（正）专注会话单列一条同步通道

- **① 抹除**：剩下「番茄记录高频、短小、单调递增；任务低频、大对象、需要合并 —— 两类负载混一条通道会互相拖慢」。
- **② 重算**：候选（a）单通道 + 客户端合并窗口；（b）两条独立通道；（c）每条记录一个 op（op-log 天然的做法）。
  我们取（c）+（a）的组合：仍然是**一条 op-log**（这是本仓铁律，[`hard-constraints`](../agents/hard-constraints.md) §3.4），
  但番茄走独立 op type + 独立批量策略。
- **③ 置换**：`FOCUSSYNCOPERATION` 这个表名换掉后结论毫发无损 ⇒ 表名是表达；「按写入频次切通道」是决定。
- **为什么落在决定侧**：这一例正好演示**结论同、形状不同** —— 它用表隔离，我们用 op type 隔离。
  若谁把那张表名一起搬进 schema，那一段立刻从决定掉到表达。

### 例 3（正反各一半）字号做 delta 表

- **① 抹除**：剩下「用户调字号时，布局不要重排」。
- **② 重算**：候选（a）三套完整字号表；（b）一套 key + 每档 delta；（c）全部相对单位 + `clamp()` 让浏览器算。
  （b）比（a）省一半，比（c）可控（（c）在原生壳上不通用）⇒ 选（b）。
- **③ 置换**：一旦把 `Double9_12_13` 这种键名与 `+1 / +2 / +6` 这些增量原样搬过来，就掉到表达侧 ——
  因为**增量是它那套排版尺度下的解**。我们的基准是 `rem` + 1.200 比例（`tokens.css` 的 `--ht-font-size-*`），增量必须重算。
- **为什么两半**：「一张 key + delta 表」是决定；「三档的具体数值与键名」是表达。
  这一例是最容易「顺手抄」的地方：抄的人以为自己抄的是那个决定。

### 例 4（反）3 528 条文案里的任意一条

- **① 抹除**：抹掉那句话后，剩下「AI 失败时得告诉用户下一步」——这是**需求**，不是结论。
- **① 就该停**：从这条需求到那句具体的话之间没有推理，只有写作。
- **为什么落在表达侧**：它没有「结论」可供重算，只有「字面」可供重写。
  所以它的 3 528 条里**没有一条**能被「决定」豁免；统计量可以借（「AI 相关 267 条 ⇒ AI 是它需要被解释的功能」），
  统计量不是文案，字面一个都不行。

### 例 5（反）`TT…` / `ZTT…` 前缀

- **① 抹除**：剩下「任务表叫什么名字」。
- **③ 置换**：换成 `task` 之后一切照旧，而且**更好** —— 不用向读代码的人解释这个前缀从哪来。
- **两个否定信号同时命中**：**零技术收益** + **自证血统**（沿用它等于在自己的产物里留一份血统证明）。
- **为什么落在表达侧**：判据不是「改了就不成立」，而是「保留它没有理由」。
  同类：分支名、提交信息、token 名、测试 fixture 名 —— 这些地方最容易被顺手带上，而 `git log` 会永久留着。

### 例 6（反）216 个 `color_#HEX` 色板 + 逐像素布局 / 动效时序

- **① 抹除**：剩下「主题要能整套换」。
- **② 重算**：能不能给出第二种色板组织方式？能，而且本仓**已经定了**：
  语义名不用外观名（[`design-system`](../agents/design-system.md) 第 2 条：`--ht-color-danger` 而不是 `--ht-red`）。
  216 个字面色值**只能靠原样保留**才能复现它的效果 ⇒ ② 给不出第二条。
- **③ 置换**：必须保留那 168 个字面 hex 才成立 ⇒ 表达。逐像素与动效时序同理：
  它们的价值全在具体数值（间距、圆角、缓动曲线、帧数），而**这些数值无法被独立推出**，只能被测量后照抄。
- **为什么落在表达侧**：抄它等于把一个**我们已判定为错误**的决定搬进来 ——
  换肤退化成整包替换，这条反面教材在取证 §9.6 的 4.10 里已经写过一次。

## 3. 资产类型 → 谁拥有 → 我们怎么用

> 「谁拥有」是**工程口径**（谁的产物、谁的字面、谁的上游），不是权利归属的法律结论 —— 法律定性见 §6。

| 资产类型 | 事实上谁持有（工程口径） | 我们怎么用 | 现有门禁 |
|---|---|---|---|
| **文案**（3 528 条键） | 它的字面，逐条可指认 | ❌ 不摘录、不翻译过来当自己的、不进词条表。✅ 可以**统计**（「AI 相关 267 条」是代理，不是文案） | `check:ui-language` 拦硬编码，不拦「登记进词典」 |
| **图标 / 插画 / 表情 / 音效**（含 `Clock.m4a`） | 它的美术作品 | ❌ 一个都不用，也不「描一遍」。✅ 自绘 SVG + 语义图标，走 `check:brand-assets` 那条「由 token 生成」的路 | `check:brand-assets` 只管应用图标与首屏动画 |
| **字体**（`Gulzar dida.ttf`、5 套字体族、包内的 Inter 等） | 品牌字体是它的；`Inter` 这类开源字体**是上游作者的**，它只是也打进了包 | ❌ 不从它的包里取任何 `.ttf`。✅ 开源字体**从上游取**并按许可登记（OFL 要随文件附许可）。本仓今天只有一份自造样本 `research/font-kit/sample-traced.ttf`（`git ls-files` 现量 **1**） | 无（§4.2 空白 2） |
| **截图 / 录屏** | 它的界面呈现 | ❌ 不进仓、不进 evidence、不当验收基线。✅ 自己跑一遍自己的界面、截自己的图 | `check:evidence-hygiene` 只管体积与已知产物名 |
| **布局**（逐像素：间距 / 尺寸 / 圆角 / 栅格） | 它的版面 | ❌ 不按它的数值对表。✅ 从 token 尺度出发用本仓栅格重新定；**允许「看起来同类」，不允许「数值对得上」** | `check:design` 抬高了抄写成本（要抄先写裸值） |
| **动效**（时序 / 缓动 / 过渡） | 它的时序 | ❌ 不量它的帧数与曲线。✅ 按 `--ht-duration-*` + 本仓缓动重新设计 | `check:design` 拦裸 ms，其余无 |
| **内部命名**（`TT…` 类名 / `ZTT…` 表名） | 它的命名习惯 | ❌ 一个都不沿用（含分支名、提交信息、fixture、token 名）。✅ 自己起名 | 无（§4.3 判据 B） |
| **表结构**（58 张表的 DDL） | 它的 DDL 文本与表名 | ❌ 不逐字搬 DDL、不搬表名。✅ 借**约束与失效条件**；形状可以且常常应该不同（例 1 我们选 1 张泛化表） | `check:migrations` 判形状纪律，不判来源 |
| **算法思路**（排序 / 重复 / 同步 / 冲突） | 无主的「思想」层 —— 也是取证唯一推荐学的那层 | ✅ 学：写成 ADR 的「二选一 + 失效条件」。❌ 不搬实现代码、它的类名、它的 `Patch` / `Clock` 命名 | 无（靠评审） |
| **功能清单**（97 篇帮助中心目录 / 菜单 IA） | 它的产品决策 | ✅ 当**需求基线**用（「它做了哪些功能」是可观察事实）。❌ 不搬它的功能命名与分组措辞 | 无（对标文档已用） |

**这张表的三条读法：**

1. 第 3 列只有两种动词：✅ 是「能做什么」，❌ 是「不能做什么」。**没有灰色地带** ——
   一旦出现「参考一下它的写法」，就已经落回表达侧。
2. 第 4 列是**今天的现状**，不是「应该有的样子」。三处写「无」的，就是 §4.3 要补的地方。
3. 它只判「能不能用」，不判「用了会不会被告」—— 后者不归本文（§6）。

> 与本边界**无关**的一条：`check:layering` 管「业务语义只许在共享层」，与表达归属无关；
> 列在这里只是防止有人把它误读成「表达层的门禁」。

## 4. 落到门禁

### 4.1 现在能拦的（157 个键里，与本边界有交集的只有这几组）

| 门禁 | 它实际判什么 | 对本边界的作用 | 拦不住什么 |
|---|---|---|---|
| `check:design` | 六个客户端根（`apps/web/src`、`apps/mobile/src`、`packages/ui/src`、`apps/landing/src`、`apps/desktop/src`、`apps/desktop/renderer`）里的裸 hex / px / ms / z-index / rgb / rem / blur | **抬高「逐像素抄布局」的成本**：要抄就得先写裸值 | 只认 6 个目录 + 5 种扩展名（`.ts` / `.tsx` / `.js` / `.jsx` / `.css`），`.swift` / `.cs` / `.xaml` 天然在外；**它不知道来源**，把抄来的 px 换成最近的 token 就全绿 |
| `check:native-bare` | 三个原生壳手写源码里的裸 hex | 补上原生那一半 | 只判 hex；px / 间距 / 圆角不判；同样不判来源 |
| `check:design-token-refs` | 每个 `var(--ht-*)` 必须解析到定义；白名单每条要写注入点；白名单不许比真实需要更长 | **最像本文所需判据的形状**：它判「能不能解析回去」，不判「名字好不好」 | 扫的是 token 引用，不是资产字节 |
| `check:ui-language` | 已迁移应用里用户可见字符串必须走 `t('key')`；中英都要真翻；诊断字段不许装句子 | 拦「把它的文案贴进组件」这个**动作** | **不拦「把这串字登记进词典」** —— 规则 1 只判「有没有走词条表」，不判「这串字是谁写的」 |
| `check:egress-wording` | 词条表与源码里不许出现「数据出境」这类尚未定性的监管词 | **先例**：证明「这句话会替法务下结论」可以做成词表 | 只服务那一个定性；不含竞品词 |
| `check:brand-assets` | 图标 / 首屏动画：产物 **==** 由 token 生成的那一份；产物在 `git ls-tree HEAD` 里；有清单引用、有代码消费 | **最接近本边界的形状**：判的是「可复现 + 有引用」，不是「像不像」 | 只管应用图标与 splash 两样，且分母是工作树加 `HEAD` 两张树，其余图片 / 字体 / 插画不在内 |
| `check:tokens` + `check:theme` | token 生成物 == token 源；主题只有一份实现 | 拦住「手改生成文件」 | 拦不住「把 216 个 `color_#HEX` 加成 token」——那是一次合法的 add |
| `check:licenses`（含 `:nuget`、`check:image-license`） | 实际装出来的 npm / nuget 依赖树 + 发布镜像那棵树 | 拦得住「把它当包引进来」 | 分母是**包管理器装出来的树**；手工放进仓的 `.ttf` / `.png` 不在任何一条的扫描面里 |
| `check:evidence-hygiene` | evidence 根下的产物名（`.app` / `.dmg` / `xcodebuild` 等）、单文件 >25 MB、单 root 超预算 | 拦得住「把它的整包或整套截图搬进 evidence」 | 拦不住一个 3 KB 的它的图标；也不判授权 |
| `check:gate-wiring` | 定义过的门禁必须真的在 `pnpm check` 链里跑 | 补的新门禁不会「定义了但没人跑」 | 只管接线，不管判据内容 |
| `check:docs` + `check:doc-citations` + `check:doc-command-claims` | 死链与失效章节引用；`git show HEAD:` 的锚；文档里「跑过的命令」必须真实存在 | 本文这类结论至少被钉在**可解析的引用**上 | 不判「这句话是不是抄的」，不判结论归属 |

### 4.2 现在拦不住的三条空白（带现量）

1. **来源不可判。** 157 个键里没有一条问「这串字 / 这张图是谁写的」。最接近的两条
   （`check:brand-assets`、`check:design-token-refs`）判的都是「**能不能解析回去**」，不是「从哪来」——
   这个差别正是 §4.3 判据 A 的支点：**把「解析回去的对象」从 token 名换成资产字节**，判据就现成了。
2. **字体与位图没有归属面。** `git ls-files` 现量：全仓 `.ttf` / `.otf` / `.woff` / `.woff2` 合计 **1 份**
   （`research/font-kit/sample-traced.ttf`，自造）。没有任何脚本判字体文件的来源与授权
   —— 全仓只有两处提到 `.woff2`，都是静态服务器的 MIME 表（`scripts/verify-password-web-journey.mjs:149`、
   `scripts/verify-email-web-chain.mjs:131`），不是授权检查；
   `check:licenses` 与 `check:image-license` 的分母是包管理器装出来的树，手工放进仓的二进制不在其中。
3. **「形状合法」就是后门。** 把它的 7 张排序表、216 个色板键搬进 schema / token，**全部门禁都会绿** ——
   它们判的是「写法合不合规」，不是「这个形状是谁想的」。

补一句：第三条是**故意留着**的。形状只能靠 §1 的三步 + §5 的六问来判；把它做成门禁，
只能得到一条永远绿的判据，而「一条永远不会失败的判据比没有判据更糟」
（[`environment-traps-index`](../agents/environment-traps-index.md) 的元规则 2）。

### 4.3 缺的那条：建议写成「可复现资产」（只给能红的判据，不实现）

**判据 A（强，建议）`check:asset-reproducible`（建议，今天不存在）**

形状照 `check:design-token-refs` 抄，不发明新装置：那条判「每个 `var(--ht-*)` 都要解析到定义」，
这条判「**每个资产字节都要解析到生成器**」—— 同一个判据换了个分母。

| 项 | 取值 |
|---|---|
| 分母 | `git ls-files`（不是工作树）。`check:brand-assets` 那轮事故的教训：产物在、提交物里没有、门禁全绿 |
| 集合 | 会被渲染或嵌入的字节：`*.ttf` `*.otf` `*.woff2` `*.png` `*.jpg` `*.webp` `*.gif` `*.svg`，以及图标 / 插画类 `*.json`（Lottie） |
| 判据 | 每个路径的 sha256 必须命中一份**由生成器写**的资产清单（建议位置：`packages/design-system/generated/` 下的一个 json，今天不存在）；生成器只吃仓内输入（token、自绘 SVG 源） |
| 失败输出 | 红，并只给两条出路：「删掉它」或「给它写一个生成器」 |
| 能红的臂 | 拷任意 `.png` 进 `apps/web/public/` ⇒ 哈希不在清单 ⇒ 红；手改清单 ⇒ 生成器 `--check` 红（产物 ≠ 源） |
| 它判不到 | 两个都是自绘、但「看着像」的资产，一条都不报。相似度不可机械判 —— 它只回答「有没有我们自己的来源」 |

**判据 B（弱，建议）`check:foreign-nomenclature`（建议，今天不存在）**

形状照 `check:ui-language` 里的 `REGULATORY_TERMS` 抄：一张**每个词都带「抓过什么事故」**的词表
（`check:docs-voice` 的 `FORBIDDEN` 就是这么写的）。

| 项 | 取值 |
|---|---|
| 词表 | 品牌词（滴答清单 / TickTick / Dida365）+ 前缀族（`ZTT` + 全大写 `TT` 类名前缀）+ 它的独有术语（逐条带理由；通用词如「番茄钟」**不许进表**，进了就是误伤） |
| 扫描面 | `packages/i18n/src/locales/*.ts`、`packages/*/src`、`apps/*/src`、`design-system/` |
| 豁免 | `docs/research/`（那里是在**讨论**边界，不是收存资产）；每条必须在脚本里写 `why`，无理由的豁免等于没有豁免 |
| 能红的臂 | 往 `zh-CN.ts` 加一条含「滴答清单」的词条 ⇒ 红；把 `ZTTTask` 写进 `packages/domain/src` ⇒ 红 |
| 它漏什么 | 同义改写抓不到（把它那句换个说法照样过）。所以它是 A 的补充，不是替代 |

**判据 C（不做成门禁）**：§1 的三步与 §5 的六问**不做机器判据**。理由同 §4.2 第三条。

### 4.4 新门禁自己要先满足两条

1. **进链**：必须在 `pnpm check` 里真的被跑。`check:gate-wiring` 会替你钉住这条 ——
   「定义了但不跑」等于静默失效，而它连退出码都不会变。
2. **能红**：先写臂再写判据。上面 A / B 各给了至少一个**能红的输入**；跑不出来就别合。

## 5. 交付前 6 问（评审用）

| # | 问 | 它抓的那类事故 | 红了怎么办 |
|---|---|---|---|
| 1 | 把它删掉，这段还写得出来吗？ | 逐字转述（文案 / DDL / 键名） | 打回，回到问题陈述重写 |
| 2 | 第二种写法是什么？为什么不选？ | 形状照搬（7 张表 / 五表链 / 三档字号） | 补 ADR 的「二选一 + 失效条件」；补不出来就不许进 |
| 3 | 换成本仓名字后还成立吗？必须保留哪些字面 / 数值 / 键名？ | 表达混进「决定」（增量数值、hex、缓动帧数） | 把必须保留的部分摘出去，只留结论 |
| 4 | 新增的 `.ttf` / `.png` / `.svg` 由哪条命令生成？ | 手工塞入的外部素材 | 删掉，或写生成器（判据 A 的 60 秒版） |
| 5 | 这串字出现在公页 / 词条表 / 对外文案里了吗？ | 把它的文案当自己的发布出去 | 立刻换成本仓文案；对照 `check:ui-language` 与 `check:docs-voice` |
| 6 | 它的名字进代码 / 表名 / token / 分支 / 提交信息了吗？ | 血统自证（`TT` / `ZTT` 一族） | 改掉；分支名与提交信息也要改（`git log` 会跟着走） |

**用法**：一次 review **必须**跑 1–3；涉及二进制资产加 4；涉及文案或对外发布加 5；涉及命名加 6。

**为什么全是否定式**（「删掉还成不成立」而不是「这是不是学来的」）：肯定式永远能答「是学来的」，
否定式答不了 —— 删掉之后手里还剩什么，是当场能看见的。
