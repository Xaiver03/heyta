# 行着色三态 = **只有清单图标着色**（产品已拍板 2026-11-08）

> 产品负责人的原话：**「只有清单图标着色，我确定是这样」**。
> 所以这一格**不再等裁决**：不做行左侧色条、不做整行淡底，只让**清单那个图标**带上颜色。

---

## 1. 三态

| 档 | 行上长什么样 | 判据 |
|---|---|---|
| **按清单**（默认） | 行首那枚清单图标取**该清单的色** | 有清单 → 图标带色；无清单（收集箱）→ 走默认前景色 |
| **按标签** | 图标取该任务的**第一个有效标签**的色 | ⚠️ 必须经 `resolveTagIds`，否则合并过的任务会读成"没有标签"（这一轮已在三个读点踩过同一族盲区） |
| **关** | **行里不存在那枚着色图标** | 不是 `opacity:0`、不是透明色 —— 是**节点不存在** |

## 3. ⚠️ 一个必须先说清的现状：**这两个 color 字段今天没有任何读点**

`grep -rn "project.color" apps/web/src packages/ui/src` ⇒ **零命中**。
也就是说 `Project.color` / `Tag.color` 从加上那天起**没有一处界面在画它们**
（侧栏的清单行也不读 —— `OrganizerList.tsx` 里 `.color` 只出现在样式名里）。

⇒ 这一格是**它们第一次被真的用上**。由此有两条纪律：

1. **色值格式没有既定约定**（`string` 而已）。不猜：见 §4。
2. 既然没有读点，就没有"沿用旧形状"的包袱 —— 可以按下面的最小形状一次做对。

## 4. 色值怎么落到 token 上（不写裸 hex 的铁律）

设计系统禁止组件出现裸 hex（`check:design`）。而 `Project.color` 是**用户数据**里的字符串，
它不可能是 `var(--ht-*)`。三条可行路径，按与现有纪律的贴合度排序：

| | 做法 | 代价 |
|---|---|---|
| **A** | 把实体 color **当成调色板槽位键**（像 `CategorySlot` 那样存不变量的编号/键），共享层映射到 `color.quadrant-*` 这类**已有语义 token** | 要定一张槽位表；但完全不碰裸 hex，且与 `Category.color` 那条既有纪律**同形**（`entities.ts:854`：「存不变量而不是'长什么样'」） |
| **B** | 实体 color 就是 `#rrggbb`，共享层原样当 `color` 传 | 违反"组件禁裸值"的字面；需要给共享层一个**显式豁免**（那会把门禁撕开一个口子） |
| **C** | 实体 color 是 `#rrggbb`，但先**映射到最近的 token** | 映射表本身就是第二套调色板，且"最近的"没有确定答案 |

🔴 **推荐 A**，理由不是"好看"，是它与本仓**已经拍过板**的那条同形：
`Category.color` 的注释原文就是「色槽**编号**（1–8），不是颜色值……存不变量而不是"长什么样"，
调色板改版不该动磁盘上的旧数据」。清单/标签的 `color: string` 是更早留下的**松口子**，
这一格正好把它收进同一条纪律 —— 但那**会动已有数据的语义**，所以要单独确认一句（见 §6）。

## 5. 落点（最小形状，4 步）

1. `packages/ui/src/task-list/model.ts`：`toTaskRow` 的入参多一个**可选**的 `projectColorToken`
   —— 与现有 `fallbackTitle` 同一类"宿主给的界面偏好"，**共享层不查实体表**（与 `EmptyState`
   同一条边界：不拖 i18n、不拖 store）；
2. `TaskRow.tsx`：**只在拿到那个值时**渲染行首图标；拿不到 ⇒ **不渲染**（这就是"关"的实现，
   也是它的判据 —— 对照臂：不传 ⇒ 零节点）；
3. 宿主侧（web 先做，mobile/desktop 随后）：三档 → 一个取色函数，**按标签那档走 `resolveTagIds`**；
4. 偏好键 `heyta.rowColor` 按 A 档登记（`docs/reference/client-persistence-keys.md`），
   **零 op**：改它只动 `localStorage`，op-log 条数不变。

## 6. 需要一句话确认的**唯一**一件事

**清单/标签的 `color` 存的是"槽位键"还是"#rrggbb"？** 今天两边都读不到，所以答案不在代码里。

- 若你希望**不碰已有数据语义** ⇒ 走 B（给共享层一个显式豁免，写清理由）；
- 若你认同 `Category.color` 那条既有纪律 ⇒ 走 A（存槽位键，与分类同形，但已有数据的 `color` 值
  要有一层"认不出就回落默认色"的兜底）。

**在此之前我先按 A 的形状做**（因为它与仓库已拍板的纪律同形），并把"认不出回落"写成判据 ——
这样即使最后选 B，改动面也只是取色函数那一个文件。
