# P2 剩余范围：目标里写明、但**不在仓库任何计划里**的那几格

> 起因：交付那一步卡在一个产品裁决上，而裁决要等人。等待期间我把「目标里点名、
> 但代码/计划里找不到」的格子逐个查了一遍 —— **它们不是"还没做"，是"没有计划"**。
> 本文只做定性，不定方案；每格都写了"落到哪儿做、从哪读现状"。

---

## 1. R13b 里**没做**的三维（目标是四维外观）

| 维度 | 现状读数 | 落点 |
|---|---|---|
| **字号档** | `packages/design-system/src/tokens.css` 的 `font-size.*` 是**语义档**（`row-title` / `row-meta`…），没有"用户可调"这一层；`docs/reference/client-persistence-keys.md` 里**没有**任何字号键 | 要先决定"档位乘在语义档上"还是"另立一套档位表" —— 前者改 `useHeytaText` 一处，后者要动 33 个族 |
| **密度** | 同上：`space.*` 是固定档；没有密度键 | 同字号档，且它与"控件高度一档"（`docs/agents/ux-principles.md`）会打架，要一起裁 |
| **行着色三态**（按清单 / 按标签 / 关） | 零命中：`grep -rn "rowColor\|colorBy" packages apps` 无结果 | 属于"读得多、写得零"（ADR-0085 §三.2）：显示时按行来源查一次清单色/标签色 |
| **应用图标** | 移动端是**安装器级资源**，运行时不可改（ADR-0085 §六 残余 2 已写在射程外） | 不做，除非产品明确要"换图标"这一档 |

⚠️ 目标第 1 条把"纯色"也列进去了。这一轮落的是**表面色系预设（warm / mist）**，
不是"用户自选一个纯色"。两者的差别：纯色要**现场生成一整套表面 token 并逐个算对比度**，
而预设是**离线算好、登记在案**的。前者是"自定义主题"，ADR-0085 §六 残余 4 把它排在射程外。

## 2. R11 的覆盖缺口（已写在自己的文档里，这里只汇总）

- 32 个容器只接了 **1 处**（`InboxBell`）——见 [`r11-error-and-loading-2026-11.md`](r11-error-and-loading-2026-11.md) §4.1
- `card` 档 **0 个消费者**，5 处本该是卡片档仍借 `page` ——见 [`r11-state-tiers-ledger.md`](r11-state-tiers-ledger.md) §3

## 3. 结论：目标第 1 条**只完成了一部分**

已入库：主题预设（warm/mist）+ 自动深浅三态 + 零 op + A 档登记 + 四道设计门禁。
**未覆盖**：字号档、密度、行着色三态、纯色自定义、应用图标（最后一格按 ADR 不做）。

⇒ 目标在这一点上**没有被完全满足**，而且缺口不是"漏了几个文件"，
是**四个维度各自需要先定方案**。没有方案就动手，等于在四个地方同时发明架构。
