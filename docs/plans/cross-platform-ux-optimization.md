# 跨端交互 UX 优化计划

> 对应审计：[`../research/cross-platform-interaction-ux-audit.md`](../research/cross-platform-interaction-ux-audit.md)
> 目标：让 Web、移动端和桌面壳共享同一套任务语义，同时按输入能力提供不同的直接操控方式。

## 产品决策

1. 拖拽、长按和滑动都是加速入口，不能成为唯一入口。
2. 四象限是任务的投影，不新增“象限状态”；拖放可以改变重要性和截止时间，但必须立即说明并可撤销。
3. 移动端不搬运 Web 的二维拖放，使用“点任务 → 详情编辑”作为主路径，长按只作为批量选择快捷方式。
4. 侧栏/详情栏宽度是设备本地偏好；拖动取消必须回滚，键盘调整必须支持 Escape。
5. 小窗口优先重排、折叠和内部滚动；任何核心按钮都不能要求用户先扩大窗口才可见。

## 本轮已执行

- `ColumnResizer`：pointercancel 回滚、最终宽度 ref、Escape 取消。
- Web 四象限：拖放成功/失败状态、截止时间变化说明、撤销按钮、动作型无障碍名称。
- 共享四象限任务行：移动端长按与批量选择态贯通。
- 移动端：任务详情安全区 inset、Android 键盘高度避让；设置页同步采用高度避让。

### Web 浏览器实测（2026-10-07）

- 浏览器证据为 **timeline-p2 1 项 + 视口矩阵 1 项**；覆盖真实视图入口、行交互与当前时间线状态机路径。
- 视口矩阵：**29 个视口断言组通过**，覆盖桌面宽度、窄桌面、平板和手机尺寸；断言包括 `document` 不横向溢出、主操作在视口内、详情栏在空间不足时自动退场。
- 证据：[`apps/web/evidence/settings-finish/viewport-metrics.json`](../../apps/web/evidence/settings-finish/viewport-metrics.json)，以及同目录的 768×400、1280×479、375×667 截图。
- 同步 rail 的窄屏定位已在当前实现中修复，并随矩阵复验通过；原生壳的最终安装与交互证据仍按 RELEASE-1 单独收口。

以上是代码阶段状态，不等于四端当前产物已经安装。移动端“显式移动到象限”已接入，仍需真机读屏、滚动冲突与安全区验收；四端最终重装统一遵循主计划 §7 的 RELEASE-1。

## 验收顺序

1. 先跑 Web 类型检查、共享 UI 测试和现有外壳/调宽浏览器旅程。
2. 再跑当前产物的移动端长按、详情键盘和安全区旅程。
3. 最后跑视口矩阵，记录 `document`、`.ht-content`、详情栏和主要按钮的几何读数。
4. 未完成项保留在计划中，不能用截图或门禁结果代替真实交互证据。

## hidden / active 复审结论

设置页的隐藏分组仍保留在 DOM，当前分组通过 `active` 控制异步副作用。Profile、Sync、Vault、Privacy、Admin、Passkey 的远端读取已按当前分组门控；Data 的导出、还原和滴答迁移面板只在用户动作后读本地文件/库，空库、仅本地和格式限制已经由状态卡表达。ReminderNotifyPanel 的 `visibilitychange` 监听与 WidgetJourneyPanel 的宿主能力探测都是本地只读能力，按设计保留，用于用户返回页面时看到真实权限/安装状态；未发现出站网络写入，不列为 hidden/active 债务。
