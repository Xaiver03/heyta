# 活动分类与分类着色（增量计划）

> 状态：**设计已拍板，代码未开始**。等 [`motivation-and-progression.md`](motivation-and-progression.md)
> 落地到 main 之后**另开一个分支**做（用户 2026-09-26 选的节奏）。
> 前置依赖：时间必须先能**归到分类上**，颜色只是最后 10%（见 §4）。
> 相关：[roadmap.md](roadmap.md) §1.2 激励与成长体系 · [`../research/competitor-incentive-teardown.md`](../research/competitor-incentive-teardown.md)（伤害模式）

## 1. 这条需求从哪来

来自一位真实用户的反馈（原话）：

> 除了时间统计的基础功能，还可以给学习、运动、社交、深度工作等等不同板块分很细致的颜色，
> 对于人脑来说可视化效应很强（比如把自己不太健康但老戒不掉的那种活动定成红色，每周一看会很醒目）

这句话里**包着两件不同的事**，必须拆开，因为它们一个该做、一个不该做：

| | 用户的诉求 | 判断 | 理由 |
|---|---|---|---|
| (a) | **让那个活动一直在视野里，不能被遗忘／被合理化掉** | ✅ **这就是真正起作用的机制** | 颜色是**前注意属性**，在被"看"之前就已经分好组 —— 一片红会自己跳出来，不需要阅读 |
| (b) | **因为它是"坏的"所以给红色**（App 赋予褒贬） | ❌ **不做** | 见 §3。这与本仓库已记录的三种伤害模式同形 |

**承认 (a) 是对的，同时拒掉 (b)，是本计划的核心。** 不做 (b) 的代价是零 —— 因为 (a) 需要的是
**辨识度 + 具体量 + 与自己过去比**，**不需要**褒贬。

## 2. 已拍板的决策

| # | 决策 | 拍板人 |
|---|---|---|
| D1 | **颜色由用户自己赋义**：我们只提供 8 个色槽位，保证彼此可区分 | 用户 |
| D2 | **App 永不判断某个活动"健康／不健康"**，也永不自动上色 | 用户 |
| D3 | 先落地激励体系，本特性**另开一个增量** | 用户 |

D1 + D2 合起来是一句话：**调色板由我们给，褒贬由用户自己赋。**

用户想把短视频设成红，完全可以 —— 那时红色是**他的**信号，不是我们的说教。
而且**自赋的红没法反驳**：一个人不会跟自己定的规矩争辩，却会立刻反驳 App 派发给他的道德判断。
这也正好落在 SDT 的自主感上，与已定的「**只与自己的过去比**」是同一条线。

### 反需求（写死，防止后来"好心"地加回来）

- ❌ **自动健康度评分 / 自动"好活动／坏活动"分类**
- ❌ 因为超支而变红（**渐进的红色预警**也是自动褒贬的一种，同样不做）
- ❌ 按分类排名、按分类打分、"本周最差分类"之类的措辞
- ❌ 任何形式的"你这个月很失败"结论文案

## 3. 为什么 App 不碰褒贬（三条理由，按重要性）

1. **它会把判断权从用户手里拿走。** 「社交」可能是陪家人，也可能是刷短视频；
   「游戏」可能是放松，也可能是逃避。**App 判错别人对自己生活的评价，比沉默糟得多。**
2. **对"戒不掉"的活动，内疚框架的预测是「不记录了」，不是「改了」。**
   看报告会难受 → 少看报告 → 数据没了 → **连"一周 12 小时"这个事实都看不见了**。
   这正是仓库已引过的 abstinence-violation 效应的近亲。
3. **仓库自己已经踩过这个形状。** [`../research/competitor-incentive-teardown.md`](../research/competitor-incentive-teardown.md)
   里「羞耻／内疚」作为**伤害模式**出现了三次：

   | 产品 | 伤害机制（原文） |
   |---|---|
   | Forest | 枯树 + 连坐**制造 guilt**，把"我的专注"变成"我对朋友的义务" |
   | Habitica | **guilt / 责任压力最重**——"我漏做 Daily，队友掉血"；死亡惩罚对低动机用户是退出按钮 |
   | 番茄Todo | **排行榜焦虑最典型**——"别人 10+ 小时"对低产出日是**羞耻来源** |

   与「从不制造愧疚」这条红线直接冲突。

### 那"醒目"从哪来？

从**辨识度**来，不是从褒贬来：一片红之所以跳出来，是因为它在调色板里**罕见而独特**，
不是因为它代表"坏"。所以我们要保证的是**颜色彼此可区分**（含色觉障碍下的区分），
而不是**颜色带有对错**。

### 数字比颜色有力

让人震动的从来是「**这周 12 小时**」，红色只是把这件事变得刺眼。
**刺眼的东西会被回避，具体的东西会被面对。** 所以分类视图必须同时给出**量**：
小时数 / 次数 / 占比，且可点开看明细。

## 4. 真正的工程量在**时间归因**（颜色是最后 10%）

「按分类统计时间」的前提是**时间能归到分类上**。现在 heyta 只有一处产生时长：番茄钟（`FOCUS_SESSION`）。
`HABIT.target + unit='分钟'` 也能贡献时长。

🔴 **好消息：零新增字段就能跑通第一版。** 全部链路都已存在，缺的只是渲染：

```
FOCUS_SESSION.taskId  →  TASK  →  PROJECT.color
HABIT.target + unit   →  HABIT.color
```

| 已存在的字段 | 位置 |
|---|---|
| `Project.color?: string` | `packages/domain/src/entities.ts:126` |
| `Tag.color?: string` | `packages/domain/src/entities.ts:133` |
| `Habit.color?: string` | `packages/domain/src/entities.ts:196` |

## 5. 可视化形状

### 5.1 不改现有热力图

现有热力图（`apps/web/src/lib/heatmap-theme.ts`）一格 = 一天，用 `heat-1..4` 编码**一个**量（强度）。
文件里那条注释已经把话说明了：

> ⚠️ 四档活动色用 `heat-1..4`，不要全部用 `primary`：色阶的意义就是**一眼看出多少**，
> 四档同色等于把"这周很密"和"只打过一次卡"画成同一个样子。

用户想要的是**第二个轴**（类别）。**一天有多个分类，一格画不了两个色** ——
硬塞只能二选一，必然丢信息。所以**别改它，加新形状**。

### 5.2 主形状：分类泳道图（small multiples）

```
深度工作  ▓ ▓ ▓ ░ ▓ ▓ ·      ← 每行一个分类
学习      ▓ ░ ▓ ▓ ▓ ░ ▓
运动      ░ · ░ ░ ▓ · ·
社交      ▓ ▓ ░ ░ ░ ▓ ▓
短视频    █ █ █ ░ █ █ █      ← 用的也是强度色阶，不是"警告红"
```

每个分类一行，行内是**强度**色阶。形状取自 GitHub「每个仓库一张图」与 Apple Health「每个指标一张卡」。

**为什么它是对的**：

- 用户要的场景是「每周一看会很醒目」→ 泳道图的对比是**跨行**的，
  **一行满 vs 一行空**一眼就出来，而单行内部的颜色浓度反而不重要。
- **它用位置表达类别、用文字标签命名，颜色只编码强度** ——
  天然满足仓库那条硬规则「**不许只用颜色表达信息**」（已写进
  `apps/web/src/features/timeline/GanttChart.tsx:36`、`features/settings/AiSettings.tsx:17`、
  [`ai-capability-branches.md`](ai-capability-branches.md)）。
  **不需要为这条规则做任何妥协。**

### 5.3 辅形状：周堆叠条

一周一根柱，按分类堆叠，配文字总量：适合「总共 40 小时里 12 小时是 X」这种陈述句。

### 5.4 用户赋义的入口

分类本质上是**清单／标签／习惯**（已有实体），所以赋义入口就是它们的编辑界面：
给一个清单选一个色槽位。**不新增"分类"实体。**

## 6. 工程约束（真成本在这里，别想着绕过）

| 项 | 约束 |
|---|---|
| 🔴 **`color` 存什么** | **不能存裸 hex**（跟不了暗色主题、对比度无法保证、违反"token 是唯一事实源"）。**存槽位号 `1..8`**：数据只存**不变量**，颜色长什么样留给 UI 层。改调色板不影响磁盘上的旧数据。 |
| **加分类色 = 加 token** | 现在语义色里分类只有 `quadrant-1..4`（4 个）。每加一个色都要在 `packages/design-system/src/tokens.ts` 的对比度清单里登记 `(fg, bg, min, why)` —— **对比度是测试实算保证的**，不是文档保证的。 |
| **暗色** | 不是亮色反相，**必须实际切着看**（AGENTS.md §5）。 |
| **旧数据** | 槽位号是**新语义** → 必须**可选 + 运行时兜底**（不认识的值 → 无色），不许必填。见 AGENTS.md §3.3。 |
| **不许只用颜色** | 每行每块必须有文字标签。已定规矩，本特性不需要新定。 |
| **派生纯函数** | 统计口径（每分类时长、每周堆叠）一律在 `packages/domain`，`apps/web` 只扁平化并注入 `now`。 |
| **零 schema bump** | 复用既有可选字段，不新增实体、不加必填字段。 |

## 7. 五项已拍板（2026-09，逐条落到实现）

1. **色槽位 = 8 个。** 越多越能满足"分得很细"，而可区分度由下面的第 5 条兜。
   `CATEGORY_SLOTS = [1..8]`，`parseCategorySlot` 只认 `1–8`，
   `"0"` / `"9"` / `"#dc2626"` / `"red"` / `"03"` / `""` 一律**回落到"无颜色"**，
   **不回落到 1 号槽位**（回落会让"我明明清除过"变成"它自己变红了"）。
2. **清单与习惯都能赋义；标签不参与。** 标签是多对多，一条专注会同时落进多个标签 ——
   那会得到两套口径、同一条时间被算两次。**时长归类只走"任务 → 清单"与"习惯"两条链。**
   两个 `color` 字段（`Project.color` / `Habit.color`）本来就在，本次只是终于被消费。
3. **无任务的纯计时不计入分类，但如实显示。** 它进 `unassignedMs`，
   界面写"另有 X 没有归到任何清单或习惯"。**不新增"给一段计时补分类"的流程**
   （那会引入一种新的时间归属语义，而它换来的只是把 `unassigned` 变小）。
4. **泳道图放 `growth`，插在「这一年」之后、「里程碑」之前。**
   顺序是时间尺度递增：本周复盘 → 分类时长（12 周 × 每类）→ 一年热力图 → 里程碑 → 身份。
   **不新建视图**：一个只在特定时刻有内容可看的视图会变成一个永远空着的标签页。
5. 🔴 **色觉障碍：不承诺"两两可区分"，承诺"颜色只是加速器"。**
   这一条是**实测**逼出来的，不是取舍偏好：
   把 8 个槽位在**灰度、红绿色盲、蓝黄色盲**三类模拟下逐一实算，
   **任意两个槽位都压不进 4.5:1 的正文对比度** —— 字面要求做不到。
   于是承诺改成：**每一行都有位置、名字、来源、数字**，格子与色块是装饰；
   另外每个槽位在界面上**永远带着自己的编号**（色块旁边就是 `3`），
   色盲用户与读屏用户都能把行和堆叠条的那一段对上。

### 8.2 口径（写下来，因为它们都是"看起来一样但不一样"的地方）

- 只算 `kind === 'work'` 的专注会话（休息不计入"做事的时间"）。
- 日期用 `focusSessionDay`（`endedAt ?? createdAt`）—— **跨零点的会话算在结束那天**。
- 软删除（墓碑）的任务/清单/习惯**一处都不算**。
- 缺 `actualMs` 时退 `plannedMs`（提前结束的会话仍按计划计入 —— 它**确实占用了那段时间**）。
- 时长只认**分钟**单位（`分钟/分/min/mins/minute/minutes`）。"杯"、"次"这类**不猜换算**，
  于是那类习惯不贡献时长；但它**照样有一行**（因为颜色已经赋给它了）。
- `peakWeeklyMs` **跨行共享**：两行同样深浅 = 同样多，行与行才对得上。
- 窗口外与未来的记录**两处都不算**（`weeklyMs` 长度恒等于周数）。

### 8.3 色板是怎么选出来的（别重挑）

在 HSL 空间 + 一组约定的原始色阶里穷举 8 色子集，目标函数
`min(正常ΔE, 红盲ΔE, 绿盲ΔE, 正常ΔE × 0.55)`，约束是每个槽位与背景 ≥ 3:1。

| 主题 | 正常 ΔE | 红盲 ΔE | 绿盲 ΔE | 与 surface 对比度 |
|---|---|---|---|---|
| 亮色 | 29.2 | 16.1 | 19.7 | 3.30:1 |
| 暗色 | 28.2 | 23.3 | 15.3 | 4.08:1 |

`tests/category-colors.spec.ts` 把这条**钉成了能失败的检查**（不是文档）：
正常 ΔE ≥ 25、红盲 ≥ 14、绿盲 ≥ 13（亮暗各跑一遍）+ 每个槽位与 surface ≥ 3:1；
另有一组"色盲模拟不是空操作"的断言（红绿被推近、红蓝仍分开、灰度不变）。
已用**注入**验证它会红：把暗色 8 号改成与 1 号同值、亮色 5 号改成近白
→ 4 条红（含"实测 1.04:1"）。

### 8.4.1 两条**被检查逼出来**的修正（不是审美，值得单独记）

1. **`check:ui-language` 是形状检查，不是内容检查。** 我的中文词条
   `'web.categories.segment.aria': '{name}：{duration}'` 形状完全合规
   （`t('…')` 包着一条存在的 key），但**一个汉字都没有** ——
   这与"忘了翻译、把英文占位留在中文表里"逐字相同。
   抓到它的是 `packages/i18n/tests/catalog.spec.ts` 的
   「中文表每一条都含汉字」，不是那条仓库级门禁。
   → 结论：**跑完 `check:*` 不等于跑过每个包自己的测试**；这一条也解释了
   为什么"中文表里只有标点的词条"必须写成有汉字的形式（现在是 `'{name}，共 {duration}'`）。
2. **`column-reverse` 的"第一个孩子在底部"与 `reverse()` 会互相抵消。**
   堆叠条原来既写了 `column-reverse` 又写了 `.reverse()`，谁是底、谁是顶
   与注释所写的**正好相反**，而且没有任何断言看得出来。
   → 已去掉 `reverse()`，并把"段序 = 行序"变成一条**能失败**的断言
   （`categories.spec.tsx`：「第一段的颜色 == 第一行的颜色」，两行总时长不同所以顺序有信息量）。
   注入 `slice().reverse()` 实测红、还原后绿。

🔴 **一条被这一轮修掉的真 bug**：`record()` 最初是"先建分类行、再判窗口"，

### 8.6 真浏览器验收：**已恢复**，5 条契约（含逐条注入证据）

上一条（8.6 的旧版）记的是"这轮做不到"，原因是**别人的在飞工作**让这一支上
Web 应用整页白屏（消费者已提交、生产者在主检出未提交）。本轮把那件事解决了 ——
**但不是替别人写代码**，而是把白屏的成因挪出测试通道：

`e2e/tests/shims.ts` 只活在测试进程里，拦 dev server 送给浏览器的模块响应，
给**五个**缺的导出接上"存在、一调用就抛"的占位：
`storage#StorageError`、`domain#planQuadrantDrop` / `clockText` / `roundedDaysText`、
`sync-client#summarizeConflictPayload`。三条纪律写在文件头：
**调用即抛**、**生产者落地后自动失效**（文件里已经有那个名字就什么都不加）、
**生效时打日志**（`[e2e 垫片] …`）。产品代码、`packages/*`、主检出一个字节没动。

⚠️ 清单是**对账**出来的，不是撞一个补一个：把 `apps/web/src` 里所有
`import { … } from '@heyta/*'` 与各包 `dist/index.js` 的**实际导出**比一遍。
实测过撞着补的代价：修好一个之后是下一个（三次白屏、三种报错、同一个成因）。
⚠️ 还踩了一条：同一个 URL 上注册**多条** `page.route` 只有最后一条生效，
所以垫片必须**按包分组**（三个同包名字分成三条路由时，只有最后那条真的加上了）。

**这 5 条契约**（`e2e/tests/categories.spec.ts`）：

| 用例 | 注入什么会红（都实测过） |
|---|---|
| 区块挂进成长页 + 空状态如实说明 + 无百分号 | 不渲染区块 |
| 色槽赋色 → **刷新后仍在** → 再点取消 | 赋色不落盘 → 行首当前色块停在未设色（实测 `rgb(226,232,240)`，期望 `rgb(22,163,74)`） |
| 真实的专注时间进入「未归类」 | 不渲染那句未归类（实测红） |
| 反需求：没有排名 / 占比 / 优劣词 | 说明里塞一个「最多」（实测红，报 `["最多"]`） |
| **样式真的落到了浏览器里**（下面单独说） | 说明文字换色 / 去掉 `border-top` / 无条件渲染柱状图 |

两条值得单独说的做法：

1. **第 2 条的重点是"刷新"**。不刷新只能证明"点到了"；刷新后仍是 3 号色槽，
   才能证明它**真的进了 op-log**（换设备/重开应用也要在）。
   写这条用例时先错了一次：点完色槽就断言 `aria-pressed` —— 而面板选完**自己收起**，
   那个按钮已经不在 DOM 里。错误本身说明了该证明什么：**读回来的值**，而不是"点到了"。
2. **第 3 条把浏览器时钟接管过来**（`page.clock.install` + `resume` + `fastForward('26:00')`），
   于是断言的是真数字「25 分钟」（`advance()` 记的是 `plannedMs`），
   而不是"跑了 3 秒 → 0 分钟"。⚠️ `install` 之后**必须 `resume`**：
   装完的时钟默认不走，而应用启动要等 `setTimeout` 才打开本地库 ——
   不 resume 的症状是白屏，看起来像应用坏了（那会是一次很贵的误判）。

**同一次跑出来的全套**（本轮复跑，`npx playwright test --reporter=list`）：
`categories 5` + `smoke 2` + `motivation 6` + `ai-breakdown 1` + `ai-capture 1` +
`ai-duration 2` + `ai-prioritize 1` + `ai-unavailable 3` = **21 绿 / 1 红**；
那条红是 `ai-unavailable.spec.ts:130`，期望「AI 未启用」拿到「AI 服务暂时不可用。」—— 那是**别人在飞工作的半条链**
（`packages/app-host/src/ai-duration.ts` 未提交的 diff 正是 `cause: result.reason`，
而 `apps/web/src/features/ai/AiDuration.tsx:245` 已经在用 `outcome.cause`），
**不改、不代写**（见 §8.5）。顺带修掉一条既有的假红：`smoke.spec.ts` 原本用裸
`page.goto('/')`，于是它红在"模块图缺名字"上 —— 那既不是环境问题也不是功能问题，
**恰好毁掉了这条用例唯一的作用**（失败归因），已改为走相同的 `openApp()`。

**第 5 条（本轮补）专门盯样式**：它读的是**浏览器算完的值**，不是"类名在不在"。
`.ht-categories` 的 `display` 必须是 `flex`、方向 `column`、`gap` 非零；说明文字的
`color` 必须**等于**当场用探针元素解析出来的 `--ht-color-foreground-muted`
（**不写死 hex** —— 写死就变成"抄一遍 token"，token 一改断言照样绿）；
没有分类行时 `.ht-categories__cell` 与 `.ht-categories__bars` 的**条数必须是 0**
（🔴 这条防的是"未归类被伪装成一根柱子"）；区间文案里有「至」；未归类那句必须有
`border-top` 且宽度 > 0。逐条注入都实测会红：说明文字换成 `--ht-color-foreground`
（`rgb(100,116,139)` → `rgb(15,23,42)`）、删掉 `border-top`、把 `WeeklyBars`
改成 `{true && …}`。

这条用例写错过一次，值得记：最初断言 `.ht-categories__bar-label` 有 12 条 ——
**红的是我的期望，不是实现**：`WeeklyBars` 只在 `peakWeeklyMs > 0` 时才渲染，
而本轮能造出来的清单行是 0 ms。改成"未归类不得伪装成泳道或柱子"之后才是在测真东西。

⚠️ **仍然没有像素级断言的地方**（说清边界，不要当它已被覆盖）：
`.ht-categories__cell` / `__bar-label` 那 **12 格 / 12 根**的具体形状**没有断言**，
因为 Web 上还没有"给任务指定清单"的界面，`peakWeeklyMs` 造不出正数。
本轮是**用眼睛在真浏览器里看过的**（区块、泳道、行首色块、色槽面板、十二格网格都渲染正常，
无重叠无裁切）—— 但那是一次性取证，不是回归防线。
