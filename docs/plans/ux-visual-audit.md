# 界面丑的根因审计（2026-11-14）

> 触发：产品负责人看完语言设置页与「我的」页之后。
> 方法：真机 `uiautomator dump`（bounds ÷3 = dp）+ 读 `TEXT_STYLES` 与 `tokens.css` 的实际值。
> 拿 `apple-design` 与 `ui-ux-pro-max` 的规则对照。
>
> 这不是"逐处美化"，是**找系统性的错**。下面每条都有读数。

---

## 一、用户看到的三件事，与它们的实测原因

### 1. 「语言设置页上面为什么写着『外观』」

页面标题是「语言」，但内容区第一组的标题是「外观」。

**这是我把组名从「外观与语言」改成「语言」之后，又加回「外观」组，却忘了改页面标题。**
一句话的事，但它让整页的标题与内容对不上 —— Apple 的 wayfinding 第一条就是
"每一屏都要回答：我在哪"。

### 2. 「『外观』这两个字的标题，还没有下面『跟随系统』大」

**它们本来就不一样大，但差得不足以形成层级。** 实测：

| 元素 | 文字档 | 字号 | 字重 | 颜色 |
|---|---|---|---|---|
| 「外观」组标题 | `section-title` | **16px** | semibold | `foreground`（**主文字色**） |
| 「跟随系统」选项 | `row-title` | **16px** | medium | `foreground` |

**同字号、同颜色、只差一档字重。** 于是组标题在视觉上是一行"加粗的正文"，
而不是"一个分组的名字"。

更糟的是：仓库里**已经有一档专为组标题设计的样式** `group-label`
（13px + semibold + `foreground-muted`），它的注释写着：

> 这一档是 2026-10-02 被产品负责人的一句"为什么标题比下面的说明还小"逼出来的。
> ……后果是实测出来的那个倒挂：标题 11px，而它**管辖**的空态说明接的是
> `row-title`（16px）—— 说明比标题大 1.45 倍。

**同一个错又犯了一次**，只是这次的形状是"组标题与内容同档所以分不出"。
而这次没人被拦住，是因为 `section-title` 与 `group-label` **两档并存**，
用的时候随手选一个。

### 3. 「我的界面 UI、UX 排版都乱得要死」

真机量出来是**三条轴、十种间距**：

```
y=198   h=20dp x=48   '我的'          ← 页面标题   轴 48
y=588   h=44dp x=48   '注册 / 登录'    ← 按钮      轴 48
y=816   h=44dp x=96   '订阅'          ← 行        轴 96
y=972   h=44dp x=96   '设置'          ← 行        轴 96
y=1224  h=20dp x=120  '近期状态'       ← 组标题    轴 120  ← 比它管的行更靠右 24dp
y=1380  h=18dp x=96   '本周完成任务'    ← 值行      轴 96
```

| 症状 | 读数 |
|---|---|
| **三条左缘** | 48（标题/按钮）/ 96（行）/ **120（组标题）** |
| **组标题比它管辖的行更靠右** | 120 vs 96，差 **24dp** |
| **同一类"动作"两种缩进** | 「注册/登录」按钮 x=48，「订阅」「设置」行 x=96 |
| **组间距无节奏** | 实测 29 / 40 / 52 / 54 / 60 / 64 / 69 / 72 / 80 / 92 dp |

组标题为什么在 120？因为 `SectionHeader` 在标题**前面**画了一枚图标
（`icon` + `space.2` = 16 + 8 = 24dp），标题于是被推右。

## 二、根因（五条，全部是系统性的）

### 根因 1 · 同一个语义有两档文字样式并存

`section-title`（16 semibold foreground）与 `group-label`（13 semibold muted）
都叫"组标题"。**同语义两档 = 每一处自己按心情选**（`ux-principles.md` §6b 的同一条，
只是这次发生在文字档位层，不在控件层）。

### 根因 2 · 组标题用了主文字色

`section-title` 配 `color.foreground`。而组标题是**索引**，不是内容 ——
它应该弱于内容（iOS 的组标题是 `secondaryLabel` 灰字）。
用主文字色 ⇒ 它看起来像"第一条内容"。

### 根因 3 · 组标题前面塞了图标

`SectionHeader` 36 处调用全部带 `icon`，`SettingsSection` 5 处带 `leading`。
图标把标题推右 24dp（mobile）/ 72dp（设置页），于是：

- 组标题与它管辖的行**不在一条轴上**；
- 组标题看起来像"一个列表行"，因为它和行一样有前置图标。

iOS 的设置页组标题**没有图标** —— 组标题是纯文字索引，图标是行的装饰。

### 根因 4 · 两个组标题组件并行

`apps/mobile/src/ui/kit.tsx#SectionHeader`（带图标、`section-title`）
与 `packages/ui/src/settings/Settings.tsx#SettingsSection`（带 leading、`section-title`）。

同一件事两份实现 ⇒ 两边的手势、间距、颜色各自演进。
（`check:theme` 只钉 token 表，钉不到"组标题长什么样"。）

### 根因 5 · 间距没有阶梯

组间距由三处共同决定：`SectionHeader` 的 `paddingTop: space.2`(8dp)、
`SettingsSection` 的 `note` 间距、以及各屏 `<Stack gap>` 自己的值。
三处相加的结果是 29~92dp 的十种值 —— **没有任何一档是刻意定的**。

## 三、修法（按 `apple-design` §16 的 Craft / Simplicity）

### 一条轴、一档字、两种间距

| 项 | 定值 | 理由 |
|---|---|---|
| 组标题文字档 | **`group-label`**（13px semibold muted） | 已有且注释论证过：中文没有大小写线索，必须靠字重 + 弱色赢 |
| 组标题左缘 | **与行左对齐**（同一条轴） | 组标题管辖行，不跟着图标走 |
| 组标题前的图标 | **去掉** | iOS 设置页的组标题没有图标；图标是行的属性 |
| 组标题上方 | **24dp** | 分隔上一组 |
| 组标题下方 | **8dp** | 紧贴它管辖的第一行（"离它管的东西更近"） |
| 页面标题 | 保持 `screen-title`，x=`screen.gutter` | 不参与组标题体系 |

### 落地顺序（每一档都能判红）

1. **合并文字档**：`section-title` 在"组标题"这个用途上不再使用；
   `section-title` 保留给"内容区的小标题"（如「新建任务」面板标题），
   并加门禁：**组标题位置出现 `section-title` ⇒ 红**。
2. **`SectionHeader` 去图标**：`icon` 变可选、默认不渲染；
   36 处调用点删掉 `icon`。
3. **`SettingsSection` 的 `leading` 不再作用于标题**：移到 body 里，或去掉。
4. **间距收敛**：组标题上方 24、下方 8，写进 `group-label` 的消费契约。
5. **左缘统一**：`screen.gutter` 一条轴；组标题不吃额外缩进。

### 判据

- 真机 dump：组标题与它管辖的第一行 **x 相同**；
- 组标题字号 **< 行字号**，颜色为 `foreground-muted`；
- 同一屏组间距（上一组最后一行 → 下一组标题）**只有一个值**；
- 门禁：`check:group-heading`（新）—— 组标题位置用 `section-title` / 带 `icon` ⇒ 红。

## 四、这次为什么会发生（我自己的部分）

前面一个月里我在做"结构"（入口分层、控件形态、触控目标），
**把排版当成结构的副产品**。而实测里最刺眼的问题（组标题与内容同级、
组标题比内容更靠右）**一条结构判据都抓不到** —— 它们不违反任何"控件高度一档"
"一屏一种控件"，只违反**视觉层级**。

所以这一轮补的不是又一个控件规则，而是**读数的维度**：
`scripts/ux-parity-metrics.py` 现在只量"行高/行距/左缘种类"，
**量不出"组标题是不是比内容弱"**。这一轮要给它加两条：

- 组标题与紧随其后的第一行的 **x 差**；
- 组标题与其管辖行的 **字号比**（需要从源码取档位，dump 不给字号）。
