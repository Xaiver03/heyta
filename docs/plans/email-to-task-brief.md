# 工单：把邮件变成待办（自动收集线的第二条入口）

> 状态：**开工单，未排期**。负责人 2026-10-27 拍的是「另开一条线」，不塞进
> [`inbound-automation-work-brief.md`](inbound-automation-work-brief.md) 那八格。
> 那份工单里 §6 第 5 格登记的就是这一条。
> 本文件只回答一件事：**这条线要做什么、先量什么、哪几格归谁拍**，不含实现。

---

## 0. 为什么这是一条线，而不是自动收集的一个勾选框

用户嘴里的"自动收集"九成指邮件（原话口径记在开工单 §6 第 5 格）。而首版自动收集收集的是
**能主动发 HTTP 回调的来源**：签名 webhook → 服务端加密排队 → 设备领取 → 抽字段 → 落待办。
邮件不是"再来一条 webhook"，它换了三件事：**谁把内容送到我们手里**、**这封信凭什么算这个人的**、
**正文在链条的哪一段才第一次变成明文**。这三件每一件都是设计，不是配置。

🔴 因此这份工单的第一条纪律：**别把它做成"给现有规则表加一个 source=email"**。
加一枚枚举值在编译期是最便宜的，在合规与隐私上是最贵的。

## 0a. 2026-10-27 之后这条线的地基变了（重指向，不是重写）

[ADR-0077](../adr/0077-inbound-hosted-extraction-at-ingest.md) 落地了窄档「接收即抽取」：
**托管档可以选择让服务端在收到数据的那一次请求里当场抽字段**，抽完立刻把源正文从那一行上抹掉，
结果重新封给同一枚收件人公钥，任务写回仍然是设备的事。

对本工单的三处直接影响，逐条对上原有的问题：

| 这份额外能力落地后 | 影响本工单哪一格 | 怎么影响 |
|---|---|---|
| "服务端读明文"第一次有了一个**在册、可红、有开关**的先例 | §2 第 3 问（明文第一次出现在哪） | 那一格从"要不要开这个口子"变成**"复用哪个口子"**：邮件正文可以走同一条腿，不必再造第三条 |
| 抽取那条腿住在 `server/src/automation/hosted-extraction.ts`，开关是 `automation_rules` 上一枚可空布尔 | §3 那一刀 | P0 那一刀（封存排队、设备解密）**仍然是默认那一刀**；托管档"当场抽"是叠在它上面的第二刀，接法是同一条路由、同一枚开关 |
| 字段授权投影 + `needs-confirmation` 那一档已经在真机上可用 | §2 第 4 问（长文与格式） | 邮件长文的"模型没把握的一整段"有了承接的档位，**但上限与语义没为长文验过**（§1 那格现量仍然有效） |

🔴 一条不许顺势滑过去的差别：webhook 那一档的来源方**已经被签名与规则绑定**，
而邮件的"这封信凭什么算这个人的"（§2 第 2 问）**还没有答案**。
复用抽取那条腿，不等于复用归属那一步 —— 归属没证之前，抽取腿接上邮件就是替陌生人读信。

## 0b. 2026-10-29 23:5x · 负责人拍了形态：**只做"上游转 JSON"这一条**，本版本不建我们的收信服务

他的原话：「邮件转待办要做呀。肯定只收 JSON 的。毕竟这个就是 DIY 的。」

这一拍正对着 §2 第 1 问（投递方式）与第 2 问（归属证明），并把 §3 那两刀换成了**第三刀**：

| 他的决定意味着 | 落到哪一格 |
|---|---|
| v1 **不**发专属收件别名、**不**自建 MX、**不**收用户的 IMAP 凭据 | §2 第 1 问选「都不选」；§3 的 P0（专属地址 + 封存排队）**不在本版本射程** |
| 邮件这条路 = 用户那一侧的转发器把内容转成 JSON，POST 进现有那枚 webhook 地址 | 接收、验签、封存、领取、抽字段、回执**一条都不新造** |
| 归属那格的答案**换了位置**：从"这封信凭什么算这个账号的"变成"这台转发器凭什么拿这把密钥" | §2 第 2 问 ⇒ 与 webhook 同档（界面上签发、只展示一次、可撤销可轮换），**不需要新裁决** |
| §0a 那条"归属没证之前不许接抽取腿"的拦路 | 随上一行一起解掉：签名者就是规则属主本人 |
| 「任何邮件都能收」这句还是不能说 | §4 第 4 格不变，而且更硬——我们连信都没见过 |

🔴 **这一拍没顺手解掉的三格**，下一位别读成一并闭了：

1. **交付物本体还没做**：一份能照抄的对接件（上游转发器 → 带签名的 POST → 事件进队列 → 设备领用），
   含"HTML、附件、长正文由上游砍到哪一步"的如实边界。这一格登记在
   [`inbound-automation-work-brief.md`](inbound-automation-work-brief.md) 的 §11 G1。
2. **一封信拆成 N 项到底扣几次额度**（§2 第 5 问）。开工单 A4 那次修法只钉住"一次物理调用 = 一次计量"，
   没回答"一封信里 3 个待办 = 几次调用"。判据形状照 §2 第 5 问那句写，仍归计量那族。
3. **§4 第 1 格（用哪个域名、谁出这台收信服务器）随 P0 一起搁下**，是**搁下不是废除**：
   哪天真要做专属邮箱那条，这一格重新回到桌面。

## 2. 六个必须先回答的问题（每个都带一个能红的判据）

1. **投递方式选哪条**：专属地址（每人一个带令牌的收件别名，转发到我们的接收端）· IMAP 拉取
   （要用户交邮箱凭据）· 自建 MX（要域名、反垃圾、可用性 SLA）。
   判据：选定后本文件必须写清"谁付这台服务器的钱、邮件停在谁的盘上几天"。
2. **归属证明**：一封信凭什么算这个账号的？发件地址绑定、专属令牌、还是首次确认邮件？
   判据：一条用例——同一封信投给两个账号，只有被证明的那一个领得到。
3. **明文第一次出现在哪**：端到端加密是本产品的地基。若正文在接收端就是明文，
   那等于新增一类服务端可见的用户内容，与 `AGENTS.md` §1 的前提直接对冲。
   判据：披露块（`web.ai.disclosure.*` 那一族）必须逐字说出邮件正文的处置；
   两壳对账尺会把不一致念成红（`apps/mobile/tests/ai-copy-parity.spec.ts`）。
4. **长文与格式**：HTML、引用链、签名档、转发嵌套、附件、多任务一封信。
   判据：`needs-confirmation` 那一档要能承载"模型没把握的一整段"，不许退化成整封塞进 `note`。
5. **额度与计费**：一封邮件可能拆成 N 个待办，扣一次还是 N 次？现有计量口径见
   开工单 §3 A4（那次"一次调用扣两下"的确证）——邮件这条入口**别在计费口径未拍之前上线**。
   判据：一条真库用例钉"一封含 3 个可执行项的邮件 = 几次模型调用 = 几次计量"。
6. **合规与对外**：域名、ICP/备案口径、留存与删除请求（GDPR 式"删掉我的邮件"），
   以及"这台实例到底替不替你存正文"这句话怎么写。
   判据：`docs/reference/inbound-automation-protocol.md` 的保留那一节必须能逐句对上真实实现
   —— 现成的范本是那把 7 天保留对账尺（`scripts/check-retention-window-parity.mjs`，
   A6 那一格入库的）。

## 3. 建议的第一刀（最小闭环，且不许越界）

> ⚠️ **本节那两刀（P0／P0.5）自 2026-10-29 起不是当前射程**——形态已由负责人改拍成"上游转 JSON 的 DIY 那条"（§0b）。
> 旧文原样留着当设计记录：哪天真要做专属邮箱，这两刀还是唯一排过的那版。

**P0 = 专属地址 + 归属证明，抽取默认仍归设备**：给每个账号一枚一次性本地部分（`+<token>` 别名或独立域），
只接**这一类**信，接收端做与现在 webhook 同样的动作——**HPKE 封存后排队**，设备领取时才解密。
这一刀的价值是把"谁把内容送到我们手里"和"归属"两格落地，同时**不新增服务端可见的正文**。

**P0.5（有先例可接，不是新发明）**：归属那一格有了答案之后，"当场抽"这一档**直接复用 ADR-0077 那条腿**——
同一枚可空布尔开关、同一条 `runHostedExtractionAtIngest`、同一套零内容日志判据。
本工单**不许**为邮件另写一条抽取链（那份 ADR 的门槛正是"不许长出第二套发送腿"）。
接之前必须先量一件事：邮件长文过不过得了那枚字段授权投影与 `maxItems`（§1 现量那格说的就是这个）。

明确不做（P0 地界外）：自建 MX、反垃圾训练、附件解析、日历邀请（iCalendar）解析、邮件线程合并。

## 4. 归负责人、执行 AI 不许拍的格子

1. 用哪个域名/谁出这台收信服务器，以及它是否进 heyta 的在册部署。
2. 是否接受"用户交 IMAP 凭据"这种产品形态（它会把我们的支持面放大一整层）。
3. 第 2 节第 5 问那句计费口径（与开工单 §6 第 3 格是同一件事）。
4. 对外怎么宣传这条入口——尤其"任何邮件都能收"这种话，在 P0 那一刀之后仍然不成立。
   ⚠️ 而且现在多了一层：**ADR-0077 那一档的对外披露本身还没发**（那份 ADR 的 §7 第 1 行）。
   邮件这条线如果要"当场抽"，披露是**第二份**文件（要多说清"信正文进我们服务端时会被读"），
   不能拿 webhook 那份草稿套用——它一个字都还没上线。
5. AC 的勾（这条线如果要开 AC-9～AC-n，勾法沿用自动收集那份计划的纪律）。
