## 0. 你要交付的东西（先看清终态）

heyta 是本地优先、端到端加密的任务应用，数据走 op-log（事件溯源，只追加）。"删除"在这套系统里有四个**互相独立**的标记：

| 态 | 字段 | 用户看到 | 能不能回来 |
|---|---|---|---|
| 已完成 | `completedAt` | 完成列表 | 取消勾选 |
| 归档 | `archived` | **哪都看不到**（本轮要修） | 本轮补"取消归档" |
| 回收站 | `deletedAt` | 回收站 | 还原 |
| 彻底删除 | `purgedAt` | 回收站里也没了 | **回不来**（但数据仍在日志里） |

三条不可让步的产品立场（写进 ADR，不许在实现时"顺手改"）：

1. **`purgedAt` 不是物理删除。** 界面与文案**不许**出现"永久删除/已清除/不可恢复的数据已抹掉"这类说法，
   只许说"不再提供恢复"。理由：op-log 只追加，我们**没有**任何物理擦除能力。
2. **不做自动保留期**（不写"30/45/90 天后自动彻底删除"）。理由见计划 §1.5 三条。
3. **一个用户意图 = 一条 op**（`AGENTS.md` §3.4）。批量操作要拆成多次用户确认，不许一次点击 fan-out 多条 op。

## 2. 批次 A —— 现在就能交（三条，各自独立可提交）

### A1 · 搜索不许返回墓碑

**症状**：Web 端把"已删除"甚至"已彻底删除"的任务搜出来。移动端不会。
**根因**：`packages/domain/src/search.ts` 的 `searchTasks` **自己不滤墓碑**，滤不滤取决于调用方递进来什么；
Web 递原始物化表（含墓碑），移动端递已过滤的列表。

**改哪里**：在 `searchTasks` **函数内部**开头排除 `deletedAt !== undefined` 与 `purgedAt !== undefined` 的任务。
🔴 **不要在调用方补过滤** —— 那等于把同一个决定留在 N 个地方（这仓库已经为此栽过多次）。

**判据（必须能失败）**：
1. 单测：往输入里放一条带 `deletedAt` 和一条带 `purgedAt` 的任务，标题都命中查询词 ⇒ 两者都不得出现在结果里。
2. 变异：把你在 `searchTasks` 里加的那行过滤**删掉** ⇒ 判据 1 必须红，并贴出红的那一行。
3. 现有调用方行为回归：Web 与移动端的搜索用例仍绿。

**别做**：不要顺手把 `packages/ui` 里 `SearchPanel` 的入参类型改掉（登记项，不属于本批）。

### A2 · 已删除任务的提醒不许再弹 + 投递过要落库

两条各自独立的缺陷，落点相邻，**同刀交付但不许混成一个提交**。

**(a) 已删任务的提醒仍在投递。**
`dueReminders` / `isReminderPending` 只看**提醒自己**的墓碑，**从不看所属任务**；
Web 的投递处只挡 `task === undefined`，而墓碑任务在 map 里**是存在的**。

- 🔴 **主修在动作层**：`packages/app-host/src/reminder-actions.ts` 的 `due()` ——
  不把"所属任务已进墓碑（或已 purge）"的提醒算成到点。同文件已有 `taskOf()` 这类取任务的现成函数，
  **不要新写一份查询**。
- 次修在投递处：`apps/web/src/features/reminders/notify.ts` 加第二道 `task.deletedAt !== undefined ⇒ 不投`，
  并把该处**与实现相反的注释**改成实话（原注释写着"这种情况不投"，而代码照投）。

**(b) 🔴 同一条到点提醒会再弹一次**（计划 D14 / G-9 定性为"缺陷根因"那一条）。
动作层的 `markReminderFired`（写 `firedAt`）**生产零调用点** ⇒ `due()` 永远把它当成"还没投递"，
Web 唯一的去重是**一次页面加载**的内存 `Set` ⇒ 刷新后、以及换一台设备，都会再弹一次。

- 改：投递成功后调用 `markReminderFired`（它自己是幂等的，已投递返回 `false` 且不写 op）。
- 判据：① 单测——投一条 ⇒ `firedAt` 落库、再调 `due()` 不含它；
  ② **第二个载体**——重放同一份状态到另一个引擎（模拟"另一台设备/刷新"）⇒ 不得再出现在 `due()` 里；
  ③ 变异——把那次 `markReminderFired` 调用注释掉 ⇒ ①② 必红。

**A2 整体判据**（含 a、b）：
- 单测：建"带提醒的任务" → 删任务 → `due()` 为空。
- 真浏览器 e2e（Playwright，`pnpm check:ai-e2e` 那一套）：到点 → **数通知条数**。
  🔴 必须配一条**同趟必然命中**的正向对照（任务未删时确实投了 1 条），
  否则"0 条"可能只是投递根本没接上（探针坏 / 够不着 / 真没发生，三者输出一样）。
- ⚠️ 移动端**没有**通知投递（整条路径从未实现）⇒ **A2 只证得到 Web**。
  交付说明里不许写"四端已修"，要写"Web 端已修；移动端无投递，见计划 §5"。

## 6. 🔴 防作弊验收（这几条是这份交接书自己的判据）

4. **不许引用"某道门禁会抓到这个"作为保障**。方法级"写了没人接"、以及 Swift / C# / C / ArkTS 三个原生壳，
   现有门禁**结构上看不见**（原因见计划 §2.0）。要保障就自己写判据。
5. **不许在用户看得见的文案里出现内部字段名**（`purgedAt`/`deletedAt`/`op-log`/`SQLite`），
