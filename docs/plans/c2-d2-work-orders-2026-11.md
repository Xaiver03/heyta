## 1. 三处先拍掉，免得两个分包各自发明

### ① R10「明天视图」**要做** —— PRD 与界面地图对它的定级冲突，以"主路径"为准

| 文件 | 它的判断 |
|---|---|
| PRD §P2 | 「`TaskFilter` 七分支无 `tomorrow`；但「今天 + 未来 7 天」已能覆盖，**边际最低**」 |
| [界面地图](../research/ticktick-surface-matrix.md):266 | 「仓内基线自己把它判成 **P0**；而 heyta 的 `TaskFilter` 是**判别联合**，缺这一档时"明天要干什么"只能翻今天列表往下扫，**主路径走不完**」 |

**裁决：做。** 理由是那条主路径 —— **每天早上过一遍明天**是这类产品最固定的日常动作，而缺这一档时
它变成"翻列表往下扫"，也就是**功能在、路径不在**。PRD 的"边际最低"是按**排期成本**说的（增量极小），
不是"不值得做"；而 :474 那句把它和标签管理页并列为"主路径上只缺两格"，正好说明它该做。

**成本也支持**：纯增量判别联合分支 + 一行 rail 项（`apps/web/src/features/shell/view-tabs.ts:87` 那一族）。

### ② R13a「我的」页**不照抄它的"钱排第 2"**

取证记的形状是：身份 → **钱** → 统计 → 引导 → 版本 → 退出，且统计本身是会员卖点
（`upgrade_item_statistics`）⇒ "我这一年干了多少"与"买不买"在同一屏上互相解释。

**裁决：不照抄。** 我们卖的是自托管，不是订阅墙；把统计做成会员卖点，等于对自建用户说
"你的数据要付费才看得见"。落地两条硬要求：

- **统计与会员解耦**：统计在任何档位都完整可见，会员入口单独一行，不进统计区；
- 「我的」页的**第一位是身份**，最后两位是**版本 / 退出**（这两条是"找得到"锚点，不许被挤走）。

📌 **现状基线（可直接对着做）**：设置浮层现在是**七组**——
账号 / 订阅 / 数据与同步 / 提醒与通知 / 外观与语言 / 功能与 AI / 关于与帮助。
证据图：[`apps/web/evidence/shell-sync-rail/settings-pending-3.png`](../../apps/web/evidence/shell-sync-rail/settings-pending-3.png)
（证据补齐分包 2026-11-06 拍的，我人眼读过；同一张图上还能读到同步那三行本地读数）。
R13a 要做的不是"再加几组"，而是把**个性化**与**行为默认值**分成两个分区（ADR-0085），
并保证任意设置项**两级内可达**。

### ③ R13b 外观**零 op**，按 ADR-0085 执行

[ADR-0085](../adr/0085-appearance-is-device-local-and-never-an-op.md)：外观（主题 / 深浅 / 字号 / 字体 /
密度 / 行着色开关与依据 / 应用图标 / 便签与倒数日样式）是**设备属性**，写本机、**不产生 op**；
行为默认值（周起始 / 默认提醒 / 默认清单 / 默认时长 / 智能识别）走 op。
判据：改主题 ⇒ op-log 条数不变（注成 `dispatch` 就红）。

✅ **登记表已经建好了**：[`docs/reference/client-persistence-keys.md`](../reference/client-persistence-keys.md)
（四档：表达 / 视图状态 / 本机数据 / 基础设施，现量 21 个键对上源码），
并由 `pnpm check:persistence-keys` 盯着 —— **加一个键不登记就红**（三条断言 + 三条自检臂）。

🔴 所以 D-② 的动作是**往里加行**，不是新建：R13b 每加一个外观键（主题预设 / 字体 / 密度 / 行着色依据 / 应用图标），
就按 A 档登记一行；**别**塞进 C 档（C 是"本机数据"，塞进去等于把外观当数据）。
⚠️ 门禁只认**字面量**键名（拼出来的扫不到）—— 新键必须写成 `'heyta.x.y'` 这种字面量。
