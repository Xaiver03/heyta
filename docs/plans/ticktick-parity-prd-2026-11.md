## 1. 需求清单（按优先级）

### P0 · 不做就是漏气

#### R14 入口契约：**一个动作该从哪一层出来**（先行，不是功能）

| 项 | 内容 |
|---|---|
| **用户会怎么遇到** | 同一个动作在三处出现、或者哪都没有；想改一个字段要先进详情再切页；空态里有个按钮但列表里没有 |
| **产品负责人原话** | 「**我觉得我们目前的 UX 极度混乱**」「某个按钮从信息架构上应该是怎么出来的，这一点非常重要」 |
| **已有的自身证据** | `product-level-ia-ux-audit.md` 判「IA 骨架执行 8 分 vs 决策收敛 5.5 分」；`multi-end-entry-coverage-audit.md` 列了 7 条两端都缺的产品洞；`filters/view` 与 `视图 key` 两套模型重叠 |
| **做什么** | 产出**一份入口表**（动作 × 层级 × 主入口 × 是否允许第二入口）与**五条可判红规则**，先于 B/C/D 落地。参考它对标的做法见 `docs/research/ticktick-ux-ia-and-entry-paths.md`（取证中） |
| **四层（待取证确认）** | 全局（菜单栏/托盘/热键）· 视图（侧栏与工具条）· 对象（行菜单/详情底栏）· 字段（行内直编） |
| **验收判据（能红）** | ① 入口表里**每个动作有且只有一个主入口**；写个脚本从表里查重复，重复即红。② 抽查 10 个动作，能在界面上按表走到（给截图或 e2e 名）。③ 反向：故意给某个动作加第二个主入口，①必须红。 |
| **代价** | 小（1–2 天，纯文档 + 一张表 + 一个自检脚本），但**它是 B/C/D 的前置** |
| **依赖** | 无。**先做**，否则 B/C/D 各自发明入口 |



#### R1 多账号本地库隔离

| 项 | 内容 |
|---|---|
| **用户会怎么遇到** | 共用一台电脑换账号登录 → 上一个账号的任务还在侧栏里；或退出登录后数据仍在本地 |
| **证据** | 三个壳的库名写死（`apps/mobile/src/db/open-host.ts:35`、`apps/web/src/lib/oplog.ts:451`、`apps/desktop/src/host.ts:33-35`）；`packages/storage/src` 里 `grep accountId` **命中 0**；退出登录只清凭据/小组件/vault，**不清 op-log** |
| **做什么** | 二选一并写进 ADR：**(a) 一设备一账号**（明确拒绝第二账号并给出口）／**(b) 单库 + accountId 分区键**（op-log 与实体都带 accountId） |
| **验收判据** | ① 账号 A 写 3 条任务 → 退出 → 登录账号 B → **本地查不到 A 的任何实体**（不是"界面不显示"，是存储层查不到）；② 切回 A → 数据完整回来；③ 判据能红：把隔离逻辑注掉，①必须失败 |
| **代价** | 小（op-log + 实体加可选字段 + 退出路径） |
| **依赖** | 无。**优先级高于任何新功能** |

#### R2 撤销历史栈（误删可恢复）

| 项 | 内容 |
|---|---|
| **用户会怎么遇到** | 删错一个清单 / 一批任务，超过 5 秒 → 只能去回收站翻，而回收站不一定收这一类 |
| **证据** | 撤销只有 5 秒回执（`check-undo-receipt.mjs`）；`undoStack|redoStack` 全仓只命中一个测试文件 ⇒ **生产代码没有历史栈**，绑 ⌘Z 是空操作 |
| **做什么** | 用已有的 op-log 做**可回滚的历史栈**（回滚 = 生成反向 op，不删历史）；界面给 ⌘Z/⇧⌘Z 与一条"刚刚做了什么" |
| **验收判据** | ① 删清单 → ⌘Z（**任意时刻**，不限于 5 秒）→ 清单与它的任务全回来；② ⇧⌘Z 能重做；③ 判据能红：把反向 op 生成注掉，①必须失败；④ **回放不产生副作用**（`hard-constraints` §3.4） |
| **代价** | 中（要处理"跨设备撤销"与"撤销已被别人改过的对象"） |
| **依赖** | 无，但**与 R7 共用一条"可解释性"叙事** |

#### R3 重复任务「跳过这一次」

| 项 | 内容 |
|---|---|
| **用户会怎么遇到** | 每周三的例会，这周放假 → 没有"跳过这一次"，只能删任务（丢历史）或改规则（动到历史实例） |
| **证据** | `exDate` 全仓 **0 命中**；P3 判它是"真缺口里唯一可立即做的"（`ticktick-data-model-parity.md` §2.3） |
| **做什么** | `Task` 上加**可选** `exDates?: string[]`（**不物化实例、不 bump schema**），与重复规则并存 |
| **验收判据** | ① 跳过某一次 → 该次不再出现，**其它次不受影响**；② 撤销后可恢复（依赖 R2）；③ 判据能红：把 `exDates` 过滤注掉，①必须失败；④ `CURRENT_SCHEMA_VERSION` 不变（有测试断言） |
| **代价** | 小 |
| **依赖** | 建议在 R2 之后（否则"跳错了"没法退） |

### P1 · 另加一条：R13 设置与个性化（**新增，产品负责人点名**）

> 产品负责人 2026-11-06：「重点看它的**设置界面**和**我的界面**，这些东西非常重要，因为这是个**个性化**的东西。」

> 详细取证见 [`ticktick-settings-and-personalization.md`](../research/ticktick-settings-and-personalization.md)（548 行，已落盘）。

**它的个性化不是一个开关，是八个维度**（两端同名可对照）：

| 维度 | 它的做法（证据） | heyta 现状 |
|---|---|---|
| ① 主题 | 预设网格 `prothemegrid` / 纯色 `purecolorgrid` / 深色 `darkcolorgrid` / **自定义** `customthemedialog` + `CustomThemeEditViewController`；文案里有「专属主题」「自定义主题」「颜色主题」 | 只有明暗（`data-theme` 27 处） |

**还有一条最"我的"但最便宜**：**行着色** —— 文案 `list_color` / `colored_by_list` / `colored_by_tag` / `show_or_hide_list_colors` ⇒ 任务行可以按**清单色**或**标签色**着色，且可整体关掉。heyta 全仓 `colored_by|listColor` **命中 0**。

**现量差距（取证给的准数，不是我估的）**：

| 指标 | 滴答 | heyta |
|---|---|---|
| 个性化维度 | **8 个，全部有证据** | **完整 0 / 半有 4 / 没有 4** |
| 主题 | 28 张预览 + 61 调色板 + **5 个系列** + 自定义 | **2 个值**（`light`/`dark`，`theme.ts:9`） |
| 设置面板组件 | 50 个（macOS nib）+ 148 个含 config/setting 的 BAML | **18 个** |
| 设置分组 | 一个纵向菜单（项数未核实） | **7 组**（`SETTINGS_NAV_ITEMS`，`App.tsx:297`） |
| 「个人设置」字段 | Windows `SettingsModel` **128 列** + `UserPreferenceModel` 21 子配置 + `CommonSettings` 32 列 | 18 个面板 |

**它自己给出的一条分类判据（值得直接采纳）**：

| 类 | 用户会说出口的那句 | 改的是什么 |
|---|---|---|
| **个性化** | 「让它看起来像我」 | 同一份数据的**表达**，不改行为 |
| **行为默认值** | 「让我少填几次」 | 新建/触发时的**初值** |

> 它把两类**混在同一个设置树里**（取证 §3.3 给了三条证据）。heyta 若照抄这个混合，用户会在"想换个主题"时要翻过一堆默认值。**R13a 的 IA 必须把两类分开呈现**，这条要写进 E 包的入口表。

**「我的」屏的形状（它的选择，不是必然）**：身份 → **钱** → 统计 → 引导 → 版本 → 退出，**会员排在第 2 位**，且统计本身是会员卖点之一（`upgrade_item_statistics`）—— 于是"我这一年干了多少"与"买不买"在同一屏上互相解释。
**这是一条要产品拍板的问题**：我们做不做这种"钱靠前"的编排？我倾向**不照抄**（我们卖的是自托管，不是订阅墙），但要把"统计"与"会员"解耦这件事写死。

**R13 怎么进排期（不新增分包，拆成两半）**：

| 子项 | 内容 | 并入 | 理由 |
|---|---|---|---|
| **R13a** | 设置树骨架（分区导航 + 一个入口）+ 「我的」页（账户 / 会员 / 统计 / 引导一块） | **C 包**（入口与可达） | 它解决的是 **IA 与入口**，不碰设计系统；而且 heyta 现有 `apps/web/src/features/settings` 已堆到 **45 个文件**，说明缺的是"结构"不是"功能" |
| **R13b** | 主题系统（预设/纯色/自定义/自动深浅）+ 字体与密度 + **行着色** + 应用图标 | **D 包**（视觉与状态） | 它全部落在 `tokens.css` 与设计系统，与 R9 暗色 token 同源，**必须同一个人做**才不会打架 |

**验收判据（R13，每条要能红）**：
① 选一个预设主题 → 刷新/换端后仍生效，且**只改 token 不改组件**；把主题持久化注掉，必须失败。
② 自定义主题改一个色 → 生成的新 token 集能通过 `check:design`（不允许裸值），且对比度达标（给读数）。
③ 行着色切「按清单 / 按标签 / 关」三态，列表颜色随之变；注掉读取点必须失败。
④ 设置树：任意一个设置项都能从**一个**入口两级内到达（给一张路径表），没有"只在某个按钮里藏着"的项。

## 2. 明确不做（写死，避免反复讨论）

| 不做 | 理由 |
|---|---|
| **委派 / 团队协作的「聚合型」部分**（排行榜 / 组队 / 防作弊 / 可信跨用户汇总） | [ADR-0062](../adr/0062-shared-list-key-distribution.md):32/:56 明写「**聚合型协作不可做**，这条继续成立」；**分发型协作（per-list key）是可做的**，两者被刻意拆开 —— 别把「不做聚合」误读成「不做协作」 |
| **`assigneeUserId?` 继续悬空** | **零写点**（ADR-0062:78-79 自己就记着这件事，仓里还有测试断言没人读写），且 ADR-0062:45 明写「`assignee` 不进明文元数据」⇒ 它有隐私维度。**先删**，要协作按 0062 重开 |
| **白噪音** | 缺的是**音频子系统**（`new Audio(` 等全仓 0），不是开关 |
| **应用锁** | 与 Vault 解锁流程可能打架，语义没定之前做就是埋雷 |
| **照 153 个窗补界面** | 粒度裁决见 §3；照窗口数补会多出约 150 个没人要的窗 |

## 3. 两个口径先定，否则清单会被读歪

1. **「屏」的粒度 = 按「用户能叫出名字的一次操作」**，不是窗口数、也不是 ViewKey。落地的实质结论：**只补 R8/R10 这两格**，不去追 153。
2. **「顺序」属于谁**（清单 / 视图 / 用户）—— R4 第一步开工前必须先答，否则会做出几套互相打架的排序。

## 4. 分包：**五个**长任务（E 先行），不拆碎

> 用户要求：**并成几条大的、长的任务**，不要散。各包按「同一个子系统 + 同一套门禁」并线，
> 每包内部由分包商自己再分（那是它的事），总包只看**验收判据**。
>
> 🔴 **2026-11-06 追加：五个包，不是四个。** 产品负责人两次点名 UX：
> 「**我觉得我们目前的 UX 极度混乱**」「某个按钮从信息架构上应该是怎么出来的，这一点非常重要」。
> 原来的 C 包（入口与可达）只覆盖了「有没有入口」，**没覆盖「入口该长在哪一层」** —— 而这一层是所有包共用的地基。
> 所以把 **E · IA 与入口契约** 单独提出来，**放在所有包之前**。

| 包 | 包含需求 | 为什么并在一起 | 主要门禁 |
|---|---|---|---|
| **E · IA 与入口契约**（**先行**） | R14（新增）：入口分层规则 + 一张**入口表** + 5 条可判红规则 | 它不写业务代码，只产出**所有包都要遵守的放置规则**；不先做，B/C/D 会各自发明入口 —— 那正是「UX 混乱」的成因 | `check:reachability` · 入口表自检（同一动作不得 ≥2 个主入口） |
|---|---|---|---|
| **A · 数据可信** | R1 + R2 + R7 | 都在回答同一个用户问题：「**我的数据在不在、对不对、丢没丢**」。共用 op-log 与状态源 | `check:reachability` · 回放无副作用 · 撤销/隔离的"能红"判据 |
| **B · 任务操作闭环** | R3 + R4(①) + R8 | 都动 `domain` + **op 写路径**，且都要"一次操作 = 一条 op"这条纪律 | `check:layering` · schema 不 bump · 单 op 断言 |
| **C · 入口与可达** | R6 + R12 + R10 + **R13a 设置树与「我的」页** | 都在**入口/IA 层**，不碰数据语义 | `ui-acceptance`（不抢前台）· 设置路径表 |
| **D · 视觉与状态** | R9 + R11 + R5 + **R13b 主题/字体/行着色** | 都在**呈现层**，共用设计系统与四态规范；R13b 与 R9 同源（都动 tokens），必须同一个人 | `check:design` · `check:ui-language` · 截图人看 |

**顺序**：`E（1–2 天）→ A 与 B 并行 → C → D`。

- **E 先行**：它只产出一份**入口表 + 五条规则**，不写功能；但 B/C/D 每加一个按钮都要按它放。E 不做，B/C/D 会各建一套入口，最后再统一就是一次返工。
- **A 与 B 可并行**：A 动底座（storage/op-log/各壳 host），B 动 domain 写路径，文件不重叠；B 唯一的软依赖是"撤销原语"，接口一落就能开。
- **C/D 在后**：C 的 R10（明天视图）与 B 抢 `task-filter.ts`（17 个消费者）；D 的 R11/R5 与 B 抢 `packages/ui`。R13a/R13b 分别并入 C/D。

**每包交付物固定三件**：① 一份计划（含"这条判据怎么才会红"）；② 实现 + 门禁读数；③ 一段"用户能看到什么变化"的验收记录（截图或 e2e）。
