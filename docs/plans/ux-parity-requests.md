## P1-1 · 日历顶栏加「今天」

### 要加什么

日历页顶栏右侧加一枚回到当天的图标按钮（与任务页顶栏的搜索/同步/⋯ 同构）。

### 为什么要加

滴答的日历顶栏有**周视图切换**（`view_week_view_mode`，144px=48dp）；
我们顶栏只有标题，翻月只靠「上个月 / 下个月」两枚箭头。

真机复现：从 11 月连点「下个月」到次年 3 月，要 4 次点击；想回来再点 4 次。
**退出重进是更快的路径** —— 这说明当前入口不够用。

### 建议加在哪

`apps/mobile/src/screens/CalendarScreen.tsx` 传给 `AppBar` 的 `actions`，
与任务页同位置（`tasks` 页顶栏三个 action 就在 `x=664/820/976`，各 44dp）。

**不新增路由、不新增菜单项、不新增一屏** —— 只是在已有顶栏的 actions 位加一枚。

### 调研：为什么放不进现有位置

| 候选 | 为什么不放 |
|---|---|
| `⋯` 菜单（如果加） | 日历页**现在没有 `⋯`**，为这一个动作开一个菜单 = 新增入口 |
| 月份标题长按 | 不可发现（没有任何提示说明能长按），且与"点标题=切换月/年视图"冲突 |
| 左右箭头的双击 | 同上，不可发现 |
| 底部导航「日历」再点一次 | 系统已用于"回到 tab 根"，语义被占用 |

顶栏 actions 是**唯一既有且可发现**的位置。

### 不放会怎样

翻远之后回不到今天，只能反向连点或退出重进。翻得越远代价越大。

### 放进去后谁在用

每天用日历的人：早上打开看今天、翻周计划后回今天。

### 验收

- 真机 dump：新按钮 44×44dp，`content-desc` 为「回到今天」；
- 点一次后，月份标题回到当月且当天被选中；
- `capture-ux-parity.sh heyta calendar-today` 归档 + `check:tap-targets` 绿。

## P1-2 · 新建面板加描述输入

### 要加什么

`CaptureComposer` 的标题输入下面加一行可选的描述输入（单行，占位「补充说明（可选）」）。

### 为什么要加

滴答的快速添加是**两层**：`et_title`（准备做什么？）+ `et_content`（描述），
一次性写完。我们的新建只有标题 —— 想写描述必须先建、再点进详情、再点「编辑备注」。

真机读数：滴答浮层 398px=133dp = 标题行 + 描述行 + 48dp 图标工具条。
我们的底部 Modal 已经比它高（标题 + 日期 + 添加 + 落点 + 取消）。

### 建议加在哪

`packages/ui/src/capture/CaptureComposer.tsx` —— **共享层**，加了两端同时得
（web 的锚定浮层与移动端的底部 Modal 用同一个组件）。

### 调研：为什么这是"加字段"不是"加入口"

它不新增任何路由/菜单/tab，只是已有输入区多一行。按 §8 的判据属于
「已有面板内的字段」（第一档，可直接做）—— 但因为会改变**两端共用的输入区形状**，
还是先请你过目。

### 不放会怎样

快速录入变成两次操作；用户干脆不写描述（描述是后面的检索依据，不写等于丧失可搜性）。

### 放进去后谁在用

所有用快速添加的人；尤其是"一句话标题 + 一句补充"的记录习惯。

### 验收

- 真机 dump：描述输入 44dp 高，与标题输入同档；四段间距仍满足 4 / 12 / 24 三档；
- 空描述提交时行为不变（不写空字段）；
- `check:capture-shape` 与 `check:tap-targets` 绿。

## P1-3 · 移动端手动主题切换

### 要加什么

设置 → 语言 那一页（原「外观与语言」）改回两段：**外观**（跟随系统 / 浅色 / 深色）+ **语言**。

### 为什么要加

滴答的外观页有 **3 个顶部 tab**（主题 / 应用图标 / 显示）+ 3 列颜色网格。
我们这一轮把组名从「外观与语言」改成了「语言」—— 因为**移动端根本没有手动主题能力**
（`HeytaUiProvider` 只读 `useColorScheme()`，没有任何 override 入口）。

改名字是绕过，不是解决。用户的系统是深色但想用浅色时，没有出路。

### 建议加在哪

1. `packages/ui/src/theme/HeytaUiProvider.tsx` 加一个 `schemeOverride?: 'light' | 'dark' | null`，
   优先于 `useColorScheme()`；
2. `apps/mobile/src/screens/SettingsScreen.tsx` 的语言组前面加「外观」组，
   用**已有**的 `ChoiceRows`（三行：跟随系统 / 浅色 / 深色）。

### 调研：为什么不能只做 web

`check:theme` 已钉住主题变量的一致性；`HeytaUiProvider` 是两端共用的。
加 override 是**产品级抽象**（任何端都能用），不是一次性组件 —— 符合 §8 第二档。

### 不放会怎样

只看系统主题。系统深色 + 想用浅色截图的场景无解；组名也名不副实。

### 放进去后谁在用

所有想在不改系统设置的前提下换主题的人。

### 验收

- 选「浅色」后，`HeytaUiProvider` 的 resolved scheme 为 light 且**重启后保持**（落本地设置）；
- 「跟随系统」时行为与今天完全一致（回归判据）；
- 设置页该组三行各 44dp，`check:tap-targets` 绿。
