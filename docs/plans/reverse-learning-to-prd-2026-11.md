## 0. 一句话结论

**逆向的产出不是"缺哪些功能"，是"哪些判断已经站不住了"。**

本轮四个方向（UX 结构 / UI 组件规范 / 功能差异 / 业界规范）各自独立跑完，
**方向之间互相推翻的地方比互相印证的地方更有价值**：合计 **24 处**原结论需要更正
（§1），其中 **4 处是"文档在讲与事实相反的话"**，1 处是 `AGENTS.md` 里的绝对句。

而真正**还该补的功能格**，四个方向加起来只有 **6 项**（§4.1），比 PRD 现有的 14 条少得多 ——
这不是"做得差不多了"，是**PRD 把研发成本记成了产品缺口**。

## 2. R13b 的真实现状（纠正交接口径）

**交接时记的是「R13b 未做、规模大」。** 实际已有 **1/3 落地**（`b6e389d59`）：

| 已做 | 未做（见 [r13b 计划](r13b-appearance-presets-2026-11.md) §5） |
|---|---|
| 表面色系预设（default / warm / mist）× 明暗 = **6 组合** | **字号档 / 密度 / 行着色三态 / 应用图标** |

而 RN 侧今天不成立。**它比"字号档没做"更该先修** —— 前者是没做，后者是**说做到了但其实没做到**。

## 3. 逆向的净产出：该补的只有 6 格

四个方向独立收敛到同一个结论：**它有的功能，绝大多数不该补**。判据按 [特征清单](../research/dida365-feature-benchmark.md) 的分类写成六条：

| 码 | 判据 | 例 |
|---|---|---|
| **A** | 主路径断点：缺它当天该干的活干不下去 | 附件、开始时间 |
| **B** | 零件已在、线没接 | 附件区（domain 齐、UI 0 引用） |
| **C** | 它的架构产物，我们的架构让这格不存在 | 重复实例物化、每视图 7 张排序表 |
| **D** | 全家桶／收费墙／垂直场景 | 课程表、检查项级提醒（Pro 卖点） |
| **E** | 补了会变成"更差的滴答" | 团队席位、全局命令面板 |
| **F** | 它做是因为**它服务端要读明文** | 日历订阅（只读镜像撞 op-log 的 LWW） |

**真该补的 6 格**：

| # | 缺什么 | 码 | 现状 |
|---|---|---|---|
| 1 | **真正的「全部任务」平铺** | A | 两端都没有；`all` 这名字已被"收集箱"占用 |
| 2 | **开始时间 + 时间点粒度** | A | `dueDate` 能带时间，UI 只有日期；time blocking 不成立 |
| 3 | **任务模板**（不建实体） | B | `Task` 字段子集 + 子树即可 |
| 4 | **日历显示设置 / 时区归属** | B | `weekStart` 已是模型参数，缺入口 |
| 5 | **快捷键一览 + 自定义** | A | 键位散在 6 个物理位置，无总表 |
| 6 | **批量条的 4 个动作** | A | 现 3 枚（完成/移清单/删除），缺改期·推迟·优先级·标签 |

> ⚠️ 第 6 条**先补 4 个具体动作，不要先造「更多」** —— 造了就等于承认对象层没有预算。

## 4. 建议新增的需求（R15–R19）

编号从 R15 起（R1–R14 已占用）。**每条格式：用户会怎么遇到 / 做什么 / 判据能红 / 它对应哪条账。**
排序是"先修说错的话，再补没做的事"。

### R15 · 加密状态的用户可读性（**最高优先级，它清理 A1–A3**）

| 项 | 内容 |
|---|---|
| **用户会怎么遇到** | 开了同步以为"加密了"，实际默认明文；或开了加密后发现云端 AI 用不了，没人告诉过他 |
| **做什么** | 设置里一页「**谁能看到我的数据**」：显示当前 `payloadMode`、服务端现在能读到什么、开加密后**哪些功能会失效**（托管 AI，`ADR-0013`/`ADR-0054:152` 明写互斥） |
| **判据（能红）** | ① 两种模式各截一图，页面**结论必须不同**（把 `payloadMode` 写死成 `e2ee` ⇒ 页面输出必须变，否则检查无效）；② 该页文案 grep「看不到」「绝对」**0 命中**；③ `readable` 模式必须明示「服务端可读」 |
| **顺带清账** | A1/A2/A3 三条。⚠️ `AGENTS.md` 是规则文件，**规则部分不擅改** —— 建议由产品负责人在 `docs/agents/key-decisions.md` 先登记「E2EE 默认口径已变」，再改 `AGENTS.md:20` |
| **对应差异化** | D6（"你可以让它看不到"） |

### R16 · 自托管「真一键」验收

| 项 | 内容 |
|---|---|
| **用户会怎么遇到** | 想自托管，但要会改配置才能起服务 —— 而自托管的目标用户恰恰是不想运维的人 |
| **现状** | 能自建（已兑现），**"十分钟一键"未兑现**（`P1-20` 仍列 P1） |
| **判据（能红）** | ① 全新机器（无 `.env`、无缓存）从 clone 到「A 端建任务 → B 端读到」，**只允许改一处**（地址）；② 任何一步失败要打印**下一步做什么**，不是堆栈；③ 删掉一个默认值 ⇒ ①必须失败 |
| **对应差异化** | D2 |

### R17 · 数据可携带的**对账**闭环

| 项 | 内容 |
|---|---|
| **用户会怎么遇到** | 「导出备份」导出了什么？还原对不对？只能信。 |
| **现状** | `export-dump.ts` 已含 `opsByEntityType`、墓碑条数、`opLog`，**但那是给工程看的** |
| **判据（能红）** | ① 导出 → 空库还原 → **三个数逐项相等**（实体 / 墓碑 / op）；② 故意删墓碑再还原 ⇒ 必须报「N 条已删数据会被复活」；③ 三个数各有标签，不许只给总数 |
| **为什么是差异化** | 它做不到——它的事实是"行"，删掉的行不存在，回放会**复活已删数据**（这正是我们墓碑设计的反面理由） |
| **对应差异化** | D4 |

### R18 · 保存的筛选器跨端（**这条是修洞，不是追它**）

| 项 | 内容 |
|---|---|
| **用户会怎么遇到** | A 机存了 5 条视图，换 B 机一条都没有 ⇒ 觉得**同步坏了** |
| **现状** | `saved-filters.ts` 存 `localStorage`，文件头自述「v1 本地不同步；不产生 op」 |
| **判据（能红）** | ① A 端存 2 个 → B 端登录 **2 个都在**；② 删一个两端同步消失；③ 注掉 op 写入 ⇒ ①红 |
| **前置** | 🔴 **必须先写 ADR 回答口径冲突（§1.4 D4）**：「保存的筛选」是**用户数据**还是**视图**？`entity-types.ts:15-18` 原则 2 说「视图不建实体」，而 `data-model-parity` §2.7 说它"是用户数据不是视图" |
| **为什么要修** | 现状与「本地优先」叙事直接打架 —— 本地优先是"本地是事实源、联网会同步上去"，不是"本地的东西永远留在本地" |

### R19 · 撤销跨会话 + 未绑定的 ⌘Z

| 项 | 内容 |
|---|---|
| **用户会怎么遇到** | 删错东西，**刷新之后** ⌘Z 没有任何反应 |
| **现状** | 引擎有 `undo()`/`redo()`（真生产代码，`engine.ts:506/511`），**但 web 壳没有任何 ⌘Z 绑定**；撤销只走回执路径（`bulk-undo`、`ProjectsPanel` 的局部 `undo` state）；栈本身是**会话内内存**（`history.ts:6` 自述） |
| **判据（能红）** | ① 删清单 → **刷新** → ⌘Z → 回来；② 批量操作后 ⌘Z ⇒ 必须出现「这一类不支持撤销」的**具名理由**（`HistorySkipReason` 已有三档，直接暴露）；③ 注掉持久化 ⇒ ①红；④ 回放不产生副作用（`hard-constraints` §3.4） |
| **对应差异化** | D4 + D11（撤销 = 反向 op 是我们架构送的，它做不到；**我们只送了一半**） |

## 5. 组件规范：要改的是我们自己的三处，与滴答无关

UI 方向的结论值得单独拎出来，因为它**反直觉**：

> 滴答能教我们的**不是任何一个数**，是「排版有刻度、布局没刻度」这个**形状**，
> 以及「把主力档写成读数」这条**纪律**。

`1083` / `24` / `36` / `6` / `8` / `4` / `167` 这些数**一个都不该抄** ——
它们各自受平台强制（鼠标命中假设）、受它自己的历史包袱影响，或混了圆形值。详见
[业界规范基线](../research/industry-ux-baseline-2026-11.md) §B「不可迁移」与
[P1](../research/ticktick-design-parity.md) §4「明确不可借鉴」。

**三处该改的（全是我们自己的账）**：

| # | 改什么 | 为什么 |
|---|---|---|
| **S1** | 暗色"不许写回 hex"从注释变成**测试臂** | `tokens.css:743-749` 自认「只有注释在管、`check:design` 不扫本文件」。基线现量 0 hex（已干净），但**没有门禁挡回潮** |
| **S2** | 补 `--ht-size-button-height: var(--ht-touch-target-min)`，`.ht-btn` 改读它 | 现在按钮高度**借可访问性下限**（那个下限本身还被写错，见 A4）。两者同值纯属选择，WCAG 一改按钮就被动变胖 |
| **S3** | 圆角按**角色**收敛：弹窗 3 档（24×4 / 16×2 / 12×3）、卡片 2 档、菜单 2 档 → 各归一 | 成因与滴答**相反**：它是没 token，我们是 `2026-11-02` 加了 role token 后**没迁移消费者**（`--ht-radius-xl` 注释自己写「旧档，逐步让位」） |

**另有 D1（阴影注释与规则矛盾）归入 S1 同一批**：它们都是"注释/文档在位、门禁不在位"。
