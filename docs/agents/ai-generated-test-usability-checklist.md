# AI 生成用例可用性清单

AI 生成的用例，进回归前逐条勾。**五条全勾才准进；缺一条打回。**

- [ ] **1. 一次跑通**：在干净检出上 `pnpm -r test` 能过，不依赖本机特有状态、不依赖别的用例先跑过。
- [ ] **2. 有实质断言**：断言验的是真实结果，不是 `expect(x);`（无匹配器）、`expect(true).toBe(true)`（恒真），整份用例不许一件断言都没有。
- [ ] **3. 覆盖至少一个负例**：至少一条用例覆盖失败 / 边界 / 非法输入（断言它会抛错或返回约定值），不留"只测正常流"。
- [ ] **4. 无跨用例顺序依赖**：用例之间不靠共享可变状态串起来，不用 `.only` 让套件不隔离；每条用例单独跑也应绿。
- [ ] **5. 无硬编码环境值**：不写死本机绝对路径、密钥 / token、账号 ID、带口令的连接串；这些一律走配置或环境注入。

## 和机械校验的关系

- **第 2、4、5 条**有机械判据：`pnpm check:ai-case-usability` 对**带 `// @ai-generated-case` 标记**的用例逐条判 `EMPTY_ASSERTION` / `ORDER_DEPENDENCY` / `HARDCODED_ENV`。
- **第 1、3 条**要读意图（能不能一次跑通、有没有负例），没有可靠机械判据，靠检视者按上面清单勾。
- 机械校验判的是"声明过的 AI 用例"：AI 生成的用例**首行写 `// @ai-generated-case`**，否则不进射程（视同未检视）。
