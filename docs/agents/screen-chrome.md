# 屏幕外壳（chrome）三档

一屏长什么样，先由它**是什么**决定，再由作者决定。本文件就是那张表。

判据：`pnpm check:nav-chrome`（顶栏动作预算）+ `Screen` 的 `chrome` 参数类型。

---

## 1. 三档

| 档 | 用在哪 | 左右边距 | 顶栏 | 低频动作 |
|---|---|---|---|---|
| `page`（默认） | 内容页、表单页、设置页、详情页 | 16dp gutter | 1–3 枚**高频**动作 | 进「更多」菜单 |
| `board` | 看板：四象限、时间线、日历 | **0（内容铺满）** | 只留全局搜索 + 「更多」 | 进「更多」菜单 |
| `immersive` | 全屏消费内容：专注计时、阅读 | 0 | 默认不画 | 靠返回手势退出 |

`immersive` 目前**没有实现**，只在 `Screen` 的类型里占位 —— 加第四档之前先用它。

---

## 2. 为什么它必须是一档、不是一个 boolean

`bleed` 这类样式开关只回答"要不要边距"，回答不了"顶栏该放几枚按钮"。
而这两件事在真机上是**同一个观感问题**：边距没收、按钮还堆着，屏幕照样脏。

三档把"边距 / 顶栏密度 / 低频动作去哪"绑成一个决定 ——
选错档是一次可见的结构错，而不是三次风格分歧。

---

## 3. 顶栏动作的判据

一屏顶栏最多 **3 枚**，且必须全部通过这一句：

> 这一枚的动作，在这屏出现的**每一次**都可能用吗？

- 搜索、视图切换、新建：是 → 留在顶栏。
- 手动同步、排序、日期显示：否 → 进「更多」菜单（`board` 档尤其严格）。

`TasksScreen` 的手动「同步」按这一条从顶栏撤下、落进「⋯」菜单；
四象限/时间线不再套 16dp gutter（`chrome="board"`）。

---

## 4. 落地方式

```tsx
<Screen title={t('…')} chrome={view === 'list' ? 'page' : 'board'}>
```

`Screen` 只读档位，不读像素 —— 加边距、改顶栏密度的细节在 `apps/mobile/src/ui/kit.tsx`。
