# ADR-0042：玻璃材质的边界 —— 只给悬浮功能层与导航，内容面永远实色

> 状态：**已接受**
> 日期：2026-10-01
> 依据：[多端 UI 审美方向与设计系统覆盖度审计](../research/ui-aesthetic-and-design-system-coverage-audit.md)（玻璃拟态专项，含 9 张截图视觉证据与逐面裁决表 §3.4）
> 产品负责人：2026-10-01 拍板（含「搜索浮层属悬浮功能层」的明确补充）

## 1. 要裁决的问题

产品方向上提出「各种东西都希望做成玻璃拟态」。`tokens.css` §3d 的材质 token
（`blur.*` / `material.*`）已注册并生成到四端，落地页导航已是正确的参考实现——
但「全部玻璃化」与既有规范（MASTER.md §2：内容面扁平）正面冲突，必须裁决边界。

审计给出的关键事实（详见审计报告 §3）：

1. **应用内的玻璃目前是「隐形的」**：搜索浮层技术上加了 `blur(20px)+saturate(180%)`，
   但 72% 白 tint 盖在浅色列表上，截图观感是一张实色白卡。**玻璃是关系，不是属性**——
   它需要背后有可折射的内容（滚动的彩色内容、色块、深色面）。
2. 全域玻璃有四重独立否决项：可读性（文字透叠，设置 sheet 88% 事故是预演）、
   性能（滚动列表上的 backdrop-filter 合成开销）、「UI 单源」（五端 blur 能力差异撕开
   ADR-0036 的共享承诺）、GTK4 无 backdrop blur（多端一致性直接破产）。

## 2. 选项

| 选项 | 优点 | 缺点 |
|---|---|---|
| A. 全部玻璃化（内容面也做） | 视觉激进、短期内「显得高级」 | 四重否决项全部命中；Apple 自己也不这么做 |
| **B. 材质系统：玻璃只给悬浮功能层与导航，内容面永远实色** | 与 Apple HIG / Win11 材质纪律同构；与既有 MASTER.md §2 边界一致；token 已备 | 需要把「端能力协商」封装进共享层，防止 Platform.OS 分叉散布 |
| C. 维持现状（只有搜索浮层一处玻璃） | 零成本 | 玻璃配方隐形等于没有；移动端 tab 栏存在感问题无解 |

**选了 B。** 它不是对 A 的折中，是把「拟态」翻译成正确的对象：**层级语言，不是风格皮肤**。

## 3. 决策（六条）

1. **玻璃只给悬浮功能层与导航；内容面（任务行/卡片/表单/日历格/图表）永远实色。**
   判据沿用 MASTER.md §2：「内容会从它下面滚过去吗」——滚 → 材质是它表达层级的手段；
   不滚 → 玻璃是浪费的。
2. **材质跟着浮层本体走，不跟着入口走。** 搜索浮层是典型悬浮功能层，用玻璃——
   它的入口在侧栏不影响这个判定。
3. **模态（登录/隐私同意/同步设置/冲突/回收站确认）维持 scrim + 实卡**：模态的任务是
   聚焦，玻璃漏注意力，方向相反。
4. **设置 sheet 维持 95% color-mix 现状**（88% 有文字透叠事故前科，
   决策记录在 `apps/web/src/styles/app.css:585-594`）。
5. **Linux（GTK4）放弃玻璃**（无 backdrop blur 能力）；**移动端不引入 blur 库**，
   RN 端用「高不透明 tint + 边缘线」伪材质，真 blur 的依赖评估另立决策
   （须过 AGENTS §3.1 可维护性 + §3.2 许可证两道门）。
6. 逐面裁决以审计报告 **§3.4 裁决表**为准（玻璃候选：tab/导航、账号菜单、通知面板、
   各下拉、搜索浮层调配方；维持：模态、设置 sheet、toast 可选；禁做：rail/侧栏、FAB、
   全部内容面；窗口级材质属壳改造，另立 spike）。

## 4. 约束（落地时不可违反）

- **端能力协商只允许存在于 MaterialSurface 抽象内部**（扩展
  `packages/ui/src/search/panel-surface.ts`），业务组件不得散写 `Platform.OS` 分叉。
- 玻璃面的对比度按「tint 合成在最坏背景上」实算 ≥4.5:1（正文），进
  `packages/design-system` 的测试矩阵——静态底色对（AA_PAIRS）覆盖不了半透明面。
- `prefers-reduced-transparency` 必须有降级（材质退为实色），与
  `prefers-reduced-motion` 同款策略：压值不删属性。
- 玻璃层入场用已定义的 `motion.*` spring token；**没有动效的玻璃不交付**
  （静态玻璃只是更贵的实色）。
- 暗色玻璃用「深蓝提升」（`#0d1526` 家族），不是亮色反相（tokens.css §3d 已有，沿用）。

## 5. 后果

- MASTER.md §2 的边界**不变**，本 ADR 是它的决策记录背书；§12 材质两硬规则继续有效。
- web 是第一战场（零新依赖）；窗口级材质（macOS vibrancy / Windows Mica）与移动端
  blur 评估是后续独立 spike，不在本决策的落地范围内。
- 本 ADR 不改变 ADR-0036（UI 单源）与 ADR-0037（桌面退 WebView）的任何结论；
  MaterialSurface 抽象恰恰是对 ADR-0036 的保护。
