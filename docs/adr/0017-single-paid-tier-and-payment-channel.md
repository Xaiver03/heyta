# ADR-0017：唯一付费档的价格，与「复用同公司晓黎支付中心」的支付通道

> 状态：**已接受**
> 日期：2026-09-27
> 取代：无（承接 [subscription-boundary.md](../plans/subscription-boundary.md) §0 的「收费的是服务器」，**关闭**它 §3 一直留着的「价格未定」）

## 1. 背景与约束

### 1.1 「收什么」早就定了，「收多少」一直没有

[`subscription-boundary.md`](../plans/subscription-boundary.md) §0（PM 定稿）已经把**收费对象**
解决了：收的是「我们替你运维那台同步中继」，**不是功能** —— 因为服务端只中转密文
（E2EE by design），任何按功能分档的定价表**我们根本没有能力执行**。

但同一个文件 §3 明确把价格留白：

> **价格是否就是 ¥139** —— 本文件用 ¥139 只是为了**对齐对标**，它出现在文档里是
> **约束可行性**（见 ai-strategy §7.2.1），不是售价承诺。

[`ai-strategy.md`](../plans/ai-strategy.md) §7.2.1 也写了同一句话：
「本文的 ¥139 / 年 是**对标产品的现行价**，不是我们的定价结论」。
那个数字是**滴答清单 Premium** 的价（证据：`../research/ai-competitive-and-architecture.md` §1.5
「高级会员 ￥139/年」）。

而代码里已经有一个**占位值**：`server/src/billing/wechat.adapter.ts` 的
`WECHAT_DEFAULT_PRICES.annual = 13_900`，注释写的是「⚠️ **暂定值**」。
**也就是说：仓库里没有任何一处定义过 heyta 自己的价格。**
（SSOS 与 AIstudy 的价格存在各自的数据库里、由后台配（`price_monthly_cents` /
`price_annual_cents`），仓库里拿不到可复用的数字 —— 所以「复用一套」指的是**通道**，不是价格。）

### 1.2 三个硬约束

| 约束 | 来源 | 它排除了什么 |
|---|---|---|
| **我们看不见明文 → 按功能分档执行不了** | [`subscription-boundary.md`](../plans/subscription-boundary.md) §0.1 | 多档位功能表 |
| **国内第一阶段没有自动续费**：周期扣款仅企业账号且注册资本 ≥100 万 | [`subscription-provider-selection.md`](../plans/subscription-provider-selection.md) §1 | 月付自动订阅 |
| **海外通道要用户本人过 KYC**：Paddle 接受中国大陆卖家开户**只有政策文本**，实操放行未验证 | 同上 §7.1 | 现在就把海外收款做成「已可用」 |

### 1.3 用户决定（2026-09-27）

1. **只做一个付费档**；
2. 大陆 **¥99 / 年**，海外 **$49 / 年**；自建**永久免费**；
3. **复用同公司的支付配置**（SSOS / AIstudy 那套），不新起第二套支付后端。

## 2. 选项

| 选项 | 优点 | 缺点 | 关键证据 |
|---|---|---|---|
| **A. 沿用对标价 ¥139/年** | 代码零改动（`13_900` 已就位）；「比滴答便宜」的论证弱但成立 | 沿用对标价等于把「我们要取代它」变成「我们跟它一个价」—— 而 README 的立身之本正是「不再为高昂的订阅费买单」 | [`subscription-boundary.md`](../plans/subscription-boundary.md) 开头引的 README 原句 |
| **B. 单档 ¥99/年 + $49/年** ✅ | 一句话讲得清（「一年不到一百块」）；仍高于支付宝个人无执照的单笔 ¥50 上限之外的**普通商户直连**路线的门槛，不改变选型结论 | 要改代码价目表 + 法务文本 + 4 份文档；ARPU 低于对标 | 用户 2026-09-27 决定 |
| **C. 多档位（按功能 / 按设备数）** | 收入上限高 | 🔴 **执行不了**：服务端看不到明文，按功能卡不住；按设备数卡则要新增服务端计数面 | [`subscription-boundary.md`](../plans/subscription-boundary.md) §0.1 |
| **D. 加月付档** | 决策门槛低 | 微信一次性支付**没有订阅对象**，月付 = 12 倍订单/客服面换同样的年收入；且 §1.2 已确认国内第一阶段做不到自动续费 | [`subscription-wechat-handoff.md`](../plans/subscription-wechat-handoff.md) §3.1 |
| **E. 第三方聚合支付（虎皮椒 / XorPay / 蓝兔 …）** | 接入快 | **二清风险**；对账多一层黑箱 | [`subscription-boundary.md`](../plans/subscription-boundary.md) §6.6 |
| **F. 自建第二套支付后端（惠付通/直连微信做全套）** | 不依赖别处的可用性 | 商户凭据、证书轮换、回调验签、履约通知全部要再养一套；**公司已经有一个** | 用户 2026-09-27 指令；姊妹项目 AIstudy 的 `docs/XIAOLI_PAYMENT_CENTER.md`（⚠️ **跨仓库，本仓库内没有这个文件**，所以这里写路径而不是链接 —— 本仓库的文档检查器只认仓库内的相对链接） |

## 3. 结论

### 3.1 一个档，两个币种，一条免费出路

| | 自建 | 官方托管同步 |
|---|---|---|
| 大陆 | **¥99 / 年** | 同左 |
| 海外 | **$49 / 年** | 同左 |
| 计费方式 | 不涉及（**不校验**） | **一次性年付**（微信支付 Native 扫码 / 海外待定） |
| 含什么 | 全部功能 | 全部功能 + 我们替你运维那台中继 |

**免费这条路是完整的**（承接 §0：「免费版 = 自托管，不是官方托管的阉割版」）。

### 3.2 价格只允许存在于「两层 + 一道门禁」

同一个数字以前出现在 5 个文件里（代码、法务文本、4 份文档），**没有任何东西保证它们一致**。
本 ADR 定下三层，并把一致性变成**可失败的门禁**：

| 层 | 唯一事实源 | 谁读它 |
|---|---|---|
| **实际收多少** | `server/src/billing/wechat.adapter.ts` 的 `WECHAT_DEFAULT_PRICES` | 服务端下单 + 回调金额校验 |
| **对外怎么说** | `packages/i18n` 的 `landing.pricing.*` 词条 | 落地页 |
| **一句话的价格表** | [`../reference/pricing-and-entitlements.md`](../reference/pricing-and-entitlements.md) 里的机器可读块 | 人 + `scripts/check-pricing-consistency.mjs` |

🔴 `scripts/check-pricing-consistency.mjs` 断言三者一致。**改价时只改一处会红。**
（这条门禁的价值是具体的：落地页说 ¥99 而价目表是 ¥139，就是**虚假宣传**；
反过来价目表改了而页面没改，用户看到的价格不是他要付的价格。）

### 3.3 支付通道：复用晓黎支付中心，不再自建

heyta 作为**又一个 client**接入公司已有的「晓黎支付中心」（跑在 FinLaw 上的
`xiaoli-platform-core`），与 AIstudy 同一形状：

```
heyta 服务端 ──(内部签名请求)──▶ 晓黎支付中心 ──▶ 微信支付
                                  ▲ 商户号/证书/APIv3 密钥/回调验签/履约通知都在这里
```

**为什么这条推翻了 §6.6 的「微信直连」**：§6.6 否决的是**第三方聚合支付**
（虎皮椒 / XorPay / 蓝兔），理由是正确的 —— **二清风险**。
但晓黎支付中心是**同一家公司自己运维的**统一支付中心，不是第三方收单，
**二清风险不适用**，而「商户凭据只养一份」的收益是真的。

## 4. 后果

### 正面

- 价格终于是**一个决定**，不再是一个占位符；README 的定位论证（¥99 明显低于对标 ¥139）成立。
- 支付的敏感物（商户私钥、APIv3 密钥、平台证书轮换）**只在支付中心一处**，
  heyta 不再需要自己保管与轮换。
- 一致性从「靠人记得改」变成「门禁会红」。

### 负面 / 需要接受的成本

- 🔴 **`server/src/billing/wechat.adapter.ts` 的地位要重新界定。** 它是**已经写完且有测试**的
  微信直连实现（26 KB，`node:crypto` 手写 RSA-SHA256 签名 / AES-256-GCM 解密，零依赖）。
  按 §3.3，它要么降级成「支付中心的一个下游实现」，要么被弃用。
  **本 ADR 不删除它** —— 在支付中心的 heyta client 接完线并有过测试之前，
  它是**唯一被验证过的微信路径**；先删掉会让我们同时失去价格校验与履约的那条链。
  这给未来的读者留一个明确的问题：「这份 adapter 还有用吗？」
- **海外通道现在是 0**：页面可以写 $49/年（用户已定），但**买不到**，
  所以页面必须**如实标注**，不能给一个点了没反应的按钮。
- **法务文本的价格必须跟着改**：`server/legal/terms-of-service.heyta.md` 写的是 ¥139/年
  （该文件本身仍是**未经法务复核的草稿**）。

### 需要靠规范 / 门禁兜住的

- `scripts/check-pricing-consistency.mjs`（本 ADR 引入）。
- 加**第二个不同金额的 SKU 之前**，必须先改回调校验：现在的金额校验是
  「付的金额是价目表里的**某一个**」，一旦有多个 SKU，必须改成按 `out_trade_no`
  里编入的 priceId 校验 —— 代码注释里已经写明这个洞的边界（`wechat.adapter.ts` §6.1）。

## 5. 未核实项

1. **Paddle 是否真的放行中国大陆卖家** —— 只有**用户本人**用中国身份注册到
   Account Verification 才能回答。这一步决定海外通道按谁写。
2. **$49 / 年在美国区是否站得住** —— MoR 费率（PayPal 中国大陆电汇提款 **$35/笔**，
   `subscription-provider-selection.md` §1）在早期单量下会吃掉大部分毛利。
   本 ADR 记录的是**定价意图**，不是经济性验证。
3. **晓黎支付中心是否支持给 heyta 开一个新 client id 与 CNY 账本** —— 本次**没有核实**，
   AIstudy 的契约文档只记录了 `XIAOLI_PAYMENT_CLIENT_ID=learning` 这一个。
   在接完线之前，「复用通道」是一个**方向**，不是已打通的事实。
4. **工信部 292 号令**对「收费的托管同步服务」的定性 —— 需中国律师判断。
5. **退款政策** —— 仍未写（`subscription-boundary.md` §3 也留着它）。
