# 架构决策记录（ADR）

一份 ADR = **一个决策**，写清背景、选项、结论、后果。它是**不可变的历史记录**。

---

## 什么时候该写 ADR

写 ADR 的唯一判据：**这个决定以后会被问"当初为什么这么选"，而答案不写在代码里。**

典型触发：

- 选了某个技术/组件/协议，且**换成另一个的代价很大**（数据格式、线协议、ORM、许可证）
- 明确**否决**了某个看起来更显然的方案（后人一定会问"为什么不用 X"）
- 定下了一条**约束所有人的规则**（比如"迁移文件必须单语句"）
- 做了不可逆或难回滚的取舍

## 不该写 ADR 的情况

- 一次调研的过程与证据 → 那是 [`docs/research/`](../research/)
- 待办、进度、排期 → 那是 [`docs/plans/`](../plans/)
- 怎么操作某件事 → 那是 [`docs/runbooks/`](../runbooks/)
- 能用代码/测试表达清楚的事 → 写代码和测试

## 规则

1. **不可变**。已接受的 ADR 不再修改结论。结论变了就**新写一份**，并在两份里互相标注取代关系。
   🔴 **"不可变"拦的是改写结论，不是封锁事实** —— 详见下面第 1a 条。
### 1a. 「勘误段」是被允许的，但**边界是硬的**（2026-09-28 补写）

这条规则本身是一次**追认**：ADR-0018 §6 与 ADR-0021 §6 在 2026-09-28 被加了勘误段，
而当时本文件只写着"不可变、只能新写一份"，且 `docs/README.md` 里"结论有变时新增勘误"
那条**只适用于 `research/` 层**。也就是说——**机制先被用了，规则后补**。
补它的理由不是"让既成事实合法"，而是：那两段说的都是**"决定照做了没有"**，
而**让一句已知为假的话留在不可变的 ADR 里，比违反不可变更坏** ——
读者会照着它做决定（ADR-0018 §4.1 写着 `expireStaleOrders`「必须作为定时任务运行」，
而它**零调用者**）。

**边界（必须逐条满足，否则不许写勘误段）：**

| # | 判据 | 说明 |
|---|---|---|
| **1** | 勘误段**只能追加**，且**不得修改正文任何一个字** | 正文是当时决策的完整记录，改它就毁掉了"当初为什么这么选" |
| **2** | 勘误段只能写**三类事实**：① 正文里某个断言**被实测证伪**；② 该决定的**落地进度**；③ 它**已被哪份新 ADR 取代**（且那份新 ADR 必须存在） | 进度类的详版放 `plans/`，勘误段只留**指路**一句话 |
| **3** | 🔴 **决不允许用勘误段悄悄改结论** | 结论变了就是**新写一份 ADR** —— 那正是第 1 条要拦的。判据：勘误段里若出现"现在改成……"，就说明写错了地方 |
| **4** | 勘误段必须**写明日期**与**触发它的实测**（命令/文件/行号） | 没有证据的勘误段与原文一样不可信 |
| **5** | 勘误段加在**文末**，标题形如 `## N. 勘误（YYYY-MM-DD）`，编号接在最后一节之后 | 便于一眼看出"哪些是后来加的" |

⚠️ 与 `research/` 层的勘误**不是一件事**：那一层是"调研结论有变"（`docs/README.md` 的
目录表），对象是**证据**；这一层是"ADR 正文里的某个断言与现状不符"，对象是**决策记录**。
两者都叫勘误，但**判据不同**，别互相引用规则。

2. **编号只增不减**，从 `0001` 连续递增，不跳号、不复用。

   🔴 **定号之前先跑一次现量**（不是"我记得下一个是 00NN"）：

   ```bash
   pnpm check:adr-numbering
   ```

   它挡的是 2026-10-05 真实发生的那一种：**两条并行会话在同一天各自占用了 `0053`**
   （一枚退款域收窄、一枚端点地址类别）。那个形状里没有任何一层会失败 ——
   文件名不同 ⇒ git 不报冲突；每条 markdown 链接各指各的 ⇒ 死链检查也不报。
   坏的只有**正文里裸写的 `ADR-0053 §5 第 11 条`**：它从此有两种读法，
   而挑错那一种不会让任何东西红。当时的处理是后来者改号（→ `0056`）+ 补这道门禁。
   ⚠️ 它现在**不在 `pnpm check` 链里**：`package.json` 里 `check` 那一行正被另一条会话的
   未提交改动占着（同一行，无法按 hunk 分开暂存），此刻并进去会连带提交别人的那半 ——
   详见 `scripts/check-gate-wiring.mjs` 允许表里那条登记的**摘除条件**。
   ⇒ **上面那一趟就是它的载体**，别指望提交时会替你跑。
3. **一份一个决策**。想写两件事就写两份 ADR。
4. **必须列出被否决的选项**及否决理由 —— 这是 ADR 最有价值的部分，代码里永远看不到。
5. **必须给证据**。引用文件路径、实测数据、官方文档链接，不要凭印象。
6. 状态变化只能走 `待确认 → 已接受 → 已取代/已废弃`，不允许回头。

## 模板

```markdown
# ADR-NNNN：<一句话说明决策是什么>

> 状态：**待确认**
> 日期：YYYY-MM-DD
> 取代：<无 / ADR-XXXX>（如适用）

## 1. 背景与约束

（什么情况逼着我们做决定？有哪些**硬约束**在？列清楚，因为结论由约束推导。）

## 2. 选项

| 选项 | 优点 | 缺点 | 关键证据 |
|---|---|---|---|
| A | | | |
| B | | | |

## 3. 结论

（选了哪个，**为什么**。要能回答"为什么不选看起来更显然的那个"。）

## 4. 后果

（接受这个决策意味着什么？哪些事以后更难做？哪些约束需要靠规范/工具来兜住？）

## 5. 未核实项

（列出你**没能验证**的关键假设。不要藏起来 —— 这比假装确定有害得多。）
```
