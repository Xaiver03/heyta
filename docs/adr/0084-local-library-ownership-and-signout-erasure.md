# ADR-0084：本机库归属唯一账号，退出登录即销毁本机库

- **状态**：已接受（2026-11-06，A 包开工时拍板）
- **日期**：2026-11-06
- **相关**：[ADR-0003](0003-multi-platform-strategy.md)（多端与宿主边界）、[ADR-0048](0048-deletion-four-states-and-the-no-physical-erase-boundary.md)（删除的层级与实话）、
  [ADR-0063](0063-email-rebinding-and-per-session-revocation.md)（退出登录必须撤销服务端那一枚）
- **上游需求**：[产品需求对齐清单](../plans/ticktick-parity-prd-2026-11.md) R1

---

## 一、问题

本地优先 + 端到端加密的产品，在一台共用电脑上换账号时：

- 三个壳的库名写死（`heyta.sqlite` / IndexedDB `heyta`），**op-log 里没有账号字段**；
- 退出登录只清凭据、vault 会话与小组件，**op-log 一个字节都不动**；
- 结果是「上一个账号的任务还在本机侧栏里」，而界面不会报任何错。

这不是缺功能，是**信任断崖**：E2EE 的承诺是「服务端看不到」，用户据此认为
「退出后这台机器上也不该有」。而对本地优先的质疑恰好相反 —— 数据在本地，
所以「本地属于谁」必须能被回答。

## 二、选项

| 方案 | 形状 | 代价 | 致命问题 |
|---|---|---|---|
| **A. 一库一账号 + 登出销毁** | 库记一个归属；登出清库；归属不符拒绝并给清除出口 | 小 | 登出后本地为空，切回需从服务端回放 |
| B. 单库 + `accountId` 分区键 | op 与实体都带 `accountId`，每条读路径过滤 | 大 | **漏一处就跨账号可见，且不报错**；与「一个意图 = 一条 op」并存要改 reducer 的选版规则 |
| C. 每账号一个库文件 | 库名带账号，登出只关闭不删 | 中 | 上一个账号的**明文仍留在磁盘上** —— 正是本需求要断的那件事 |

## 三、决策

**采用 A。**

1. **库归属**：第一次出现带 `accountId` 的认证会话时，把 `{accountId, serverOrigin, boundAt}`
   写进 `STORES.META` 的 `LOCAL_LIBRARY_OWNER`。此后再出现**不同**的 `accountId` ⇒
   `LocalLibraryOwnedByAnotherAccountError`，写路径与同步都 fail closed。
2. **匿名库可被认领一次**：没有归属的库（纯本地使用）在第一次登录时归该账号；
   这之后它不再是「这台设备的」，而是「这个账号的」。
3. **退出登录 = 销毁本机库**。顺序：先算「有没有东西还没上传」→ 有待上传则**必须**经用户确认 →
   `eraseLocalData()`（宿主自己的销毁器）→ 凭据清理 → 宿主重开一份空库。
   **销毁失败要如实说**（`containerRemoved: false` 逐类报告），不许说成"已清除"。
4. **归属不符的出口只有一条**：清除本机库，然后以新账号重新开始。
   不给「保留两个账号的数据」这种选项 —— 那需要 B 方案的全部代价，而收益只有极少数场景。

## 四、后果

**接受的代价**

- 登出后本地没有数据：切回同一账号要等一次服务端回放。这是**有意的**，与 ADR-0048
  「删除的层级」同一条口径：说过的话要能兑现。
- 离线且未同步时登出会丢改动 ⇒ 所以第 3 条的确认是**硬前置**，不是提示。
- 匿名库被认领后，原本「这台设备上的本地数据」变成「该账号的数据」，可能被同步出去。
  这与用户点「登录」时的预期一致（登录就是要同步）。

**明确不做**

- 不做分区键（B）：它把「隔离」变成每条查询的责任，而漏掉的那条不会红。
- 不做每账号库文件（C）：它解决"切换方便"，不解决"上一账号的明文还在盘上"。
- 不加密整个本地库：本地加密是另一条线（ADR-0080 的载荷加密只管**上传**载荷），
  把它塞进本 ADR 会让两步互相等。

## 五、判据

| 层 | 判据 |
|---|---|
| 存储 | 登出销毁后 `countAllOps() === 0`，且物化状态里查不到原账号任何 id（**不是界面不显示**） |
| 共享层 | `claimLibraryOwner` 对同账号返回 `same`、异账号返回 `mismatch`；`assertLibraryOwner` 在 `mismatch` 时抛可判别错误 |
| 写路径 | 归属不符时 `dispatch` / `sync` 都拒绝，且错误里带**当前** owner（界面能说清"属于谁"） |
| 销毁前置 | `pendingUpload > 0` ⇒ `planLibraryPurge()` 返回 `requiresConfirmation: true` 与条数 |
| 版本 | `CURRENT_SCHEMA_VERSION` **不变**（META 加键不是 schema 变更） |

**这些判据怎么才会红**：把 `assertLibraryOwner` 注掉 ⇒ 跨账号单测必须失败；
把登出编排里的 `eraseLocalData()` 注掉 ⇒「库为空」断言必须失败。
读数记在 [A 包计划](../plans/package-a-data-trust-2026-11.md) §5。

## 六、残余

- 销毁器由宿主注册；**没注册时登出不做假动作**：返回 `no-eraser` 并把它当失败报出来，
  而不是「清过了」。
- 登出后服务端令牌的撤销仍是 best-effort（ADR-0063 的既有边界），
  本 ADR 不改变它；但**数据在不在本机**不再取决于网络是否成功。
