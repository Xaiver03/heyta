# ADR-0058：自动收集的提交许可与异构任务批

> 状态：**已接受（技术方案，2026-10-07）**。实施状态见[计划](../plans/inbound-automation.md)，线形状见[协议](../reference/inbound-automation-protocol.md)。本 ADR 不批准价格、套餐和保留期，也不声明功能上线。

## 背景

外部一条事件可提取多条不同任务。现有 BATCH 把同一 payload 施加给多个实体，现有 dispatch 每次生成新 op。服务端领取租约不能与客户端 SQLite/IndexedDB 事务原子提交；“本地已写但未上传”时重新转派会创建第二个 op。认证同步禁止 B 冒充 A 上传其操作。依据与反例见[复审](../research/inbound-automation-review.md)。

## 决策

1. 采用不可重复的提交许可：许可前租约可转派；许可后 owner 与 opId 不变。许可是自动化用户意图的授权线性化点。暂停只阻止新许可；已授权在途事件会继续恢复，界面明确披露。没有原设备或可信同步证据时进入结果不确定，不再次创建。
2. 新增 `BATCH/TASK` 的版本化 `heytaTaskBatch: 1` payload，包含 1–50 项独立字段与共同来源 receipt。一批严格校验、一次 dispatch、一次 append；每项共用原 op 的时钟、timestamp、clientId 和 opId。批语义不通过循环动作实现，不修改 vendored sync-core，不 bump CURRENT_SCHEMA_VERSION。
3. Task 的来源字段可选；旧数据默认没有来源。源码消费者先部署支持该 marker，再开放接收。未知 marker 拒绝而非按普通字段物化。普通多项共享 payload 的 BATCH 保持既有含义。
4. 去重和恢复不能只依赖可删除的任务可见状态：中心保留事件身份，本地保留原 op/checkpoint 与来源证据。稳定 ID 只是协议组成部分，不独自宣称分布式幂等。
5. 远端回放是纯数据变换，不重新校验当时目标清单、不触发 AI、同步或其它业务动作。创建时的授权和清单校验由 app-host 统一完成；回放按原因果版本合并，保留用户后续编辑与墓碑。

## 取舍

不选择租约过期即重建、仅靠固定 taskId 覆盖、或者冒充原设备补传。首版选择最多一次创建，**不承诺原提交设备永久丢失后仍可自动完成**。未来若需要许可后的无条件接管，应另立加密提交恢复协议并验证认证、并发和成本边界。

本 ADR 不改变普通手工任务的离线写入能力；只对自动化事件授予一次在线提交许可。权益、密钥、日期语义、模型计量与全端验证仍需按计划完成，批 reducer 单独通过不能成为开放功能的依据。
