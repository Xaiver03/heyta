# ADR-0014：记忆偏好层的两个闸门 —— 主开关与纠正持久化

- **状态**：已接受（2026-09-26）

- **落地**：`packages/domain/src/preferences.ts`、[`docs/plans/ai-memory-system.md`](../plans/ai-memory-system.md)

## 1. 背景：产品负责人拍板两件事

[`ai-memory-system.md`](../plans/ai-memory-system.md) §10 留了两个待拍板项。
产品负责人答复：

> 「愿意动这个 Schema 的没关系。然后呢，需要有个总开关，
> 没问题，需要有个总开关，**不然的话用户可能担心自己的隐私的问题**。」

于是本 ADR 把两个决策固定下来。**这不是我在两个方案里选一个**，
而是产品负责人对"要不要为用户隐私让路"的直接表态。

---

## 2. 决策一：**记忆主开关**，默认关闭，且 fail-closed

### 2.1 决策内容

| 项 | 值 |
|---|---|
| 默认状态 | **关闭** |
| 关闭时的行为 | **零推断、零偏好、零出境内容** |
| 闸门位置 | `inferPreferences()` 的**入口**，不是调用方 |
| 参数性质 | `memoryEnabled` 是**必填**字段，**不是可选** |

### 2.2 🔴 为什么必须是**必填**，不能是可选

本项目已经踩过这个坑一次，而且那次是 **fail open**：

> `createLocalApiHost(ctx, actions, options)` 里，
> `isReadable` 曾经写成 `options.isReadable ?? (() => true)` ——
> 于是"忘了传"等于"全部可读"。**闸门形同虚设，而代码看上去是对的。**

同理，如果 `memoryEnabled` 可选、默认 `true`，那么任何一个新的调用点
（新平台、新界面、别人写的集成）只要忘了传，就会**默认推断用户偏好**。
而隐私开关**绝不允许 fail open**。

所以：**没有默认值，传错就编译不过。**

### 2.3 关闭时返回**空集**，而不是"低置信度"

关闭状态下返回的 `PreferenceSet` 里：

- 五个偏好字段**全是 `null`**
- `withheld` 也是**空的** —— 关闭时系统**不解释自己**，
  因为连"我还需要 N 次专注"都是一种已读数据的表现

这条由测试直接钉住：传入一份**明确有信号**的数据集，
只要开关是关的，结果必须与 `emptyPreferenceSet()` 完全相等。

### 2.4 与出境披露的关系

偏好摘要会进入发往模型的 prompt，因此**必须出现在出境披露里**
（复用既有的 `buildDisclosure()` 路径，见 ADR-0010 §3.14：
披露是三维的 —— 发给谁 / 发什么 / 留多久）。

⚠️ 注意区分：**偏好推断本身不出境**（在本机从 op-log 算），
出境的是**被选中的那一条偏好摘要**。所以披露要写的是后者。

✅ **已核实：披露层不需要改代码。** `EgressDisclosure.fields` 的类型是
`readonly string[]`（`packages/ai/src/egress.ts:67`），
`buildDisclosure` 原样透传（同文件 :89）。所以"把偏好摘要写进披露"
只是 M3 接线时多传一个字段名，**不是**一个待实现的功能缺口。

> 之所以要专门核实并写下来：本仓库反复出现过「以为要改、其实已有」
> 和「以为已有、其实没人调用」两种错。**断言之前先看类型和调用点。**

## 3. 决策二：用户的**纠正**写入 op-log

### 3.1 决策内容

偏好是**推断**，一定会错。用户需要能纠正它。而纠正信息
**无法从 op-log 推导出来** —— op-log 里没有"用户认为这个推断是错的"这条事实。

所以纠正**必须被显式记录**，产品负责人同意为此动 schema。

### 3.2 🔴 关键发现：**不需要 bump `CURRENT_SCHEMA_VERSION`**

这是本决策里最省事、也最容易搞错的一点。

`applyOperation` 对**未建模的 `entityType` 静默忽略**（不抛异常）。
因此新增一个 `PREFERENCE_CORRECTION` 实体类型是**纯可加性的**：

| 客户端 | 行为 |
|---|---|
| 新客户端 | 读到纠正 → 覆盖推断值 |
| 旧客户端 | **静默忽略**，不崩、不污染游标；显示**未纠正**的推断值 |

旧客户端的降级是可接受的：它显示的是一个**仍然诚实的推断**，
只是没应用用户的覆盖。**没有任何数据被破坏，也没有客户端被栅栏住。**

对照 [`schema-version.ts`](../../packages/shared-schema/src/schema-version.ts) 的政策：

> 「若旧客户端能未迁移地应用，就应该用 payload 标记（envelope 模式）
> 向前兼容，**而不是 bump 版本号**。只有"必须把旧客户端硬栅栏在外面"的语义变更，
> 才值得付出 bump 的代价。」

本变更是**旧客户端能未迁移地应用**的典型 → **不 bump**。
`CURRENT_SCHEMA_VERSION` 保持原值。

### 3.3 推断结果**不持久化**

| 对象 | 存哪 | 为什么 |
|---|---|---|
| **推断结果** | **不存**，每次从 op-log 重算 | 纯函数 → 确定性可重建 → 零漂移、零 schema 改动 |
| **用户纠正** | op-log（新实体类型） | 无法推导，必须显式记录；且要跨设备同步 |

**推断结果不落盘**是 ADR-0005 的直接要求：落了盘它就是第二份
**会漂移**的语义摘要，而漂移正是 ADR-0008 记录过的那类故障。

## 4. 后果

### 4.1 好的

- 隐私开关**无法被误默认打开**（编译期保证，不是靠自觉）
- 偏好层零新增依赖、零 schema bump，且**三端可复用**（纯函数）
- 用户纠正能跨设备同步，且不栅栏旧客户端

### 4.2 代价与风险

| 风险 | 说明 |
|---|---|
| 界面工作量 | 需要"看见偏好 / 单条删除 / 覆盖"的界面（M6），否则纠正无处可去 |
| 旧客户端不一致 | 旧客户端显示未纠正值 —— 已知且可接受，但**不要**在文档里假装一致 |
| `withheld` 的展示 | 「我还需要 N 次专注」必须真的展示，否则冷启动又是"装懂" |
| 主开关的语义边界 | 关闭的是**偏好推断**；事实层（`memory.ts`）不受影响 —— 它只是本机数字，不出境 |

> ⚠️ 最后一条容易被误读：主开关**不是**"关闭所有记忆"。
> 它是"关闭**推断用户是什么样的人**"。事实层的推迟次数仍在本地计算 ——
> 但那不构成隐私问题，因为它不出境、也不刻画人。

## 6. 未决
