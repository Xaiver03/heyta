# ADR-0021：托管 AI 用 **DeepSeek V4.1 Flash** —— ¥12 那一档只在 flash 级上成立

> 状态：**已接受**
> 日期：2026-09-27
> 取代：无。本 ADR **关闭** [ADR-0020](0020-ai-subscription-two-tiers.md) 的 §5 第 1 条
> 「模型档位未定」，让它的 §3.6 与「¥12 / 月 · 300 次」从**条件成立**变成**成立**。
> 不改变 ADR-0020 的任何价格、额度或周期结论。

## 1. 背景与约束

ADR-0020 把付费定成月付两档，第二档（¥12 / 月）买的是**我们的云端 AI，每月 300 次**。
同一个 ADR 把一件事标成红灯：

> §3.6 的单价已从官方定价页取证，但**用哪个模型还没定**。已量化：flash 级 300 次/月
> 成本 ≈¥2.01/月（占增量 29%）；pro 级 ≈¥7.71/月，超过 ¥7 增量（每份亏 ¥0.71/月）。
> **所以价格与额度必须和模型选型一起定案。**

也就是说：**模型选型在这个产品里不是技术细节，是单位经济。** 约束有三条：

1. **AI token 成本 ≤ 该档增量的 1/3**（ADR-0020 §3.3 的纪律）。
   增量 = ¥12 − ¥5 = **¥7**，所以月度 token 成本上限 ≈ **¥2.33**。
2. 额度必须是**对普通用户有意义**的数字。在 pro 级上要守住 1/3 纪律，
   额度得砍到 ≈90 次/月（ADR-0020 §3.6）—— 那基本等于卖不动。
3. 单价**已取证**：2026-09-27 直取 DeepSeek 官方定价页
   <https://api-docs.deepseek.com/quick_start/pricing>，不依赖印象。

## 2. 选项

| 选项 | 优点 | 缺点 | 关键证据 |
|---|---|---|---|
| **A. `deepseek-flash`（V4.1 Flash）** | 300 次/月 成本 ≈ **¥2.01**，占 ¥7 增量 **29%** ✅ | 推理能力弱于 pro 级 | 定价页：输入 \$0.15 谷 / \$0.30 峰，输出 \$0.60 谷 / \$1.20 峰 |
| B. `deepseek-v4-pro`（V4-Pro-0813） | 更强的推理 | 单价贵 **4.4 倍**：300 次/月 ≈ **¥7.71 > ¥7**，**每卖一份亏 ¥0.71/月**；要守住 1/3 就只剩 ≈90 次/月 | 同上：输入 \$0.66 谷 / \$1.32 峰，输出 \$1.98 谷 / \$3.96 峰 |
| C. 只做 BYOK，不提供我们的云端 AI | 零 token 成本、零保留争议 | 放弃 [ADR-0013](0013-cloud-ai-and-maas.md) §2「会提供统一云端 AI 并**按此收费**」，第二档失去存在理由；也没解决「普通用户不会去申请 API key」 | ADR-0013 §2 |
| D. 自建 / 开源自部署推理 | 边际成本可控，内容不出境 | 现在没有 GPU、没有权重、没有运维能力，与「个人项目」的资源量级不匹配 | 本项目无相关基建 |

## 3. 结论

**托管 AI 用 `deepseek-flash`（DeepSeek V4.1 Flash）。**

这是**价格与模型的联合定案**，不是两个可以分开做的决定：

- ¥12 / 月 的增量 ¥7 里，AI token 成本 ≈ **¥2.01（29%）**，落在 1/3 纪律内；
- **300 次/月 在 flash 级上是能卖的数字；同样额度在 pro 级上是亏的。**

> ⚠️ **换模型就是改价。** 这不是提醒，是等式：pro 级的 ¥7.71 月度成本已经
> **超过 ¥7 增量本身**，与「多花 ¥7 买到什么」直接冲突。

## 4. 后果

1. **这档的可行性绑在 flash 级的单价上。** 上游调价会让结论失效 ——
   所以需要一个可执行的复算动作，而不是一句"以后再看"（见 §5 第 2 条）。
2. **pro 级能力不在这档里。** 想要更强推理的用户只能自带端点，
   而自带端点的 AI **永久免费且不计量**（ADR-0020 §1.4）。
   所以这不是"阉割"，而是「我们只卖我们算得过来的那部分」。
3. **模型 id 必须是配置，价格必须是契约。** `deepseek-flash` 的版本号会滚动
   （V4.1 → V4.2 …），**换版本不该触发改价**；但**换档位**（flash → pro）
   必须重算额度或价格。这两件事在代码里要能被区分开。
4. **不能因为"用户想用更强的模型"就默默升到 pro** —— 那是每份倒贴钱，
   而且倒贴多少要到月底才知道。

## 5. 未核实项

1. **单次 1,500 输入 + 400 输出仍是估算**（ADR-0020 §5 第 2 条）——
   flash 级的 ¥2.01/月 建立在这个估算上，没有真实调用样本，误差可能达数倍。
2. 🔴 **上游调价与换权重的通知义务未知** —— 没有任何机制保证 flash 的单价
   或底层权重不变，所以本 ADR 的结论带一个**外部失效条件**。
   复算动作应当是具体的：定价页变了就重跑 ADR-0020 §3.6 的那张表，
   看 29% 是否还在 1/3 以内。
3. **`deepseek-flash` 的准确 API model id 没在真实调用里验证过** ——
   本 ADR 用的是定价页上的**档位名**；接服务时以实际可调用的 id 为准。
4. **「1 次 = 1 次」的补贴幅度仍未量化**（ADR-0020 §5 第 4 条）：
   `capture` 与 `breakdown` 的 token 差多少倍不知道，所以 300 次 的**构成**
   会显著影响真实成本。
5. **没有做能力对比实测** —— 选 flash 的理由是**单位经济**，不是"flash 够用"的
   验证。四个 AI 功能（捕获 / 拆解 / 耗时估计 / 优先级）在 flash 上的实际可用性
   一次都没测过。**这是本 ADR 最大的未核实项。**
