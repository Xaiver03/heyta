## 1. 为什么需要这份 ADR

一句在仓库里流传的话是「删除就是进回收站，彻底删除就是删掉」。按代码摊开，这两句话
**都只说对了一半**，而错的那一半会直接产出对外承诺不了的文案与做不出的功能：

| 流传的说法 | 实测 | 后果 |
|---|---|---|
| 「彻底删除会把数据删掉」 | **系统里没有任何物理删除路径**。`purgedAt` 只是一个标记（`packages/domain/src/entities.ts:31-51`） | 政策文案一度写着"服务器 45 天后清理"（缺陷 D8，已改） |
| 「已删除的东西搜不到」 | Web 搜索能搜出**已彻底删除**的任务，移动端不能（D9） | 同一件事在两端不同答案，而两端都不报错 |
| 「删了任务提醒就没了」 | 已软删任务的提醒**仍会投递**（D1），且同一条到点提醒刷新后会**再弹一次**（D14） | 通知栏与"点进去什么都没有" |
| 「归档就是隐藏」 | 归档清单对 AI / MCP / CLI **全可见**，唯一那处过滤在共享 UI（`packages/ui/src/projects/model.ts:107`） | 共享 UI 不是安全边界 |

**这四条没有一条是"有人写错了代码"** —— 它们的共同形状是：**"隐藏"这个决定被留在了调用方手里，
而调用方不止一个。** 本 ADR 的核心产物就是把它抬成一条不变量（§4 I5）。

## 2. 决策：四个互相独立的状态

```
                    ┌──────────── archive ────────────┐
                    ▼                                  │
   alive ──delete──► trashed ──purge──► purged          │
      ▲                │                                │
      └──── restore ───┘                                │
                    │                                   │
   archived ◄───────┴───────── unarchive ───────────────┘
```

| 态 | 字段 | 用户看到 | 能否回来 | 依据 |
|---|---|---|---|---|
| 已完成 | `completedAt` | 完成列表 | 取消勾选 | 既有 |
| 归档 | `Project.archived`（`entities.ts:203`）。⚠️ **便签没有归档态** —— 它只有 `isPinnedToToday`；标签连 `archived` 字段都没有 | **哪都不出现**（本轮要补「已归档」出口） | 能 | 既有 |
| 回收站 | `deletedAt` | 回收站 | 还原 = `UPD { deletedAt: null }` | 既有 |
| 彻底删除 | `purgedAt` | 回收站里也没了 | **不能**，但数据仍在日志里 | `packages/app-host/src/actions.ts:495-514`（`restore` 对 `purgedAt` **抛错**，见 `:503`） |

**`purgedAt` 永不单独出现**：不变式 `purgedAt ⇒ deletedAt` 成立，且这是刻意的 ——
清掉 `deletedAt` 会让离线对端把这条数据当"从未删除"**再同步回来**（`entities.ts:38-45`）。
老客户端读到带 `purgedAt` 的 op 只当普通字段合并，行为与升级前一致（不复活、不显示）。

## 3. 三条不可让步的产品立场

1. **`purgedAt` 不是物理擦除，也不许被宣传成物理擦除。** 界面与文档只许说
   「不再提供恢复」，不许说「已永久删除／已从服务器销毁／数据已抹掉」。
   理由：op-log 只追加，本仓**没有**任何擦除能力（调研 §5）。
2. **回收站不设自动保留期**（不做「N 天后自动彻底删除」）。理由三条都成立（计划 §1.5）：
   ① 没有物理删除能力，做出来只是"把条目从唯一还看得见它的地方挪走"的**假删除**，
   比不做更糟；② E2EE 下服务端算不出来，只能各端裁决 ⇒ 两台设备必然给出不同答案；
   ③ TTL 的两个真实动机（云端存储成本、可对外承诺的删除时限）我们一个都不具备。
   **外部旁证**：Microsoft 的两级窗口 30 + 93 天服务的是**合规与电子数据展示**
   （且官方明说"回收站未编制索引"）；同品类的 Todoist **对项目根本没有回收站**，
   官方补救是"新建项目 + 导入自动备份"。⇒ 该品类"找回"的备选是**备份**，不是 TTL。
   🔴 **重新讨论这条的终点条件**：因果全量边界（checkpoint / 因果 `REPAIR`）
   **且**客户端 op-log 压缩（`archiveUpTo()`，已实现、生产零调用方）落地之日。
3. **一个用户意图 = 一条 op**（`AGENTS.md` §3.4）。批量删除要拆成多次用户确认，
   不许一次点击 fan-out 多条 op。

## 4. 五条不变量，每条都要有能因注入转红的判据

| # | 不变量 | 现在由谁守 | 判据 |
|---|---|---|---|
| **I1** | 每个箭头恰好一条 op | 动作层 | `packages/app-host/tests/trash-actions.spec.ts` |
| **I2** | 还原回到"删除前那一态"（含归档态） | `restore` 只清 `deletedAt` | 今天**免费成立** ⇒ 要的是判据而不是代码：任何人在 `restore` 里顺手重置别的字段就该红（W1/W4 补） |
| **I3** | 归档不许借用 `deletedAt` | 既有裁决 | 变异判据（W3） |
| **I4** | `purgedAt` 不许清 `deletedAt`，也不许被宣传成物理擦除 | 既有裁决 + 文案 | 文案侧已钉（见 §7 门禁列） |
| 🔴 **I5** | **「隐藏」由层负责，不由调用点负责** | 见下 | 形状统一成一句话：**把原始表整个递进去也不得出现** |

**I5 是这份 ADR 的新增规则**，也是 D9 / D11 两个实测泄漏的共同根因。两种隐藏各有唯一定义处：

- `deletedAt` / `purgedAt` 归**领域层与动作层各自内部滤**：
  `searchTasks()` 内部先过 `aliveTasks`（`packages/domain/src/search.ts`，A1 已落），
  `due()` 内部滤掉所属任务已进墓碑的提醒（`packages/app-host/src/reminder-actions.ts`，A2 已落）。
- `archived` 归**动作层的 list 分裂**：`listProjects()` 不含归档 +
  `listArchivedProjects()` 只含归档（W9，**尚未落**）。
  ⚠️ 今天唯一那处过滤在共享 UI（`packages/ui/src/projects/model.ts:107` 的 `aliveProjects`），
  而**共享 UI 不是安全边界** —— 它管得住界面，管不住 local-api / MCP / AI / CLI
  与任何未来的非 UI 消费者。所以这条要写在动作层，不是补在某个界面。
- 界面上那个「显示已归档」开关的语义是**显式取第二路数据**，**不是**"把过滤关掉"。

## 5. 回收站不收哪些实体，以及为什么这不是排期

**收**：任务、便签、清单、习惯（P-1 已拍）。
**不收**：提醒、番茄钟/专注记录（P-1 已拍）。

理由是**语义差异**，不是"以后再做"：

- **提醒是任务的从属派生物**，其 id 就是 `${taskId}:${triggerAt}`。单独"还原一条提醒"
  没有可指认的用户意图 —— 它要么随任务回来，要么不存在。把它放进回收站会造出一个
  能还原成什么都不还原的条目。
- **专注/番茄钟记录是历史事实**（"我在 X 时间专注了 N 分钟"）。历史事实没有
  "误删恢复"这一说，只有"统计里算不算它"这一说，而后者归激励体系（ADR-0022 那条线）。
  给它们回收站，等于给用户一个可以**改写自己过去**的入口，与"只与自己的过去比"红线冲突。

对外承诺的口径（帮助文档、政策）必须**逐实体**说，不许写「所有数据都可恢复」。

## 6. 物理擦除：两条候选路径，都不是本轮能带走的

| 候选 | 做法 | 为什么现在不做 |
|---|---|---|
| **定向删除** | 服务端按 `entityId` 摘掉对应 op | 服务端只看密文，**不知道**哪条 op 装着哪条实体；要它知道就等于放弃 E2EE |
| **逐实体密钥封装** | 每个实体一把子密钥，销毁密钥即"加密擦除" | 密钥管理面 + 存量数据全量重写；而且**擦除可验证性**仍是问题（备份里还有） |

🔴 **明确否决过、不许再顺手做的四件事**：
① 清掉 `deletedAt`（离线端复活）；② 写 `deleted: false` 这类布尔（与墓碑语义并存会出现两真）；
③ 服务端 TTL（§3.2）；④ **复用账号级密钥做"加密擦除"** —— 账号级密钥一销毁整个账号都读不回来，
做不出**逐记录**擦除（调研 §5.4），把它叫"彻底删除"是虚假的精确。

## 7. 壳级门面的边界（是边界，不是缺陷）

`packages/app-host/src/native-bridge.ts:273` 的门面**只有** `removeTask`（发软删 `DEL`），
**没有** `restore` / `purge` / `listTrashed`。⇒ **走壳级窄门面路径的端，当前不提供误删恢复**
（macOS 原生壳的 5 能力界面即此形态，缺陷 D13 记的就是它）。

裁决：这是**边界**。闭合它的责任在各原生壳转向共享 UI 的那一轮
（[multi-end-unified-strategy](../plans/multi-end-unified-strategy.md) §6.3-T3），
**不在本轮**；本轮只负责不许把它**宣传**成"四端都有回收站"。

## 8. 与政策文案的那条线（⚠️ 法务口径待最后确认）

政策里「承载删除的加密历史会在保留期（45 天）届满后被清理」**已被改写为实话**（A3 已落）：
服务端保留清理的候选集要求该账号流水里存在一条**因果全量 op**
（`CAUSAL_FULL_STATE_OPERATION_WHERE`，`server/src/sync/sync.types.ts:35-40`），
而客户端只产 `CRT`/`UPD`/`DEL` ⇒ 每日任务删除条数恒为 0。
**设备行**的清扫（`device.service.ts` 的 `deleteStaleDevices`，只看 `lastSeenAt`）
与**注销账号**的级联硬删是**真的在跑**，文案里也照实分开写了。

⚠️ 这段的**最终措辞**产品负责人没有逐字拍（是靠「其他按你的建议」覆盖的）。
新句子原文已单独交回给他过目；在他确认之前，本节标为**待最后确认**，
`packages/legal/tests/retention-claim.spec.ts` 钉的是"不许再出现无条件承诺"，

## 11. 增补（2026-10-03 晚，批次 E）：注销是今天唯一在跑的物理删除路径，但它只覆盖五层里的一层

产品负责人新增要求：「删除账号一定要是彻底销毁」+「按欧盟的标准走 GDPR」。
本 ADR §6 原来只交代了"回收站里的彻底删除不是物理擦除"，没有把**注销**这条真的在物理删的路径
连同它的边界写全。这一节把它补上；它**不推翻**§1–§10 的任何结论，只是把"销毁"这个词的适用范围钉死。

**结论（新增四条，均可核验）**

1. **注销账号 = 服务端物理删除。** `prisma.user.delete` + 数据库级联，
   口径真源是**引用 `users` 且 `ON DELETE CASCADE` 的外键：16 条 / 覆盖 15 张表**
   （`referrals` 占两条，所以条数 ≠ 表数）。
   ⚠️ **这两个数在 2026-10-04 04:27 被 `structure.spec.ts` 重量为 19 条 / 18 张表** ——
   增量来自 vault 批次（ADR-0050）新长的三张级联表，而这一节写在它之前。
   政策侧已跟着改（`data-rights` 第五节 GDPR 行 + 该文件头注释各带一条"旧数留原文旁边"的更正），
   **本节原句不删**，因为"16/15 曾经是现量"本身就是这一族抄件会漂的证据。
   ⚠️ 本 ADR 与政策文案此前抄的「19 处」「18 处」是**另一个口径**（全部迁移里
   `ON DELETE CASCADE` 的累计出现次数，含与账号无关的级联、且历史重建重复计数）—— 已更正，
   并由 `packages/legal/tests/structure.spec.ts` 从 `server/prisma/migrations` 现量对账，
   扫**九份文档 × 中英两栏**，不再是只钉 privacy 一份。
2. **"彻底销毁"在五层里今天只覆盖第一层**：① 服务端行（已真删）；② `payment_events` 无账号外键，
   注销后行仍在（订阅指针置空，只剩金额与时间）；③ 每日整库备份含**邮箱明文/口令散列/passkey**，
   代码里没有"从既有备份中定点删掉某一个人"的能力；④ 服务端日志会把邮箱明文写盘，无轮转与到期删除；
   ⑤ 🔴 **其它设备上的本地明文库一行都不会少** —— 这一层以前没有任何一份文档写过。
3. **因此政策口径固定为**：注销承诺必须逐处列出"仍然存在的副本"，且**每一格做级联硬删承诺的文本
   都必须在中英两栏同时写明"不会清除其它设备上的本地数据"**。
   把注销写成"你在所有设备上的数据立即彻底销毁"在本产品里是**虚假陈述**，
   门禁 `structure.spec.ts` 会红。（这不是修辞选择：本地优先 + E2EE 下设备端就是事实源。）
4. **要让它成为真承诺，缺的是两件产品动作而不是文案**：
   **E1**（注销可辨识 —— 已落：`TokenFailureCode` 必填，`ACCOUNT_CLOSED` 与
   `TOKEN_REVOKED`/`ACCOUNT_UNVERIFIED`/`TOKEN_INVALID` 严格分码；客户端**只在** `ACCOUNT_CLOSED`
   下才允许销毁本机数据。理由不是洁癖：改一次密码就会推进 `tokenVersion` 让所有设备拿到 401，
   按 401 删库等于把用户数据毁掉）、
   **E2/E3**（各端真的清干净：`DbAdapter` 今天连 `destroy` 都没声明，IndexedDB 那份 `destroy()` 零调用方，
   Web 有 4 类本地存储且迁移期刻意不删旧库 ⇒ **只删一类会被另一类复活**；Windows/macOS 各有两份独立数据）。

**与本 ADR §3 那条"没有冷静期"的冲突要单独裁决**：GDPR Art.17 要求"无不当延迟"，苹果 5.1.1(v) 要求应用内可注销，
而 E2 落地后"注销"会连带清掉各设备上**尚未同步出去**的明文数据。若产品负责人选择加冷静期，
那是**变更 §3 的结论** ⇒ 按仓库纪律要另写一份 ADR 取代这句，而不是在这里改它。当前状态：**已登记为 P-11，未拍**。

## 12. 增补（2026-10-04 凌晨，批次 E 第二笔）：§11 里那四句"今天还缺"已经被产品动作追平了三句半

⚠️ **这一节只更正 §11 的"当前状态"读数，不改 §1–§11 的任何决策**。§11.4 本来就把 E2/E3 写成
"缺的是两件产品动作而不是文案"，所以动作落地之后回来改写状态栏是这节计划的一部分；
而 §11.3 那条**政策口径要求仍然成立**（下面第 4 条写清它今天该怎么落字）。
所有读数逐条现量，命令就写在旁边。

1. **"其它设备上的本地明文库一行都不会少"（§11.2 ⑤）已经不再成立** —— 不是被推翻，是被产品动作
   补上了：那台设备**下一次同步**拿到 `ACCOUNT_CLOSED` 时会自己把本机明文销毁。
   现量：`git show HEAD:packages/sync-client/src/client.ts | grep -c eraseLocalData` = **2**，
   处置在 `client.ts:929-977`，判据 `packages/sync-client/tests/account-closed-erasure.spec.ts`
   （含"401 + 该码同样算注销"与"**除该码外每一个失效码都不许触发销毁**"两条）。
   ⇒ 这句话的准确版本是"**不会立刻少**"：设备离线、或用户不再打开它，那份明文就一直在那儿。
2. **`DbAdapter` 连 `destroy` 都没声明、`destroy()` 零调用方（§11.4）已过期**。现量：
   `git show HEAD:packages/storage/src/db.types.ts | grep -c destroy` = **5**（契约），
   三套实现各有 `async destroy`：`indexeddb/indexeddb-adapter.ts:570`、`sqlite/sqlite-adapter.ts:255`、
   `memory/memory-adapter.ts:196`（三份的 HEAD 命中数都是 **1**），调用方是
   `apps/web/src/lib/local-data-destruction.ts:234`。
3. **"只删一类会被另一类复活"那一档，Web 侧已闭合**：`eraseWebLocalData` 一次清**四层** ——
   主库走适配器自己的 `destroy`、`localStorage` 前缀键、`sessionStorage` 前缀键 + 令牌那几把**无前缀精确键**、
   service worker 层。注册点 `apps/web/src/main.tsx:53`（刻意放在入口而不是同步 store：销毁是设备级的）。
   另有两条形状值得记：`deleteDatabase` 的 `onblocked` **只等待不作决议**，决议只来自
   `onsuccess` / `onerror` —— 当场 resolve 会让销毁报告在"别的标签页还握着连接、库其实还在"时说"删了"；
   代价是那个 Promise 可能一直挂着，这是**诚实的挂起**，界面层若要给期限就该在这一层的调用点做超时并说明原因。
4. **§11.3 那句边界要改的是措辞，不是取消**。政策文本现在必须写"其它设备上的本地明文**不会立刻**清除，
   要等那台设备下一次同步"，而不能继续写"不会清除"。常驻判据不受影响，因为它钉的是**语义在场**而不是
   字面：`structure.spec.ts:557-563` 那四组是 `BOUNDARY_ZH = /本地.{0,16}(库|数据)/`、
   `BOUNDARY_EN = /local(?:\s+\w+){0,3}\s+(data|databases?|store)/i`、`DEVICE_ZH = /(其它|其他)设备/`、
   `DEVICE_EN = /other device/i`。
   🔴 这一条不是推演，**实测过**（04:1x 用四条正则各跑一遍新措辞）：中英两句命中
   `BOUNDARY + DEVICE` 全为 **true**；反向对照"只提设备、不提本地库/数据"的那句命中为 **false** ——
   也就是新措辞能活，把边界删掉照样红（该判据自己的变异 M7 也验过同一件事）。
   ⇒ 记这条是因为它给了一个可迁移的形状：**要求"必须提到某件事"的判据，能在事实变化时原样活着；
   要求"必须是某个字面句子"的判据，会在事实变化那天变成谎言的守卫**。
5. 🔴 **§11.2 里还开着的三档，本轮没有假装闭掉**：
   ② `payment_events` 无账号外键（仍在）；③ 整库备份没有"从既有快照里定点删掉某一个人"的能力
   （P-12，运维侧）；④ 服务端日志的邮箱明文轮转与到期删除（P-4 已改写入侧，历史日志仍在）。
   加上**设备侧新登记的三档**：
   (a) macOS / Windows 原生壳的**第二份存储**（WebKit 持久 `websiteData`、WebView2 profile）没有销毁通道，
   现量 `apps/desktop-macos/Sources` 里 `WKWebsiteDataStore` 只有 1 处且是 `HeytaMacApp.swift:416` 的
   `.nonPersistent()`（只在 `HEYTA_WEBKIT_EPHEMERAL=1` 下生效），`apps/desktop-windows` 里
   `DeleteProfile|BrowsingData` **0 处** ⇒ 那两个壳上"点下注销"目前只清壳自己那份 SQLite，
   **Web 层那第二份还在盘上**；这一处例外已经写进对外文本（`data-rights` 第五节中英把"不承诺"从一处
   扩成两处，`minors` 第七节改为指向那一节而不是抄第二份，2026-10-04 04:2x），接上销毁通道后这两句要回写；
   (b) 本机销毁器注册表是**模块级单例且不分归属**，早一步注册的兜底会一直赢，于是
   `eraseLocalData()` 可能报 `containerRemoved: true` 而那台设备的库还在（假成功；修复落点
   `packages/app-host/src/host.ts:340-342` 那句 `if (!hasLocalEraser())`，该文件本轮现量仍是别人的未提交 diff）；
   (c) 隐私政策与第三方清单里"**今天还不存在**"那三句（`privacy` 中英、`third-parties` 中文）——
   被 §12.1 否证，但那两份文件的 `version` 行正被别人改，实质修改必须 bump ⇒ 挂起，形状见计划 §10.7。

**验收与未验收要分开写**：上面第 1–3 条是**代码 + 单元判据**层面的事实（其中 web/mobile/node-host
三个注销入口的 spec 本轮第一次真跑：`cli-account` 11/11、`account-closure-entry` 11/11、
`local-data-destruction` 11/11、`account-closure-model` 10/10）。**跨设备那半条今天仍未取证** ——
也就是"B 设备离线一段时间后重新联网同步，界面上真的空了"这句话目前只有单元层的支撑，
没有真机那一跑。**本 ADR 不把它写成已成立。**

> **对端设备离线再连**，界面上那条记录真的消失 —— 现有设备腿读的是本机的销毁结果，不是对端的重连收敛。
