# ADR-0086：隐私同意是一道**网络守卫**，不是首启的墙

- 状态：已接受
- 日期：2026-11-16
- 相关：G-11（首启未征求同意）、G-12（冷启动可能已发请求）、ADR-0003（离线可用）、PIPL 第 14 / 16 条

## 背景

当前实现是：`startPrivacyGate()` 在 `App` 首次渲染前调用，若 `privacyConsent.undecided()`
就 `openPrivacySheet('first-launch')` —— 面板**盖在欢迎页之上**。

这样做的原始论证（写在 `apps/mobile/src/privacy/startup.ts` 的文件头）是：

> 欢迎页那个「注册 / 登录」按钮一按就会发请求，所以"这台设备能不能对外说话"必须先问。

这条论证只对了一半：**点登录时会发请求，而不点登录时一个请求都不会发**。欢迎页本身
（漫画 + 两个按钮）是纯本地的。于是"必须先问"被实现成了"无论如何先问"，
代价是**用户看到的第一件东西是权限决策，而不是产品**。

2026-11-16 真机实拍证实了这个代价：iPhone 首次启动，一张覆盖整屏的同意面板把三格
漫画完全盖住，用户第一眼看到的是「在使用联网功能之前」。

## 决定

**同意的锚点是"第一次真正要出门的那一刻"，不是冷启动。**

具体四条：

1. **冷启动不主动弹。** 欢迎页、任务页、任何纯本地操作都不触发同意面板。
2. **需要联网的动作触发它，且"动作"指的是真的发出请求那一步。**
   手动开同步、用 AI、分享，以及**登录表单的提交** —— 这些在**发出请求之前**
   打开面板，`reason = 'required-for-action'`。
   ⚠️ **不是"打开登录面板"那一刻**：打开面板一个请求都没发，用户还在填表；
   而未同意时 `AuthPanel` 画的是本地表单，他在那儿看到的是真表单而不是一堵墙。
3. **「只用本机」不是降级模式，因此不弹。** 选它的人永远不需要同意联网；
   他只在本机读写。PIPL 第 16 条禁止因不同意而拒绝服务，而 heyta 的本地优先让这条路
   是**同一个完整产品**（ADR-0003）—— 所以"永远不问"对这类用户是合法且正确的。
4. **被拦住的动作必须说出口，而不是变成"失败"。** 网络层拦下时抛的是
   `PrivacyConsentBlockedError`（已存在）。宿主必须把它接成"打开同意面板"，
   而不是让它落进通用的网络错误处理，变成一句"同步失败"。

## 为什么不是"合并成一屏问两个决定"

现有实现刻意把"能不能联网"与"要不要登录"拆成两块面板，理由写在 `startup.ts`：
合并会让「只用本机」读成「不登录」。

本 ADR 保留这条拆分，只改**次序**：先做的是"用户主动要走那条要出门的路"，
所以同意面板出现在登录面板**之前**，且只在那时出现。

## 判据（每条都要能红）

|---|---|---|
| 1 | 未决定时，底层 `fetch` 调用次数为 **0** | 已有：`apps/web/tests/consent-gate.spec.ts`、`apps/mobile/tests/privacy-consent-gate.spec.ts` |

## 后果

- **好**：用户先看到产品；同意发生在需要它的上下文里（告知更具体，符合 HIG 的
  just-in-time 原则）；纯离线用户永远不被问。
- **代价一**：需要一条"等用户决定"的通道 —— 网络动作被拦后要挂起，等面板给出决定，
  同意则**原样重试那一次请求**。没有它，"同意之后什么也没发生"会比"没同意"更让人困惑。
- **代价二**：如果宿主没有 UI（headless / 测试），这条通道会一直挂着。
  因此必须有超时降级：超时后抛原错误，不静默成功。
- **代价三**：提交时被拦下的那次请求**目前不会自动重试** —— 用户同意之后要再点一次提交。
  这是下一步（`waitForPrivacyDecision` 那条通道），本 ADR 只保证"不静默失败 + 时机正确"。
- **不变**：`local-only` 与 `accepted` 的落盘、撤回、失败回执全部沿用现有实现。

## 不做的事

- 不改 `PrivacyConsentRecord` 的形状，不加"已询问次数"这类字段 —— 判定仍然只有
  「没问过 / 同意 / 只用本机」三态。
- 不把同意合并进注册表单的勾选框。勾选框只在注册那条路上，而同意是**设备级**的
  （同一台设备上换账号不该重问，同一账号换设备要重问）。
