# ADR-0061：规则删除后凭原设备持有的回执完成迟到同步

> 状态：**已接受（技术裁定，2026-10-08）**。补全 [ADR-0058](0058-inbound-automation-commit-and-task-batch.md) 的许可后不转派与 [ADR-0060](0060-automation-entitlement-and-retention.md) 的删除保留边界；未代表整条功能已开放。

## 必须同时成立的两个要求

规则删除要清正文、草稿与去重摘要；但许可已发出后，原设备可能已经创建本地任务、尚未上传。若同步只查中心许可表，清理许可会把合法任务永久挡在本机；若为了同步一直保留该表中的结果摘要，又违反已批准的保留期。延长摘要期限、允许换设备重建都不可接受。

## 决策

许可原子落盘后，服务端返回一枚签名提交回执。原设备先把回执按账号、服务端、worker、本地库 epoch 和 opId **持久保存**，成功后才能派发任务；回执不是业务 op，不得同步给其它设备。任务正文和源摘要不在回执中。

回执 v1 包含：部署实例 UUID、签名 keyId、账号 ID、workerId、syncClientId、本地库 epoch、不透明事件 ID、条数。操作与成员 ID 由事件身份和序号确定。使用独立 32 字节 HMAC-SHA256 密钥，签名输入为 `heyta-inbound-commit-v1.` 加 base64url 编码的严格 JSON 载荷；线形状为 `payload.signature`，不带 padding。验证器拒绝额外字段、错误实例、非规范编码和坏签名。

这不是“新授权请求”的短期票据，而是已授予意图的证明，因此不设置到期时间、不因订阅到期或规则删除自动作废。**仍须账号 JWT + 未撤销 worker 凭据**；另一 worker 取得回执也不能使用。设备撤销和账号 tokenVersion 失效仍在同步事务的账号锁内检查。仅验回执签名不算设备认证。

`AUTOMATION_COMMIT_KEYS` 是部署私有配置，包含稳定 instanceId、activeKeyId 和验证密钥集合；多副本共用，重启/恢复不得自动重新生成。轮换只新增活动键，保留旧验证键。移除旧键会使它签发的离线回执失效，必须作为显式撤销/事故处置，不能声称无损轮换。正文 KEK、Vault root、JWT 密钥和 webhook 凭据均不能复用作此密钥。

正常同步上传信封新增可选 `inboundCommitProofs`，按 opId 携带回执；它不进入 op payload、请求指纹或远端下载。服务端优先查仍存在的许可，许可清理后用回执验证同一身份，缓存返回前与实际写事务内均执行。原 op 的精确重复仍由既有唯一 ID 与密文校验裁决。

客户端将自动收集与普通任务分批。缺少凭据/回执，或服务端返回 `INBOUND_AUTH_REQUIRED` 时，该 op 保持待上传，不改写为新 op、不永久标记拒绝；普通上传和下载继续执行。不能借用 `INVALID_CLIENT_ID`，因为其现有语义是永久移出上传队列。

## 验证和剩余接线

已用真 HTTP/PostgreSQL 测试显式删除许可与摘要行后，原设备凭回执上传一条 op、重试仍为一条；没有回执、坏回执、另一 worker 和撤销后的原 worker 均拒绝。这里删除的是测试夹具中的许可行；真正的规则删除接口、签发状态机、客户端持久 journal 和跨端接线仍需实现，不能把本用例说成规则删除全链路已通过。
