# font-kit —— 手写体 → 矢量字体 的工作台

这套东西是为「你手写、我编译」这条路线准备的最小工具集。**全部是临时工作目录，不进产品代码，删掉不影响任何门禁。**

| 文件 | 是什么 |
|---|---|
| `handwriting-grid-A4.pdf` | 打印用的字格模板，3 页 96 格（大写+数字 / 小写 / 标点） |
| `template.html` | 上面那份 PDF 的源文件（矢量，可直接在浏览器打印） |
| `manifest.json` | 每格的 mm 坐标 + 五条参考线的位置，给矢量化脚本读 |
| `make_template.py` | 生成上面两样东西的脚本（改字符集/格数就改这里） |
| `trace_pipeline_demo.py` | **端到端验证脚本**：合成笔画 → potrace → TTF → 渲染回图 |
| `proof-trace-to-ttf.png` | 上面那步的产物：左边原笔画，右边从 TTF 渲出来的效果 |
| `sample-traced.ttf` | 顺手生成的样本字体（只有一个 `n`，仅证明管线通） |

## 已验证的事实（不是推测）

`trace_pipeline_demo.py` 真跑通了整条链路：位图笔画 → potrace 矢量 → 校正坐标 → 二次曲线转换 → TTF → 用 Pillow 从 TTF 渲回来对得上。过程中踩到并解决了两件真实的事：

1. **potrace 不读 PNG**，只吃 pbm/pgm/ppm/bmp。要先转 PGM。
2. **potrace 输出三次贝塞尔曲线，而 TTF 的 `glyf` 只收二次曲线**。直接塞进去会抛
   `has cubic Bezier outlines, but glyphDataFormat=0`。必须先过 `Cu2QuPen` 转二次，
   或者改出 OTF/CFF（三次曲线原生支持）。这个选择会影响最终字形精度。

## 你只需要做三件事

1. **打印** `handwriting-grid-A4.pdf` —— 打印机里选「实际大小 / 100%」。
   ⚠️ 千万别选「适合页面」，缩到 96% 会让 manifest 里的毫米坐标全部失效。
   （就算真缩了也能救：格子外框本身就是标定物，我能反推出 px/mm。）
2. **写** —— 0.6–0.8mm 黑笔，单笔画不连笔，一格一个字，写慢、写匀。
   同一个字的笔画粗细要尽量一致：粗细不匀，二值化后轮廓会出现凹口，
   矢量化结果就会有毛刺，而这是我在后处理里只能缓解、不能消除的。
3. **扫** —— 600dpi、灰度、整页不裁不转，一页存一个文件，命名 `p1 / p2 / p3`。
   300dpi 也能用，但细笔画会在二值化时断线。

## 我拿到扫描件之后做什么

```
扫描件 → 二值化(Otsu) → 按 manifest 逐格裁切 → 归一化到格子参考线
      → potrace 矢量化 → 三次转二次 → 组装 UPM/度量/字距 → TTF + OTF + WOFF2
      → 出样张（12px / 24px / 48px / 一段中英混排 / 一串数字）给你挑毛病
```

关键点：**归一化不能靠眼睛**。每个字裁出来之后，用 manifest 里的
`guide_y_mm` 把它的 baseline / x-height 对齐到统一的字模坐标，否则
96 个字会各自漂在不同高度上，看起来就像"手抖"。

## 已知的边界（先说清楚，免得到时候互相失望）

- 手写体对外发布，合理定位是**标题 / 展示 / 签名**类字体，不要宣称能当正文。
  正文要的是几百次光学修正，手写天然没有。
- 汉字手写 3500 字 = 约 40 张 A4，且写到后面手会飘，一致性是最大风险。
  建议先只做 95 字符 ASCII 的试做批次，验收合格再决定扩不扩。
