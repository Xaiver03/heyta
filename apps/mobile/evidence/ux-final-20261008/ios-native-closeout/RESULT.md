# iOS 原生交互验收（注册协议与个人中心）

日期：2026-10-08

设备：`heyta-iphone-17pro` / `FE195661-B021-4A71-AAD1-1F2F7AE3A102`（已启动）

包身份：已安装 `com.heyta`，版本 `1.0`，构建 `1`。本轮没有重建、重装、清空数据，也没有提交注册、发送验证码或联网请求。

## 已实际点验

- 个人中心 →「注册 / 登录」→「还没有这个邮箱的账号？创建一个」可达。
- 注册表单显示邮箱、登录密码、再次输入密码、服务器地址、协议勾选和「发送验证码」。
- 「《服务条款》」可点击，原生应用内阅读器打开；标题、关闭按钮、摘要、版本、正文和长内容均出现在无障碍树中。
- 点击关闭后回到注册表单，非真实邮箱草稿 `native-reader-check@example.invalid` 保留。
- 「《隐私政策》」可点击，原生应用内阅读器打开；标题、关闭按钮、摘要、版本、正文均出现在无障碍树中。
- 隐私政策关闭后回到注册表单，邮箱草稿、协议入口和「发送验证码」仍在。
- 切换系统暗色后再次打开隐私政策，阅读器仍能正常呈现标题、关闭按钮和正文；随后已恢复亮色。
- 个人中心 → 设置 → 常规、同步与隐私、数据管理的返回链路可达。
- 数据管理实际入口名称为「备份与迁移」，点击后显示「分享 JSON」「分享任务清单」「从备份还原」「从滴答清单导入」等完整数据操作；返回设置、关闭设置回到个人中心。

## 发现与边界

已有 `scripts/qa/profile-settings-ios.py` 仍期待旧入口文案「导出数据」，所以脚本在进入数据管理后报告失败；当前真实界面使用更准确的「备份与迁移」。这属于验收脚本文案漂移，不是产品交互失败。本轮按实际 AX 点击补验了该入口及返回链路。

当前移动端个人中心/设置无「帮助中心」入口；帮助中心仍由网页端承载。本轮没有改产品源码，因此未把网页外链冒充成移动端原生验收通过。

窄屏/横屏变体在这台既有 iPhone 17 Pro 模拟器上没有可安全切换的设备几何配置，未伪造该项结论。
