台账 912 那一行的后半句、交接文件 §四第 21 格留的那半句：**「其它模板填入非空真实数据」**。

## 这一趟照出来的装置事实（六条，都是会让下一趟白跑的形状）

1. 🔴 **这台模拟器上 `input text` 会把 `-` 和 `!` 打成全角 `－` `！`，而且与 IME 开关无关**：
   现量三档（关 IME + 冷启动 / 开 IME + 冷启动 / 再关一次 + 冷启动）打的都是
   `x-y!z` → `x－！yz`。⇒ 造数据那批标题**只用字母和数字**；快速添加里的 `!1`（优先级）
   在这台机器上打不出来，"重要"这一半改走详情里的「标记为重要」点选。
   ⚠️ 机制**没量清**（不知道是 `input` 的键码映射还是系统的中文标点层），
   但"能不能用"这一档已经量清了：不能用。
2. 🔴 **`uiautomator dump` 在"取不到 idle 态"时打 `ERROR: could not get idle state.` 而退出码仍是 0**
   （现量：专注环在转的时候 `rc=0` + 那行 ERROR）。⇒ 只看 rc 的 harness 会**读到上一枚同名文件的陈旧内容**
   并把它当"现在这一屏"。本腿第一版就是这么把一次成功的"开始专注"读成"没生效"的。
   现在 `dump()` 显式认那行字，读不到就返回空列表。
3. **专注页在 running 时根本读不到无障碍树**（进度环一直在动）⇒ 专注档的判据不能走 a11y 树；
   这一趟改成读**组件卡自己**（卡上写着「专注中」），比读应用界面更贴近这一格的题。
4. **「今天」「标记为重要」这类控件，可点的那一枚是 `Button(content-desc=…)`，可见文字住在里面的 `TextView`（`clickable=false`）上**
   ⇒ 按 `text` 找可点节点会**什么都找不到**，找到那行字点它又什么都不发生。
   本腿为此加了 `find_control`（desc 或 text 两种形状都吃）。
5. **详情窗格是可滚的**，「标记为重要」在折叠线以下时整枚不在可视区 ⇒ 到达判据用"中心在可视带内"，
   不是"在树里"（同族那一格本账已经踩过两次）。
6. **上一趟崩在详情窗格里时，冷启动会停在那张开着的 sheet 上** —— 那里既没有「新建任务」也没有底部 tab，
   照旧往下点就是 `IndexError`。⇒ 造数据前先 `am force-stop`（`launch_app(fresh=True)`）。
   ⚠️ 但 **capture 阶段不许 fresh**：专注那一轮的 `focus.active` 只在内存里，杀掉再起来，
   下一次发布会把它读成 idle，今日专注那枚卡就退回空态。

## 一条产品侧观察（**未裁决，不当结论**）

取图时组件卡写「专注中」，而**同一时刻应用自己的专注页**读到的标签是「已暂停」、主按钮是「继续」，
并且在这期间 `进度` 从 5% 走到 12% 再走到 31%。两件事至少说明：
**暂停/继续不会重新发布快照**（`publish` 挂在 `dispatch` 后面，暂停不写库 ⇒ 没有 dispatch ⇒ 没有发布），
所以组件会停在最后一次发布的那一档，直到下一次写入或 `validUntil` 过期。
"标签说已暂停而进度还在自增"这半句**没有判成缺陷**：我这台的探针通道本身被污染
（`uiautomator dump` 单次耗时现量 2.1–11.1 秒，环在动时还直接读不到），
不足以区分"界面自相矛盾"与"我读到的两个瞬间不是同一个瞬间"。要判它得先有一条不依赖 a11y 树的读数。
