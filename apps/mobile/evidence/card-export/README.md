## 本 README 里有**两种** SHA，别把它们读成互相矛盾

| 写法 | 是什么 | 怎么自己复验 |
|---|---|---|
| `SHA=<12 位>`（判据③那一行里） | 探针读数器打的：**整枚文件的 sha256 前 12 位**（`scripts/screenshots/png-stats.mjs:314` → `verify-mobile-card-export-read.mjs:94` 截 12） | `shasum -a 256 <这张图> \| cut -c1-12` |
| `shasum = <40 位>`（各节开头那行） | 系统 `shasum` 的默认档：**SHA-1** 全长 | `shasum <这张图>` |

17:4x 逐枚对过，两档都自洽：`ios-latest-card.png` ⇒ sha256 前 12 位 `13e10d6cde3b`（= 判据③那行）、
SHA-1 `d3b0f62fa223…`（= iOS 节开头那行）；`latest-card.png` ⇒ `2821b4820f8f` 与 `b0f8e8e9b795…`（19:0x 现量；第三趟那对 `2ac31233b2ed` / `9e9b7ac4bce2…` 随盘上文件一起成为历史读数）。
🔴 **写这一节是因为这两种形状在同一页里混排时，下一个对账的人会以为其中一处抄错了** ——
它们不是同一个函数的输出，谁也推不出谁，所以"值不一样"不构成缺陷证据；
真要判"图被换过"，两档都得重算。
