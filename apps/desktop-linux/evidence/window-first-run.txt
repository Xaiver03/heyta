## 窗口（Xvfb，1280x800 屏）

```
libEGL warning: DRI3 error: Could not get DRI3 device
（↑ Xvfb 没有 GPU，GTK4 从 ngl 退回 cairo 软件渲染；**不是错误**）

WINDOW_TITLE=heyta
WINDOW_SIZE=900x560
```

截图：`window-first-run.png`（1280x800，25,983 字节）。
窗口里那行「还没有任务。上面写一条试试。」不是硬编码 —— 它是 `listTasks()`
穿过 JavaScriptCore → `@heyta/app-host` → `SqliteAdapter` → C 同步驱动 → SQLite
之后返回的空列表被渲染出来。

底部那行是**真实数据**：`库：/root/.local/share/heyta/heyta.sqlite　设备：muktls4b-1-h20tnb83`
—— clientId 是从 SQLite 里读出来、穿过 app-host 到 GTK4 的。

## 库真的建出来了（与其它端同构）

```
$ sqlite3 ~/.local/share/heyta/heyta.sqlite ".tables"
__heyta_seq  archive  meta  ops  ops__mt3  state
```

`heyta.sqlite` = 73,728 字节，表结构与 macOS / Windows 壳**完全一致**。

## 复现

```bash
# 在 Linux 机器上（Ubuntu/Debian）
sudo apt-get install -y build-essential pkg-config \
    libgtk-4-dev libjavascriptcoregtk-4.1-dev libsqlite3-dev xvfb x11-utils imagemagick

# 仓库根：先打包 TS 门面（与 Windows / macOS 壳共用同一个产物）
node packages/app-host/scripts/build-native-bridge.mjs

cd apps/desktop-linux && make
HEYTA_BRIDGE_BUNDLE=../../packages/app-host/bridge-bundle/native-bridge.js ./heyta-smoke

# 窗口 + 截图（无头）
Xvfb :99 -screen 0 1280x800x24 &
export DISPLAY=:99 GDK_BACKEND=x11 GSK_RENDERER=cairo
HEYTA_EXIT_AFTER_MS=9000 ./heyta-linux &
sleep 5 && import -window root window.png
```
