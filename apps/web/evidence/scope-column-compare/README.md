# 范围列要不要给习惯 / 时间线补（§9.2 第 2 步的对比图）

产品负责人 2026-10-06 第 5 条：「数据侧边栏和那个侧边栏，哪有这么排版的？为什么不会这么排版呢？」
左半（右边那一格空白）已经由 H10 两刀修掉（见 `../detail-column-resize/` 与计划 §9.7）。
右半是这一组图的用途：**范围列（`.ht-sidebar`）现在只在 `tasks` 与 `calendar` 两档出现**，
习惯 / 时间线要不要也给它，需要看一眼两种排布再拍。

## 这四张是怎么来的（重要：`with-*` 不是当前产物）

| 文件 | 状态 |
|---|---|
| `as-is-habits.png` / `as-is-timeline.png` | **当前源码**的样子（无范围列） |
| `with-habits.png` / `with-timeline.png` | 临时把 `App.tsx` 那一列的渲染条件改成 `view === 'tasks' || view === 'habits' || view === 'timeline'` 之后拍的 |

变体是**一次性**的：改完拍完就把 `App.tsx` 还原（`shasum` 回到改动前那一枚），
临时夹具 `e2e/tests/tmp-scope-column-compare.spec.ts` 跑完即删。
所以 `with-*` 这两张**不是**任何一份可安装产物，它们是"照那个方案做会得到什么"的证据。
取数：2026-10-06 15:4x，1280×800，出厂夹具（零习惯、零任务）。

## 看图得到的读数（这就是我建议"不补"的理由）

1. **词表对不上。** 那一列的内容是**任务的**：今天 / 最近 7 天 / 已完成 / 四个象限 / 清单 / 标签。
   搬到习惯或时间线旁边，读起来是"习惯页左边挂了一组任务筛选器"，而不是"习惯的范围"。
2. **栅格被挤坏。** `with-timeline.png` 里时间线自己的表头与内容整片不见了 ——
   那一列占掉 240px 之后，中间那一格没有为它准备任何可画的东西，"+ 新建"两枚按钮
   被甩到右边缘。`with-habits.png` 轻一些，但习惯板子被挤到右栏、中间整片空。
3. **两档的"范围"本来就不是同一件事。** 日历那一列是**多选勾选**（迷你月历 + 显示范围），
   任务那一列是**单选筛选**。要给习惯补，得先回答"习惯按什么筛"（分组？清单？），
   那是**新功能**，不是排版改动。

⇒ **建议：不补**，保持"范围列只在有范围的视图里出现"。
如果负责人要的是"习惯也能按分组看"，那应该单开一单先定那一档的词表与列内容，
而不是把任务那一列原样搬过去 —— 上面第 1、2 条就是搬过去的样子。
