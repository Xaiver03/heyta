## 为什么不是 `pnpm check:ai-e2e`

那个套件会先 `pkill` 机器上在跑的 vite dev server（AGENTS §7 第 87 条）。
本轮工作树与另一条线共用，那一条线的 dev 进程正活着 —— 所以这里换一条
**不启动 vite、也不杀任何进程**的载体：静态产物 + 无头浏览器。
无头因此同时满足 §6.2 规定二（不抢前台）。

## 看这四张时顺手量到、但**判成不是缺陷**的一件事

三张图里都能看见底层那条捕获输入框的 placeholder 淡淡压在「个人信息」那一行上
（暗色那张最明显）。我一度当"透出 = 缺陷"要当场修。读了
`apps/web/src/styles/app/sheets.css:20-27` 才确认这是**刻意的语义**：
`.ht-sheet` 的背景是 `color-mix(... 95%, transparent)`，注释写明"下层看得见但退到后面"
是信息架构（对照滴答实测），而且**95% 这个数本身就是一次"文字压文字"实测之后钉的**
（曾为 88%，太低时下层深色文字以可读浓度透上来）。所以：

- ✅ 不改。把它调成不透明会让 `settings-sheet-ia.spec` 那条 IA 判据变红；
- ⚠️ 但**边界要说清**：95% 只保证"退成隐约一层"，它**不保证不与本层文字同行重叠** ——
  这次 ghost 恰好压在「个人信息」标题那一行上。要真治它，得给浮层第一条内容留一条
  避让带（那是设计改动，不是这批改判据的顺手事），登记给下一轮界面批。
