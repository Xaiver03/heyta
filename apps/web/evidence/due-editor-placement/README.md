# 日期弹层的**放置**：面板被视口底裁掉 ⇒ 那个日期在界面上选不到

**这不是日历那一屏的事**，是任务行上「截止」弹层的放置逻辑。
它是在 R11 批五收尾跑**全量 e2e** 时被 `e2e/tests/due-date-edit.spec.ts` 照出来的
（台账：`docs/plans/ui-review-fill-zh-timeline.md` §9.11）。

拍法：`cd e2e && npx playwright test tests/due-date-edit.spec.ts`。
⚠️ **`before-*.png` 不是当时的截图** —— 当时的已被后续几趟跑覆盖。
它是用**旧放置逻辑**（变异臂 S：两头都放不下时"宁低不遮"照旧朝下开）复现后拍的，
复现命令：`python3 /tmp/mutate-r11.py S`（跑完自动还原源文件）。

| 文件 | 是什么 | 它证明 |
|---|---|---|
| `before-clipped-by-viewport.png` | 旧放置逻辑，视口 1280×720，任务行落在 y≈504 | 面板**朝下开**：只画得出 2 个星期行（28…4 与 5…11），**18 号以及之后三周根本不在屏幕上**。而面板是 `position: fixed` 且"滚动即关" ⇒ 用户滚列表就把面板关掉，**没有任何办法点到那格** |

## 判据

| 层 | 在哪 | 钉的是什么 |
|---|---|---|
| 纯函数 | `apps/web/tests/due-date-edit.spec.tsx` 的「弹层放置」4 条 | 三种情形（下 / 上 / 两头都放不下）+ 视口比面板还矮时不产生负顶边。每条都断 `top + 面板高 <= 视口高` |
| 真浏览器 | `e2e/tests/due-date-edit.spec.ts` 的 ②.5 | **每一格的日子都在视口内**（量 `getBoundingClientRect`，越界的把 `aria-label` 与 y 一起打出来） |
| 变异 | 臂 S（`/tmp/mutate-r11.py`） | 把第三支改回旧的"宁低不遮" ⇒ e2e 精确红，实测报出 **37 格**在视口外（`10月18日@y=753`…`11月8日@y=921`） |

## 🔴 为什么以前没红

放置判据原来是**一个表达式**：

```ts
const openDown = rect.bottom + 500 < innerHeight || rect.top < 500;
```

第二个 `||` 就是"两头都放不下时仍然朝下"（当时的注释写的是"宁低不遮列表头"）。
2026-10-02 这条判据**是绿的** —— 那时任务行落在 y≈380；
对话助手那一屏（`401bbcd6`）在列表**上方**加了约 120px，行掉到 y≈504，
刚好跨过 `rect.top < 500` 这条线。⇒ 一次"往上加了块面板"的改动，
把下面一个弹层的**边界情形**从"够得着"推到"够不着"，而**没有任何一道门禁直接看这件事**，
是那条 e2e 用例顺带照出来的。

📌 一般规律：**弹层的放置判据不能只测"通常那一档"** —— 它的失败模式是
"锚点落在某个 y 之后整块东西消失"，而那个 y 由**页面上方有多少块面板**决定，
不由弹层自己决定。所以判据要断"每一格都在视口内"（全量），不是"某一格点得到"（抽样）。
