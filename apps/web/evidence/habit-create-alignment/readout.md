# 「添加习惯」对齐验收（2026-10-24）

本组图来自**真实 Chromium**（Playwright，`e2e/tests/habit-create-alignment.spec.ts`），
不是设计稿、也不是静态采样。暗色走的是**产品自己那枚开关**（`switchTheme()`），
不是 `emulateMedia` —— 应用一旦"用户显式选过"就不再看系统偏好，
那条路会拍出"名字写暗色、量的是亮色"的假证据。

## 人看过之后确认的事（这一栏是规定的产物，不是装饰）

1. 收起态**没有**任何一枚图标；点开头像右侧那颗铅笔才出现整排。
2. 五个可键入控件（名称 / 频次 / 数值 / 单位 / 达成方式 / 补打卡）**高度完全一致**，
   上下沿对齐成一条线。
3. 标签（频次 / 数值 / 达成方式 / 补打卡范围）**左沿对齐**，控件左沿也对齐 ——
   两条竖线，不是"每个字段各自为政"。
4. 分隔线**一条**，横跨内容宽；它上下是两件事（这条习惯是什么 / 漏了怎么补）。
5. 「取消 / 添加习惯」**常驻在底部**，不随正文滚动。
6. 暗色下控件比弹窗底色**更深**（`surface-sunken` 对 `surface-raised`），
   边界读得出来 —— 而**没有描边**（产品负责人 2026-10-07「无描边交互」）。
7. 390 宽下不出现"一字一行"的标签（那是第一版实测 `0px` 轨道造成的，
   根因是"一行不是一个容器"，已改成 `FormField` 的 `.ht-input-field`）。
8. **键盘焦点环画得出来**（截图上那一圈蓝）：本轮修掉了全局
   `:focus { outline: 0 !important }` 把**所有输入框焦点**一起抹掉的真缺陷，
   判据是 `habit-create-shape.spec.ts` 的 **S6**（真浏览器读 outline 并现算 ≥3:1）。

## 这一组图是在**共享原语**之上拍的

`FormField`（`apps/web/src/lib/form/FormField.tsx`）把"一行字段"收成了一处实现，
本对话框与「新建清单」都用它。手写 `<label>` 的存量由
`pnpm check:form-anatomy` 记账（72 处 / 27 文件，只减不增）。

## 这份证据**没有**证明的事

- 真正的测量判据在 `e2e/tests/habit-create-shape.spec.ts`（S1–S5），它量的是几何与顺序；
  本目录的图只回答"人看着对不对"。
- 物质性边界：手机端（`apps/mobile`）的新建习惯**没有**跟这一批对齐，不在本组图里。
