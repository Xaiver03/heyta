# 邮箱链接全链路（ADR-0039 §2.1 / §2.2）的证据

> 入口：`node scripts/verify-email-auth-chain.mjs`（**不开 TEST_MODE** —— 要走真的发信那条路）

## 它证明什么

| 文件 | 它证明 |
|---|---|
| `email-chain-pass.txt` | ✅ **绿**：真发出一封信 → 点开确认页 → **一次点击换到会话** → 令牌一次性 → 库里 `is_verified=1` 且令牌已清 |
| `email-chain-INJECTION-get-consumes.txt` | 🔴 **红**：把 `/verify-email` 改回"**GET 就消费令牌**"（= 修之前的行为）⇒ 第 ④ 步当场 401 |
| `email-chain-run.txt` | 最近一次运行的自述（邮箱、preview URL、链接、各步状态码） |

## 为什么那封"信"是真的

本地 `server/.env` **没有 `SMTP_*`**（实测 0 个键），于是 `server/src/email.ts` 走它的
**Ethereal 兜底**并把 **preview URL** 打进日志。脚本不去"假装发信成功"，而是
**把那个 URL 抓回来、从渲染后的邮件正文里取出链接** —— 所以它验的是
"信里到底有没有那个链接、链接指向哪"，而不是"端点返回了 200"。

⚠️ Ethereal 的预览页是**外壳页**：邮件正文被内嵌时斜杠变成 `\u002f`、`&` 变成 `&amp;`。
不归一化就取不出链接，而症状是"信里明明有 token，脚本却说取不到"。

## 红/绿一对，差在哪一行

| 输入 | ③ 确认页渲染 | ④ 换会话 |
|---|---|---|
| 修后（GET **不**消费） | ✅ | **✅ `kind=session`** |
| 注入（GET 又消费） | ✅ | **❌ HTTP 401** |

⇒ 同一份判据在两种实现下给出相反结论 —— 这就是"修复是承重的"的证据。
**顺带说明为什么这个 bug 危险**：邮件客户端的**链接预取**（Outlook SafeLinks、Gmail 预览）
会在**用户点之前**把链接抓一遍。GET 消费令牌 ⇒ 用户点进来只看到"链接已失效"，
而服务端日志一片干净。

## web 端全链路（真浏览器 + 真邮件）：✅ 绿

入口：`node scripts/verify-email-web-chain.mjs`（走**生产同源拓扑**的本地复刻：
本脚本起一个反代，`/api`+确认页 → API 服务端，其余 → `apps/web/dist` 真产物）。
十一格判定，全部要走真浏览器 + 真邮件：

| 步 | 结果 |
|---|---|
| ① 应用在**同源反代**下打开（真产物） | ✅ |
| ① 地址框**预填成同源地址**而没人碰过它（结构类） | ✅ |
| ① UI 注册（真界面，**一个地址都不填**） | ✅ |
| ② **真发一封**（Ethereal 兜底，从 preview URL 把信读回来） | ✅ |
| ② 链接指向**反代那个 origin**（不是 `localhost`、不是 API 的端口） | ✅ |
| ② 链接带 `lang=` 且等于提交时的**界面语言**（结构类） | ✅ |
| ③ 打开链接 ⇒ **确认页**（不是"已失效"） | ✅ |
| ④ 点击 ⇒ 跳到 `/app/` 且应用挂载 | ✅ |
| ④ 会话经 **URL fragment** 投递到应用（结构类） | ✅ |
| ④ 地址栏里的会话 fragment **已被抹掉**（结构类） | ✅ |
| ⑤ 落盘凭据出现（刷新之后仍是登录态） | ✅ |
| ⑤ 身份菜单出现"**退出登录**"⇒ **应用真的登录了** | ✅ |

### 「一个地址都不填」这一格是判据，不是省事

旧脚本在这里 `fill(WEB)` —— 注册的前置条件是"先把你连哪台服务端敲出来"，
而那面墙正是被拆掉的东西。现在整条旅程**没有任何一次输入地址**，
并且**读回那个框的 `value`**：

> **"不用填"和"默认值是对的"是两件事。** 只看注册成功，可能成功地把请求
> 发去了别处（比如构建期烙进去的旧域名）。

🔴 变异实测（2026-10-01）：把 `AuthPanel` 的预填初值改回空（= 拆墙之前的行为）
⇒ **恰好这一格红**（`实测 value=""`），其余十格**全绿**，旅程照样跑通。
所以这一格钉的是"保证"，不是"能不能用" —— 这正是 `outcome` / `structure`
分开的意义。

### 链接里的 `lang=`：一整条腿以前从来没被验过

加这一格的过程本身就值得记：旧的取链接正则停在 `[0-9a-f]+`，
于是 **`&lang=en` 被截掉了**。后果不是"少打印一段"，而是这一腿从未进过判据，
而截图会**看起来像本地化坏了** —— 无头 Chromium（Playwright 默认配置）
实测**根本不发 `Accept-Language`**（同一次会话里 `navigator.language` 却是 `en-US`），
所以没有 `lang=` 时服务端落到 `zh-CN` 兜底，**英文界面 + 中文确认页**就是这么来的。

- 🔴 变异实测：把 built server 的 `withLocale` 改成原样返回 `link` ⇒
  **恰好这一格红**（`lang=(没有)`），其余十格全绿。
- ⚠️ 新正则的字符类里那个 `\\` 是承重的：预览页把链接放在转义过的 `href=\"…\"` 里，
  只排 `"'` 与空白会把结尾的反斜杠当链接抓回来（实测 `lang=en\` ⇒ 这一格红）。
  **红得对，但红的是探针** —— 又一次"先怀疑探针"。

## 那个长期的"点了邮件链接回来还是未登录"——根因定位（2026-09-30）

它**不是**"应用没读"，而是**读的东西在半路上被丢了**。仪器给出的原始读数：

```
写入时间线      ：确认页 set sessionToken / loginEmail / loginBaseUrl（真的写了）
确认页 pagehide ：sessionKeys = [sessionToken, loginEmail, loginBaseUrl]   ← 最后一刻还在
应用启动那一刻  ：sessionKeys = []                                        ← 没跟过来
                 （且时间线里**没有任何 removeItem** —— 不是被谁清的）
```

**根因**：确认页由同步服务端渲染，带着 `@fastify/helmet` 的**默认**安全头
`Cross-Origin-Opener-Policy: same-origin` + `Origin-Agent-Cluster: ?1`；
应用（`/app/`，静态产物）**两个头都没有**。⇒ 从确认页跳到 `/app/` 会
**切换 browsing instance**，`sessionStorage` 不跟着回到原来那一份
（`localStorage` 不受影响 —— 同一份时间线正是靠它才活到了 `/app/`）。

**修法**：会话改走 **URL 的 `fragment`**（`/app/#sessionToken=…`）。fragment 不发给服务端、
不进 `Referer`、不进任何访问日志，而且是 URL 的一部分 ⇒ **一定跨得过去**，
**不依赖服务端与反代的头配置保持一致**（自建换个反代不会再坏一次）。
应用读完**立刻** `history.replaceState` 抹掉它。

> 上游模块里"别把令牌放进 URL"讲的其实是 **query**（`?token=…` 会进日志与 `Referer`）。
> fragment 两类泄漏都没有。而且 fragment 严格**小于** localStorage：
> 应用若启动失败，它随标签页一起消失，不会跨重启留着。

## 红/绿 2×2 —— 修复与判据**都**是承重的

`sessionStorage` 那条投递**依赖两个独立部署件（服务端 / 反代）的头配置一致**，
而那是个默契、不是保证。所以下表两列不是"两种实现"，而是
**同一份判据在"头配置恰好一致"与"不一致"下的结论**：

| 投递方式 \ 响应头 | 带 COOP/OAC（**生产的真实形状**） | 摘掉 COOP/OAC（注入） |
|---|---|---|
| `sessionStorage`（修复前） | **结果类 ❌❌**（真的登不上）<br>`web-chain-INJECTION-legacy-storage.txt` | **结果类 ✅✅**，结构类 ❌<br>`web-chain-INJECTION-legacy-storage-strip-coop.txt` |
| **`fragment`（现在）** | **全绿 ✅**<br>`web-chain-GREEN.txt` | **全绿 ✅**<br>`web-chain-INJECTION-strip-coop.txt` |

- 左上红、右上绿 ⇒ **"丢"确实是那两个头造成的**（因果，不是猜的）。
- 左下全绿 ⇒ **修法本身成立**。
- 右下全绿 ⇒ **修法不依赖那两个头的存在**。

第三份注入 `web-chain-INJECTION-drop-fragment.txt` = 把 fragment 投递也摘掉
（服务端脚本里 `'/app/#' + params.toString()` → `'/app/'`）：**结果类与结构类一起红**
⇒ 证明那两格判据**是活的**，不是"今天恰好绿"。

⚠️ **判据分两类，总结会分开点名**（`outcome` / `structure`）。
右上那格是**结果类全绿、结构类红**：那一轮**用户其实能用**，红的是"保证"。
一句话"全链路未通过"会让人以为产品坏了 —— 所以脚本会明说
"红的是保证而不是功能"。

⚠️ 三个注入都做在**反代里改响应体**，不碰工作区文件：
注入若靠改源文件，跑完就会留下一个改坏了的仓库，而那种残留极难被发现。
改写**失配会当场抛**（`注入 X 没匹配上`）—— 静默失配会造出一条**假证据**：
注入没生效 ⇒ 这一轮仍然全绿 ⇒ 而我却会把它当成"判据是活的"。

🔴 上面那两条**新**变异（预填初值 / `withLocale`）没法在反代里做（一个在产物里、
一个在发信代码里），所以做在**一次性的干净 worktree**（`git worktree add` 到 HEAD，
跑完整个目录删掉），**共享工作树一个字节都没动**。
两处都留了还原判据：`AuthPanel` 那行改回原文后 `sed -n 151p` 复读过，
`email.js` 还原后 `grep -c 'lang='` 回到 1。
**变异跑在临时树里 = 结论仍然对当前 HEAD 成立**，而跑在共享树里 = 会留下没人发现的残骸。

⚠️ 顺带记一条**判据自身**的坑：第一次写这里时用 `res.text()` 读那次 POST 的响应体，
而确认页成功后**立刻跳走** ⇒ 读取被取消、`.catch` 吞掉 ⇒ 证据里只剩"(没抓到)"，
**看起来像"根本没发请求"**。改成**同步记状态码**才看见 `200`。

## 如实记边界

- **只验了邮箱这条**。手机号那条是**预留**（ADR-0039 §2.4），没有真实短信网关，**不许**说它能用。
- **不验 UI 点击**（那是浏览器套件的事，见 `e2e/auth-journey/`）；
  **不验桌面壳回调**（`heyta://auth`，反向授权那一步，单独验）。
- 🔴 **这条脚本走的是 Ethereal，不是真实收件箱**。要分清两件事：
  - "**真实 SMTP 发得出去**"在生产上已经实测过（自建 SES 通道；账号语言 → 英文邮件
    落件那条见 `docs/plans/i18n-multilingual.md` §3 的验收记录）；
  - 但**"真收件箱里点开那封信"这一腿从来没跑过** —— 仓库里**没有任何收件箱读路径**
    （无 IMAP 工具、无测试邮箱密码），所以这条判据在"真邮箱"下仍是**未实测**。
    已作为编号缺口登记在 `docs/plans/user-journey-and-auth.md`。
- **锚点一律用 `data-testid`，不用文案**：这台机器上 Playwright 起的是 `en-US` 浏览器，
  而应用现在**认浏览器语言** ⇒ 旧版那句 `input[placeholder^="添加任务"]` 直接超时，
  而应用其实是好的（真产物手验过：`#root` 18277 字符、`capture-input` 在）。
  **拿文案当锚点 = 把"换了语言/改了措辞"读成"应用没打开"**（§7 第 46 条那类假红）。
  ⚠️ 还剩一处没换掉：注册按钮用的是 `/注册新账号|Create account/`（两种都列着），
  因为 `AuthPanel` 里没有 testid。第三种语言一进来它就会红。
- 注册确认页的**文案暂复用** `verify.*` / `login.*`（贴切度一般：注册链接会说"完成这次登录"）。
  这是**明确的跟进项**，写在 ADR-0039 §3。
