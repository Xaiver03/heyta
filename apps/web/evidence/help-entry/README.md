## 这一格不证明的三件事

1. **不证明"干净检出上有一道门"**：钉这张界面的 Playwright 用例 `e2e/tests/help-entry-ux.spec.ts` 原文写"至今未入库"——
   ⚠️ **10-11 18:3x 复量作废：这枚 spec 现在在 `HEAD`**（`git cat-file -e HEAD:e2e/tests/help-entry-ux.spec.ts` rc=0，由 `63e61f23` 带入）。
   所以这一格现在证明**仓库里有这道门**，而且 19:0x 那一趟（r101）**四条腿全绿**（含先前红着的 375 亮 / 375 暗两条 —— 红因是共享装置 `switchView` 只认窄屏 rail 的「更多」面板那一段、不认常驻段，修法与读数在台账「窄屏那一档的「更多」换了形状」那一格）。
   🔴 **但这一格仍然不证明它在只含已提交内容的树上跑绿**：r101 跑的是**主检出工作树**。这一枚 spec 的那两条 375 腿靠的是它自己那一步"先试常驻直达、等不到才展开更多"（同批还有共享装置 `e2e/tests/helpers.ts` 里窄屏那两段），**这两枚现已入库（`ff2efe5b`）**，所以欠的不再是"改动没进仓库"，而是"没有一次跑在只含已提交内容的载体上"。
   要闭合它需要一棵干净载体重跑，命令在台账「窄屏那一档的「更多」换了形状」那一格末尾。
2. **不证明外链真的打得开**：这四张是静态渲染取证，`href` 与 `rel` 由那枚 spec 判（它现在在 `HEAD`，但见上一条的边界）。
3. **不证明四端**：Web 一栏。iOS / Android / 两个桌面的帮助入口见台账 UX-S9-09 那一行的"完整四端容器矩阵待验"。
