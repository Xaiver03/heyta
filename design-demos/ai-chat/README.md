# heyta · AI 对话界面 — 三方向原型

参照对象：朋友那套（WeKnora / WunoOS）聊天界面的「机制」——居中阅读列、助手富内容（工具轨迹 + 结果卡 + 确认）、克制输入区；
品牌基座：直接用 heyta 自己的设计 token（主蓝 #2563eb + slate 中性 + 语义色），不搬他的 TDesign 皮肤。

三版都基于同一个真实场景：把「Q4 品牌物料」本周到期任务整理 + 超期顺延 + 按优先级重排，助手给出可确认的变更。

---

## A ·《他的样子》— 最贴他
- 文件：`A-weknora.html`
- 骨架：单列居中阅读流，助手整段 markdown + 结果卡，用户一个问题气泡。左侧轻量会话栏。
- 气质：干净、留白足、企业感，最接近 WeKnora 那套的观感。
- 适合：想要「原样搬到他的感觉」，风险最低、最稳。
- 代价：个性偏中性，像很多 AI 产品的默认长相。

## B ·《heyta 原生》— 最贴产品
- 文件：`B-heyta.html`
- 骨架：工作台感。助手回答是一张带表头的卡，工具步骤做成竖向时间轴，任务变更用「原值→新值」diff 行；输入区上方常驻上下文 chip（项目 / 本周到期）。
- 气质：任务管理产品的味道最重，和 heyta 现有信息结构最顺。
- 适合：要它看起来就是 heyta 的一部分、而不是外挂一个聊天框。
- 代价：信息密度最高，比 A 更「满」。

## C ·《克制编辑感》— 最有设计感
- 文件：`C-editorial.html`
- 骨架：单主色（蓝只用于强调/发送/确认），排版主导、留白最大；助手回答像一篇干净的文档，任务用细线表格，工具轨迹收成一行可展开；输入是悬浮胶囊。
- 气质：安静、高级、几乎看不到「AI 产品套件」的痕迹。
- 适合：想让对话界面本身成为产品的质感亮点。
- 代价：信息密度最低，需要用户习惯「少按钮、重排版」。

---

选定方向后：按 heyta 的 `AGENTS.md`（设计 token、禁裸值、界面不加说明文字）落到 `apps/web` 的 AssistantPanel 上，先做一屏可跑的静态壳再接通流式。
